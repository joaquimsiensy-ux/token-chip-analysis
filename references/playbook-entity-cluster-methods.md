## 3. 地址身份标注（批量标签库前置 + 三级兜底）

**第零步（强制前置，先于一切人工定性）：批量标签库过一遍。** 全部候选大户/关联地址先跑
`python3 ~/.codex/skills/token-chip-analysis/scripts/labels/label_lookup.py --chain <链> --file <地址清单>`（加 `--json` 得机器可读 JSONL）。
七段输出的处置纪律（v4）：[SERIAL] 惯犯庄家命中=最高优先级，立即调案源比对手法（跨案命中必写报告）；[RISK] 定性风险命中=必写进报告；[RISK-CANDIDATE] 社区候选=降权提示不作定性；[RISK-UNKNOWN] 白名单外旗标=人工核验后扩白名单或修数据，不自动定性；[EXCLUDE] 设施=不计入实体持仓/大户榜（资金路径叙事保留）；[IDENTITY] 身份=不剔除、报告标注（locker/airdrop-distributor/token-sale/charity 禁作聚类合并边；locker/分发器持仓按 bucket 单列桶）；[PRIVACY] Tornado 使用记录=陈述事实不定性。
**库无记录≠白户**——未命中的仍走下面三级兜底；cross_chain 联查命中只是提示，定性前须现场核验（普通合约同址≠同实体）。EVM cluster.py / analyze_holdings.py、SOL replay_edges.py / build_evolution.py（阵营体检）、HL main_metrics.py 已内置该库自动兜底（`--no-labels` 关闭；缺表显式报 degraded_mode——看到该警告说明本次运行无标签防线），但对"人工逐个定性"环节，第零步照跑。Robinhood 链疑似公共 bot 合约再加跑 `fingerprint_check.py --chain robinhood <地址>`（字节码模板指纹，命中=candidate 级、行为复核后才按设施处理）。对未命中库的候选大户可选跑 `goplus_check.py --chain <链> --file <清单>` 做恶意地址体检（candidate 级降权提示，EVM 主力可用、SOL 覆盖未证实——纪律见 labels/README「运行时风险通道」）。分析收尾把 miss-queue 新增条目扫一眼（跨 token 反复出现者优先核验回填）（来源：标签库 v4 接入 2026-07-17；v4.1 GoPlus 通道同日）。

对 Top 持有人逐个定性，把 CEX 托管/路由/池子/官方金库从"疑似庄家"中剥离——五次分析中这一步多次直接改写筹码结构结论（来源：五会话共见，2026-07）。证据强度按级递减，用哪级就按哪级措辞。

**第一级：官方/浏览器标签（最强）**
- EVM：WebFetch 区块浏览器地址页取 Public Name Tag——曾靠它把"疑似老庄分仓""神秘大户"改判为 CEX 储备合约与热钱包，把占供应近四成的 Top1 识破为 CEX 场内托管路由。**大户定性必须查官方标签，不能只看链上行为猜**（来源：SIREN(BSC)，2026-07）
- GMGN holders 自带 tags / start_holding_at / native_transfer.from（gas 来源），是免费标签与聚类线索的复合来源（来源：OPN(BSC)，2026-07）
- Filecoin：扫描创世 actor ID 低位段（f00–f0126）批量取全部官方标签地址（基金会/PL/Faucet/Burn/挖矿储备）——免费获取项目方地址库的关键手法（来源：FIL(Filecoin)，2026-07）
- Hyperliquid：Hypurrscan globalAliases 数百条实体标签 + 官方 API nonCirculatingUserBalances 直接点名团队/基金会地址（来源：HYPE(Hyperliquid)，2026-07）
- Solana：Solscan 公开标签；托管类型可从 token account 的 owner 程序直判（多签程序=官方金库、vesting 程序=解锁托管 PDA）（来源：IO(Solana)，2026-07）
- **标签冲突裁决：以区块浏览器官方标签为准**——聚类工具/子代理/第三方 tracer 转述的 CEX 标签与浏览器官方标签不一致时（曾有 tracer 报 MEXC、Etherscan 官方标签实为 Binance 20），一律以浏览器页面亲验为准，转述值不落库（来源：外部 ASTEROID(ETH) 考古，2026-07）

**第二级：外部证据（次强，逐条留 URL）**
- CEX 的 Proof-of-Reserve 审计 PDF：免费、权威的交易所钱包地址来源（来源：IO(Solana)，2026-07）
- 媒体报道与链上侦探推文的地址指认；链上行为与官方分配文档对表（排放节奏、配额结构吻合即可定性官方金库）（来源：IO(Solana)，2026-07）
- 后台子代理批量考证：给统一 JSON schema（标签/首笔注资来源/钱包年龄/是否仍持仓），强制每条论断带来源 URL + 置信度、查不到就明说（来源：FIL(Filecoin)/SIREN(BSC)，2026-07）

**第三级：行为特征兜底（只够"疑似"级，措辞必须降级）**
行为特征库（来源：IO(Solana)/FIL(Filecoin)，2026-07）：
- 整数余额、长期只进不出 → 冷储特征
- 同时是多个热门代币的最大持仓者 → CEX 归集钱包特征
- 多对象、小额、规律发放 → 运营/发薪钱包
- 固定周期向大量小地址发奖 → 排放/奖励金库
- 每月同日 + 金额分毫不差 + 金额整除还原出归属参数 → 机械 vesting 解锁（区分"机械解锁"与"主观卖出"的硬指纹）
- 一组地址只进不出且按固定额度顺序填充 → 同一实体拆分冷储

**兜底级的边界教训：**
- "单向把币打进某 CEX 热钱包"只能证明客户存币关系，**不能证明该地址归属该 CEX**——交易所内部冷热调拨与客户充值是两种不同链路，归属判定被对抗复核降级过（来源：FIL(Filecoin)，2026-07）
- **CEX 地址归属的实锤正解：交易所 Proof-of-Reserves 审计文件**——各大所定期发布的 PoR 审计 PDF 自带官方钱包地址清单（按链分段），与标的持有人地址集取交集即账本级确认哪些地址是该所官方钱包，权威度高于一切行为推定（SQD 案 Bybit PoR 2026-04-22 PDF 命中 3 址，直接把一个"疑似官方场外仓"实体翻案为 CEX 托管）。用法：官网 PoR 页下载 PDF → pypdf 抽文本 → 取对应链地址段 → 与地址集取交集；再配浏览器官方标签（Arbiscan 等）互证。清单未列的所内周边仓（归集/储备）可用"资金源 ≥99% 来自 PoR 实锤钱包+所内调度流程指纹（先 dust 测试后大额）"补充判定，置信度注明靠行为学（来源：SQD(Arbitrum) 分析对抗复核，2026-07-20）
- **【候选·单案】交易所质押产品体系的识别三件套（"神秘巨鲸"翻案通道）**：①资金 99%+ 可溯至某 CEX 热钱包**本体**、且有大额**回流热钱包本体**（散户把币直接打回交易所热钱包=丢币，只有所内调度这么走——回流是最硬一环）②链上试水时间恰在该所 staking 产品**官宣前数周**（Wayback 快照对官宣时间线，试水=内测指纹）③受托/委托给专业节点服务商且几乎专属。三条命中即定性"CEX 托管质押产品"，归 CEX 桶**不判庄**——LPT 案把全网最大"神秘巨鲸"（6.96% 全局权益）翻案为 Bitvavo 质押产品体系；此类体系还常见"主仓换代"（数年一换新主仓地址）与受托节点更替，溯源要把历代主仓串成一个体系看（来源：LPT(ETH+Arbitrum) 分析对抗复核，2026-07-21）
- **【正式·两案】CEX 提币"囤仓大户"的托管/储备层判定指纹组（"独立用户提币囤仓"叙事的反转通道）**：从 CEX 提币后长期囤置的大户群，可能连"独立用户提币"都不是，而是交易所自身的托管/储备层。指纹组（满足多条即判托管/储备层）：①跨户 raw 级逐位相等转账（两个"互不相关大户"间的转账金额在最小单位逐位相等）②同秒多户动作 ③整点提币窗 ④持仓篮子镜像（多个大户持有的代币组合高度重合）⑤durable nonce/系统地址注资。前置一层（正式，机制已两见）：**同分钟多户注资/出账=交易所批量批次伪影**，批次节奏是所方运营机制不是行为指纹——充值侧见 data-pipeline-evm §6 坑表 AKE 条（同分钟 71 址同批入账），提币侧 USELESS 案再证；凡"时间对齐"类关联必先拉同窗全量做对照组。命中托管层的影响：该群从"大户建仓"整体反转为中性的所方资产调度，CEX 托管合计相应上修（来源：USELESS(Solana) 分析对抗复核，2026-07-21；SPX6900(ETH) 第二独立案例复现转正，2026-07-25）。**ETH 侧指纹三件套（Coinbase Prime Custody 实测）**：①**gas 精确滴灌**——分仓群 gas 全部来自同一 Prime Custody Gas Supplier（`0xa86309988947559b6e72ef716c5058f479386c0f`，已入 address-book；其创世资金来自 Coinbase 4，标签库多源确认）；②**批量激活窗**——7/8 址首笔收币集中 ~61h 内；③**单 tx 等额分发**——同一笔 tx 连续 log（log71-76）同发 6 址、其中 5 址完全等额 36,613.97 枚。快照层面此群曾因"金额不规整+多笔分批"被判偏向个人 DCA 提币，gas supplier 通道是把"两可"定向为机构托管的决定性证据——**判"个人提币囤仓"前必查分仓群 gas 来源**（命中托管商 supplier 一票翻转）
- 免费标签覆盖不全（部分 CEX 的钱包无人标注）时，表格里明写"未能免费确证"，合计数旁标注"可能低估"（来源：IO(Solana)，2026-07）
- **transfer_in 型大户可能是质押/托管 PDA，程序归属判别必须先于庄家定性**——"多地址转入+短期大额累积+transfer_in 标签"表面完全符合归集庄画像，PUB 案 13.57% 供应的"疑似 dev 系分仓"经 owner 程序两跳判别反转为官方质押池（币的主人是各质押用户）。Solana 完整判定链见 data-pipeline-solana §2a 五步法（含升级权限风险必查）；EVM 同理先查合约身份再谈归集（来源：PUB(Solana) 分析，2026-07-14）

## 4. 金库与核心实体逐笔归因

**建清单：** 项目方金库、vesting 托管、做市商、官方回购/护盘基金、外部披露指认的操盘实体，全部进实体清单，逐地址拉全量流水。

**逐笔归因规则：**
- 每笔大额流出对应到一个公开活动（上所划拨、做市补给、公告解锁、生态发放、回购执行）；**对不上的单列成"未解释流出"清单重点追查**（来源：五会话共见，2026-07）
- 解锁/分发款穿透中转层追到终点，按终点二分：进 CEX = 进入可售状态；进囤币钱包 = 被收走。终点未定型的标注"在途"（来源：IO(Solana)，2026-07）
- 按时间轴对比同一来源的去向变化：同一 vesting 源不同月份从"进交易所"变为"进囤币鲸"（或反向）即行为拐点——这是单份报告里最强的证据形态（来源：IO(Solana)，2026-07）
- **轮换出货通道也是行为证据**：同一来源每期固定经同一中转、但每期更换下游终点地址（本月 CEX、下月新地址 A、再下月新地址 B）= 刻意轮换路径规避追踪——处置行为+隐匿意图的组合指纹，单列报告（来源：IO(Solana) 实录核验，2026-07-12）
- 接收方是实体地址时再追一跳并分类（转 CEX / 市场卖出 / 再质押 / 桥出），逐类计数而非笼统描述；注意"第一跳没卖"不等于"没卖"，追到几跳就说几跳（来源：HYPE(Hyperliquid)，2026-07）

**结构指纹与意图克制：** "长期沉寂后在拉升次日突然划出大额 → 拆成面额规整的一次性新地址 → 收币后分钟级充所"这类完整链路要逐环节记录并画图；但结构成立≠意图成立——高位变现与做市/所内活动供库存在链上不可区分，定性只写"协调投放"，两种意图并列（来源：OPN(BSC)，2026-07）。

**杠杆手法：**
- 外部情报→链上复核范式：先拿第三方分析师披露的实体地址清单，再用批量余额查询（EVM 用 Multicall3）核验现仓，直接量化实体当前持有——绕过自建聚类的冷启动（来源：SIREN(BSC)，2026-07）
- 大额批量分发交易可直接解码提取全部接收地址（一笔近千地址的分发交易即一份现成实体名单）（来源：SIREN(BSC)，2026-07）
- vesting 是链原生结构的（如 Filecoin multisig actor），锁仓明细（initialBalance/unlock 起止）链上直读，无需外部解锁表（来源：FIL(Filecoin)，2026-07）
- "官方解锁新增流量归零"≠"卖压消失"——已解锁未处置的存量仍在，必须分开表述（来源：FIL(Filecoin)，2026-07）
- **【候选·单案】"社区分发桶"女巫化回收识别（claim 桶必做接收人收敛检验）**：项目方的 claim/奖励分发桶（数万笔出账）表面是"发给社区"，但分发对象可能高度女巫化——数百领取地址薅取小额后**收敛到单一归集地址**，再走系统 SOP（多层传仓→与其他官方桶同款汇聚节点→充 CEX/场内）变现。判据：①对分发桶的全部接收人做归集收敛检验（AKE 案 591 笔归集到单址收拢 5.62%）②归集后的去向与项目方其他桶的变现管道是否同一套汇聚节点/SOP（同款=同主人的强旁证）③"分发笔数多"本身不证明"真散给社区"。定性：命中即"社区分发相当部分实为系统内回收变现，高度疑似项目方左手倒右手"，归项目方运营系而非散户——**漏检的代价是把项目方出货错算成社区流通**（AKE 案 4 月真实系统出库 18.2% vs 名义"社区分发"口径）（来源：AKE(BSC) 分析完整性复核，2026-07-19）
- **【候选·单案】官方桶金额精确对表归属法（正经 VC 币的归属铁证通道）**：把创世/TGE 一级分发的各接收地址金额与官方 tokenomics 文档的桶百分比逐桶对表——金额分毫不差命中官方桶（SQD 案 375.7M = 28.1% 桶精确吻合）即该地址归属官方体系的账本级证据，强度高于行为推定；配套纪律：官方文档桶表先固化成数字清单再对，禁止"大致接近"式匹配（来源：SQD(Arbitrum) 分析，2026-07-20）
- **【候选·单案】可回收 MM 贷款指纹（官方做市 vs 独立做市的账本判据）**：做市地址同时满足 ①是官方 vesting 的受益人 ②官方后来把其剩余额度**回收再锁入新 vesting**（revoker 权限实际行使）——库存可被官方收回=典型 token loan 做市结构，写"官方出借库存的做市"有账本支点（独立做市商的自有库存不可能被项目方收回）；仅满足①时只能写"从官方渠道获得库存"（来源：SQD(Arbitrum) 分析，2026-07-20）
- **【候选·单案】机构托管"逐月换仓轮换链"指纹（与上方"轮换出货通道"条相反的良性形态，两者必须区分）**：同一仓位**每月整仓**转移到全新地址、链长可达 40+ 跳、余额基本不减、常带 OTC 台采购起点——这是机构托管的安全轮换作业（定期换址是托管安全规程），**非出货**；而"传动链分批剥离出金"（每跳剥固定额度经出金台/CEX 入托管、主仓逐跳递减）才是离场作业。判据=看链上每跳的**余额守恒性**：整仓平移=托管轮换，逐跳递减+剥离额有出金去向=派发。两种形态混判会把机构长持错读成庄家出货（或反之）（来源：LPT(ETH+Arbitrum) 分析，2026-07-21）

---

- **平台出纳机器人的自动分发名单=官方关联仓发现通道**：发射台类标的的平台出纳（高频自动归集费用的 EOA，万笔级）会以机器节奏给极少数地址发 dust 级 ETH——把「出纳的 ETH 出账收款人全集」作为官方阵营标准排查项，名单上的非金库地址是"运营侧隐性关联仓"候选（实测借此发现官方系隐性仓位 0.15%，其在利好日/风波日三次买入零卖出；定性注意：买入资金若来自其自身提款则写"运营侧关联地址的自发买入"而非"官方出资自买"）（来源：BEGGAR(Robinhood) 分析对抗复核，2026-07-17）


## 6. 关联地址聚类规则

**前置硬步骤：聚类候选先过批量标签库**（§3 第零步；cluster.py 已默认内置 resolver 拦截——
tier=exclude 设施与 locker 禁作合并边，被拦地址写入 clusters.json 的 label_excluded_nodes 供对账）。
手搓聚类脚本或新链临时脚本时同样必须先过 `label_lookup.py`，防 CEX/桥/路由被串进实体簇（来源：标签库 v3 接入，2026-07-16）。

**证据边类型（多类证据构边，连通分量 + 证据打分）：**
- 大额直转 / 共同资金来源（首笔注资同源）/ 来自金库一跳 / 时序同步（如 72h 内共同注资）/ 共用中转地址（来源：五会话共见，2026-07）
- 共用中转 = "共用出纳"：两个"独立"大户在各自解锁日汇入同一中转、中转链路又闭合归集到同一终点，是集群判定最经典的强证据（来源：IO(Solana)，2026-07）
- **小额测试转账紧跟大额 = 同人验证铁指纹（机制二见，实战复现）**：先转小额（如 1 万枚、10 枚）、分钟级内跟进大额到同一目标——这是转账人在验证自己控制的新地址，比"同额多胞胎"更硬的直转边强化。实战复现补强：同一发送方对**两个**目标各做"10 枚测试→隔 3-4 分钟全额跟进"（一对二 SOP），可据此把两个表面独立的囤仓簇合并为同一人（BANANAS31 案 F2）；不同实体在同日各自执行同款 SOP 时，测试转账的**秒级交替时序**（A 簇测试→B 簇测试→A 簇全额→B 簇全额）是跨簇待证关联的强行为信号（来源：外部 bibi(BSC) 考古，2026-07；BANANAS31(BSC) 筛查复核，2026-07-22）
- **N/N 全员 wei 级等额"归集→原路返还"= 最强协同指纹（可单独排除全部备择）**：一批 N 个分仓先经中转全部归集到单一主仓，一段时间后主仓**按 wei 级零误差把每一份原额退回对应分仓**（返还量=该分仓归集时供出量、N/N 无一例外）——这个结构直接排除 OTC 收购（收购方不会数十天后把币按原额退回"卖家"）、托管重组、B2C 用户群三类备择，比 gas 同源更硬。配套指纹：归集/返还经**专用原子转发合约**（同 tx 即收即转、生命周期仅操作窗、只服务这批地址）。**报告须区分"控制铁证区间"**：等额闭环只证"至迟归集时点起单一控制"，此前的建仓段同源性由"后续 100% 归集"倒推、定性为高度疑似（不可把铁证区间前移到建仓期）（来源：SIREN(BSC) 分析对抗复核，2026-07-19）
- **【候选·单案】镜像执行扫描法（发射窗协同检测的独立通道，对"gas 刻意分离"的协同单元有效）**：对发射窗全部达锚仓（如峰值 ≥1%）做**全对（all-pairs）买入序列扫描**，命中条件三件套＝①逐笔买入**块差 ≤2**；②对应笔**数额比 0.8–1.25**（接近 1:1 镜像）；③**≥2 笔**满足前两条（单笔巧合排除）。价值：互转/共同 gas/两跳中转全阴的协同单元，仍会在**执行层**露出镜像节奏（同一操作者先后操作两钱包）；实测 53 仓 1378 对全扫唯二命中、且双双被 first-funder/热钱包同源旁证坐实为真协同（一组合并后即发射窗真实第一大仓），信噪比极好——全阴四通道后补这一扫，防"分仓买入的单一控制者"漏检。参数与工程注记：块差/数额比按上述默认起步；脚本固化按"≥3 次稳定重现"节奏暂缓，参数先落册（来源：SPX6900(ETH) 筛查 E4 复核，2026-07-25）
- **【候选·单案】短窗口多来源整包归集的控制边界**：大量来源地址在短窗口把余额整包汇入同一收币地址，只能直接证明**归集完成后的资金由该收币/卖出路径统一控制**；它不自动证明归集前的来源钱包属于同一实控。共同 funder、共同部署者、跨链同控、来源钱包之间的机械连通或其他独立控制证据未出现前，来源钱包放入 `associated_source_addresses` 观察队列，不计入确定实体成员；实体份额先按收币/执行地址自身可证余额计算。对抗复核还须区分用户主动授权归集、代币骗局诱导授权、CEX/托管批处理等备择解释（来源：FROGGIE(BSC) 筛查复核，2026-07-23）
- 成边条件：≥2 类证据，或 1 类强证据（来源：HYPE(Hyperliquid)，2026-07）；注资/gas 同源边的强度分级与"私人 funder"公共性三步体检见下方「gas/资金面溯源纪律」块（未过体检不得计为"强证据"）
- **【候选·单案】R1 直转边阈值对"百倍换手老 meme"过松（阈值校准条）**：cluster.py 的 R1 边阈值默认总量 0.005%（denom=20000）——对上线两年级、全史换手数百倍的老 meme，0.005% 的绝对量已跌到散户互转量级，会串出千址级巨集群（实测 1502 址假巨群；0.05%＝denom 2000 变体＋标签兜底后收敛到 189 址社区互转圈量级）。校准纪律：币龄 >1 年或全史成交量/市值 >50 倍的标的，R1 起步阈值上调一档（0.05%），再按集群规模回调；cluster.py 已加 `--r1-denom` 参数（默认 20000 不变，cluster_sensitivity.py 同名参数原有）（来源：SPX6900(ETH) 筛查，2026-07-25）
- **【候选·单案】LP 头寸 NFT 的无对价划转 ＝ 资产层关联硬证据（V3 类池专有通道）**：集中流动性头寸是 ERC721，**只有持有人能撤**——所以"挂 LP 的地址 ≠ 撤 LP 的地址"这个异常本身就是线索，它必然意味着 NFT 转移过。追法：拿到该头寸 tokenId 后查 NPM 合约的 ERC721 Transfer（`topic3=tokenId`，块区间就在两笔操作之间，HyperSync 一次返回）。**无对价划转（tx value=0、无配套支付）＝强证据**：KOGE 案一个"净额精确为 0 的刷量地址"铸得的头寸（当时约值 200 万美元）在 **6 分 44 秒后以 0 BNB 转给项目方签名人**并由其撤出，NFT 至今仍在签名人名下——这是该案刷量层与项目方之间的**首条资产层直接证据**（此前只有时间同步类间接证据）。`scripts/evm/lp_positions.py` 自动标出这类头寸；注意区分真信号与"挂入额低于选取门槛被漏选"造成的假阳性（脚本已分强弱两栏）（来源：KOGE(BSC) 第二轮追加取证，2026-07-25）
- **【候选·单案】同一最小 tick 档的同期挂撤 ＝ 强协同指纹（比"相隔 N 秒转账"硬）**：V3 的 tick 空间约 88 万档，两个实体**选中完全相同的 1 宽档**、同日先后挂入/撤出、且双方都是单边 0 对手币——KOGE 案项目方运营钱包与大庄#1 于 2025-06-01 在 `[-41457,-41456]` 同一档先后进出（03:23 挂 3 万枚 → 09:58 挂 **91.8 万枚** → 12:18 撤 → 15:53 撤），大庄撤出 6 分钟后即把 888,888 枚存入项目方的质押合约；同款指纹另见"其他大户"与项目方同处 `$64.81` 一档、撤出仅差 26 分钟。**分母检验照做**（同窗稀有性）：统计同期该池全部头寸的 tick 分布，档位越拥挤指纹越弱（来源：KOGE(BSC) 第二轮追加取证，2026-07-25）

**硬规则（违反任何一条都产出过垃圾结论）：**
- **服务枢纽剔除**：与超过 15 个不同地址有边（度>15），或出度>200 的节点（DEX 路由/空投分发器/归集服务/部署者），视为服务商剔除其边。不剔除的实测后果：单个"实体"聚出 848 个成员的大杂烩（来源：HYPE(Hyperliquid)/OPN(BSC)，2026-07）
- **同模板 bot 路由同样剔除（与上条互补——模板孪生体单个度数可能不超线）**：同一字节码模板批量部署的 bot 路由（双胞胎/多胞胎合约，各自数千对手方）会把互不相关的用户粘成两位数百分比的假"大实体"——设施剔除名单必须含"同模板高对手方合约"排查（getCode 哈希分组 + 度数阈值）（来源：PING(Base) 分析，2026-07-17）
- **公共尘埃/撒币/清扫网络剔除（"专属后勤"错觉的解药）**：集群外围常见一个向各分仓统一发小额币的"撒币"地址、或回收各分仓尘埃的"清扫"地址——**看着像集群专属后勤，实测常是服务上万地址的公共设施**（1inch 生态尘埃分发、swap WBNB 中转跳板等）。任何拟作"集群服务地址"的候选，落笔前必查其**全网服务面**（对手方总数）：对手方 >1000 且集群地址只占其流量个位数百分比的，判公共设施、**不作实体专属证据**（实锤：SIREN 两个初判"集群撒币/尾币归集"地址实测服务 2 万/9 千地址、集群仅占 3.8%/0.44%，被复核剔除）（来源：SIREN(BSC) 分析对抗复核，2026-07-19）
- **CEX 热钱包不可作为共同资金来源证据**：从同一热钱包提币的地址不构成关联（热钱包是全用户共用资金池）（来源：OPN(BSC)/HYPE(Hyperliquid)，2026-07）
- **【候选·单案】同尾数批量提币=「同批次」指纹非「同人」指纹**：CEX 按固定费率/手续费扣除后，同费率期的整数提币到账额尾数相同（如多址同现 `.974486181` 尾数）——这只证明"同一时段从同一所提币"，**不证明同人**（体系外反例实证：同尾数地址同日独立清仓、与体系行为完全无关）。同人判定必须由行为协同独立支撑（同步移仓窗/共享归集口/长周期同构囤仓）。伪影对照法：真同批伪影=跨多日小额分散；可疑簇=单日窄窗+金额同量级+后续囤仓协同（来源：BANANAS31(BSC) 筛查复核，2026-07-22——初判"统一尾数=同人分发"被复核降格）
- **DCA 定投服务合约会伪装成"化整为零分发器"**：出方是数百个互不相关用户、形似庄家分仓网——**入方构成检验**一步拆穿：入方 99%+ 是池子（服务代买）=定投服务；真分发器的入方是金库/母仓。判定为服务后其用户间不构成任何关联边（来源：PING(Base) 分析，2026-07-17）
- **两跳下游追踪每跳节点先做合约体检**（eth_getCode 批查 + 度数阈值）：下游集合混入公共 swap 执行合约时，"经合约买币的散户"会被批量误判为马甲——实测 132 址体检出 14 个合约，剔除后目标口径 21.9%→12.7%、96 址"大集群"拆为三个独立星座（来源：CASHCAT(Robinhood) 分析，2026-07-13）
- **"标签库命中 registry 官方地址"优先级高于"行为像私有合约"**：跨链桥履约地址（deBridge taker 类）行为形似私有执行合约（低余额、定向转账、少数对手方）——裁决规则：labels 库/官方 registry 亲验命中即判**履约管道**、禁作合并边，行为学证据不得推翻 registry 身份（来源：PING(Base) 分析对抗复核，2026-07-17）
- **最大集群必须回查首笔资金来源验证性质**（官方资助网络 vs 操盘实体是两种完全不同的结论）（来源：HYPE(Hyperliquid)，2026-07）
- 区分"官方控制"与"来源官方"：从金库拿过币 ≠ 被官方控制，两种标签分开打（来源：OPN(BSC)，2026-07）

**伪造与投毒防护（对抗性数据环境的免疫层）：**
- **地址投毒防护**：资金上游归因只认大额转账（设阈值过滤尘埃转账），且比对完整地址而非前缀——曾把伪造 vanity 前缀的投毒攻击地址误判为大户资金上游（来源：FIL(Filecoin)，2026-07）
- **zero-value transferFrom 投毒会串进聚类簇**：投毒者用 0 额 `transferFrom` 伪造 Transfer 事件（事件层与真转账无异、无需授权即可发出）+ 仿冒前缀地址，让受害者流水里出现假对手方——聚类边若不过滤 0 额，投毒地址被当真实对手方串进 BFS 簇（BANANAS31 案 79 址簇曾混入大量 0 仓投毒址）。对策：**一切聚类构边一律 value>0 过滤**（BFS 脚本已内置；cluster_prep_duck 的 edges_agg 同版补齐——手搓临时聚类脚本时此过滤是第一行义务）（来源：BANANAS31(BSC) 筛查，2026-07-22）
- **vanity 定制地址的两种操盘方用法**（与上条"被投毒"相反，这是操盘方自用）：①**配对自证**——注资金主与收币大户地址共享 8–26 位十六进制**中段**（前后缀不同），=批量定制的配对地址，同一实体最硬指纹之一（铁证级；识别看中段不看前缀）；②**仿冒基建伪装**——生成前 12+ 位仿冒 LiFiDiamond/Relay 等真实路由的假基建 EOA 分发筹码，专骗肉眼排查。识别：与真基建地址逐位比对（前缀同、中段不同）+ `is_contract=false` + 无浏览器标签 + tx 数少。三条 vanity 规则合一：**凡涉 vanity 一律完整地址逐位核对**（来源：外部 CASHCAT/GME(Robinhood) 考古，2026-07）
- **外部尘埃投毒可伪造"出纳网络"/gas 边**：第三方营销 dust（批量撒 0.0006 ETH 级）曾把 19 个互不相关大户伪造成完美的"一母多子出纳"假象，据此误判出"庄家组"、被对抗复核用收款人构成证伪（REFUTED）。**出纳网络判定三查（缺一不可）**：①拉出纳地址**本体全量 tx**核验收款人全集（只看 gas_in 里与大户相交的子集会把无差别撒网误读成定向名单）②查收款人构成：含"从未持仓/已清仓/公开 bot 农场"地址=非庄家名单（庄家出纳只养自己的仓位地址）③与同链其他代币的空投/dust 名单查同额同期重叠（重叠=撒网服务）。旁证：真出纳特征=**低频专职**+发射前注资+建仓级金额（0.1-1 ETH 级）；dust 是持仓形成**后**的尘埃级（<$2）。**尘埃级金额（≤0.001 ETH）的 gas 边默认不作聚类证据**（来源：CASHCAT(Robinhood) 分析，2026-07-13；同案两路复核独立触发，条目合并于 v3.0 整编）
- **实体启动 gas 的上游可以是灰产资金边（背景画像，不是合并边）**：实测某吸筹中枢的启动 gas 上游带 ChainPatrol 投毒 bot 资金池标记——可入报告作背景画像与风险提示，但公共灰产池逻辑同公共热钱包，不构成实体合并边（来源：PING(Base) 分析，2026-07-17）
- **关键地址字符串一律从落盘数据文件取完整值**，禁止从终端打印的截断输出复制再凭记忆补全——地址末段是校验和，补全即编造。覆盖一切来源的文字转述，**包括自己派出的复核 agent**（复核报告里的截断前缀落地到附录/JSON 前必须回落盘文件反查完整值——曾凭前缀补全出后 32 位全错的地址、险些进监控名单）；脚本打印涉及后续引用的地址时直接输出完整 42 字符（来源：FIL(Filecoin)，2026-07；CASHCAT/NOXA(Robinhood)，2026-07-13/15）。**本纪律同等覆盖 topic0/事件签名**：一律从落盘的 topic_map JSON 取，不从记忆手敲——LPT 案手敲 TransferBond topic0 错一段，扫出 0 笔 silent fail（来源：LPT(ETH+Arbitrum) 分析，2026-07-21）

**【候选·单案】「同分钟一对一批量交割」协同指纹（伪装分散型实体的统一调度铁证）**：N 个**不同**中转钱包在**同一分钟内**（跨数个区块）各发 1 笔转账、**一对一**交割给 N 个不同终端钱包——独立操作者无法在 60 秒内集体动作，这是单一程序批量签发的直接证据（本案最大一批 122 中转 → 122 终端跨 13 个区块）。**必配对照组检验**：统计同窗口内全网符合同型模式（同分钟 ≥N 个不同发送方 → ≥N 个不同接收方）的批次总数——本案 5 天窗口全网仅 12 个批次、其中 8 个属该体系、余 4 个经查为同一手法，稀有度即指纹效力。配套形态：中转层扇出极小（本案 381 个中转中 216 个只服务 1 个终端）＝用完即弃的钱包配对结构（来源：BUILDon(BSC) 分析，2026-07-25）

**【候选·单案】双检测双盲漏检机理（"从市场买入＋随机化分仓"实体的检测缺口）**：两套主力检测——①BFS 按"币源在网络内"扩散（追项目方系统）②聚类按等额/直转指纹合并——对**从公开市场买入筹码、且分仓金额随机化**的实体**同时失效**：它的币源是池子不入任何已知网络，它的金额分布无档位聚集不触发等额聚类。本案一个现仓 13.81% 的实体因此整体沉入"散户"桶，靠对抗复核翻出。**补第三道扫描（零额外采集成本，用已有重放产物即可）**：按「首入时间窗 × 阵营名单外 × 现仓门槛」筛地址，再按首入分钟做批次聚集统计，同分钟 ≥5 址即翻出整族。阴性结论"无其他达标实体"落笔前必须跑这一道（来源：BUILDon(BSC) 分析对抗复核，2026-07-25）

**行为指纹判定（同步/面额/委托类——每条指纹先问误报率）：**
- **"同秒等额买入"矩阵指纹三要素法**：①"同一秒 ≥3 地址从池买入且金额相近"只是**初筛**——公共交易 bot 用户多时同秒常见（对照组实测：311 个同 bot 用户剔除目标矩阵后仍有 11 例"同秒≥3"）；②有效指纹=三重叠加：**wei 级面额一致** + **重复共现富集**（成员两两活跃秒重合度对随机期望的富集倍数 >1000 倍级才算硬；单次共现只作外延不并入硬边）+ **资金边/币流边闭环**；③检验任何行为学指纹前先造**对照组**（同工具全体用户）——指纹在对照组中的出现率就是它的误报率（来源：TRASH(Robinhood) 增量更新对抗复核，2026-07-14）
- **面额指纹的环境依赖性（分母检验）**：同一面额指纹的效力取决于**同时段全场同面额买家数**——死盘环境（实测正例：当时段全场仅 9 笔买入、其中 0.1 ETH 整 3 笔全是目标组）独占性成立=有效指纹；bot 潮环境（同面额全场 672+ 独立用户）零区分力。"整数×99%"（bot 抽 1% 费后净额）是**通道指纹非实体指纹**。引用面额指纹必须同时报告分母；同次分析中同一指纹可在 A 集团成立（死盘窗）而在 B 集团被击穿（bot 潮窗）（来源：NOXA(Robinhood) 分析对抗复核，2026-07-15）
- **同秒面额指纹必须比对"报价币输入面额"，禁止比对 token 输出面额**：swap 的 token 输出量由池子瞬时价格决定，同秒两笔输出面额**必然不同**——拿输出面额得出"无一致性"是方向性错误；操作者指纹在**报价币输入侧**（同程序同参数下单，WETH 输入可 wei 级逐位全同——实测 144658800000000000 两笔同秒逐位一致）。输入面额也要过上条分母/独占性检验（来源：meow(Robinhood) 分析对抗复核，2026-07-15，初稿曾据输出面额漏掉一个伪装分散集团）
- **低档同秒共现扫描（防"分仓贴线钻候选线"漏检，新庄扫描硬步骤）**：候选榜按份额设线（如 ≥0.8%）可被"多址分仓、单址全部压线下"钻空（实锤：9 址协同族单址全部压 0.55% 以下，两轮分析均漏检，合并 3.69%）。对策=份额线之外**必须补行为线**：对 0.1%–候选线档全体地址按"从池买入时间戳"聚集扫描，同一秒 ≥5 址买入即翻出整族（等差递减面额是程序化批量的附加指纹）；零额外采集成本。**参数补强**：仅扫"同块 ≥3 buyer 且重复共现 ≥3 次"会漏"仅 2-buyer 共现但买入额 wei 级同额"的强指纹对——2-buyer 块纳入扫描+wei 同额检测（同额对才升边）；BSC 出块 ~0.45s 同块≈同秒（来源：TRASH(Robinhood) 增量更新，2026-07-17；哈基米(BSC)，2026-07-18）
- **EIP-7702 delegate 指纹的正确用法**：不能笼统以"是通用/参考实现"驳回同 delegate 关联信号——判据是**产品分发面**：主流钱包各用自家 delegate 合约，无产品前端的参考实现 singleton（如 Simple7702Account）使用面极窄，多个大户委托字节级一致恰是小众指纹；单独同 delegate 仍不足成边，须与其他证据组合（来源：bibi(BSC) 分析，2026-07-12，复核曾据此翻出漏检的 PLAUSIBLE 集群：同 delegate + 同跨链通道 + 归集硬边 + 时间同步四指纹）

**gas/资金面溯源纪律（正查+反查+性质分级）：**
- **注资证据分级（gas/资金同源边的强度标尺）**：**私人 gas 钱包**（本体 <20 笔交易）供养多个母钱包＝强证据；**同窗批次注资**（多地址在同一 ~90 分钟窗集中入金、多波重复）＝中等证据；**公用桥 solver / CEX 热钱包同源**默认剔除，仅当"同 48h 窗 + 行为指纹一致"才升中等。报告按分级分开计数/画图，强证据簇与同窗批次簇不混在一个数里（来源：外部 GME(Robinhood) 考古，2026-07）
- **gas funder 判"私人"前必过公共性三步体检**（总笔数→余额量级→时窗收款人分散度，操作见 data-pipeline-robinhood 坑表）：App 类链的平台托管提款热钱包（万笔级/千 ETH 级/时均数十收款人）形态酷似私人母钱包，曾致四址聚类整体误判；据单一 gas 边建的聚类，funder 被证公共后整体作废（来源：Pointless(Robinhood) 增量更新复核，2026-07-14）。**补强①——体检必须在 funder 的活跃窗内做**："已弃用清空"（余额归零、无近期签名）不是"非服务型"证据——轮换退役的协议 keeper 形态酷似用完即弃的私人母钱包，查其**活跃期**的笔数/收款人分散度才见真身（GOAT 案 86KSd 以"已弃用清空"判非服务型，实为 Jupiter DCA keeper）。**补强②——排他反例检查**：判私人前先在本案 gas 档案里查同 funder 还服务谁——服务名单里出现已单列的独立地址（互不相关画像）即公共设施实锤（GOAT 案该反例就躺在同一 gas_origins.json 里：86KSd 同时服务被单列为独立定投户的第四址，未查致 5.24% 假小庄）（来源：GOAT(Solana) GPT5.6 外部复核采纳，2026-07-24）
- **★注资边成立的先决字段闸（Solana 侧，5.24% 假实体级实锤）**：gas 溯源产物（gas_fast/gas_origins）每条记录先看 `my_sol_delta`——**≈0 即目标根本没收到 SOL，该 funder 只是这笔交易的 fee payer（代付执行者），不是注资方，一律禁作注资/gas 同源边**。Jupiter DCA/limit-order/聚合器的自动执行交易由协议 keeper 轮换代付，指纹三件套：目标 `my_sol_delta=0` + 同 tx 含 Jupiter DCA/Router 等自动执行程序 + 同 keeper 服务多个互不相关地址；`approx=true`（翻页截断近似"最早笔"）单独不成边。gas_fast 算法在目标 SOL 零变化时机械取"交易中 SOL 减少最多的账户"当 funder——这个字段语义是"谁付了这笔交易的费"，不是"谁给目标打了钱"，消费前必须区分。实锤：GOAT 三址合并为 5.24% P1 小庄的唯一依据是共同 funder 86KSd（my_sol_delta 全为 0、tx 全走 Jupiter DCA），外部复核整实体撤销、三址拆回独立 holder 后全部不达标（来源：GOAT(Solana) GPT5.6 外部复核采纳，2026-07-24）
- **gas 档案必须双向用（正查金主 + 反查下游）**：只查"候选的金主是谁"会漏"候选自己是别人的金主"（实锤：某"独立新面孔"实为已知庄家集团最大成员的 ETH 金主，发射前 6 笔 8.7 ETH，这条边一直躺在档案里）。gas_in 档案建 funder→下游反向索引，聚类前对全部候选跑"它给谁供过金"；已知实体成员的 funder 也回头对照候选集（来源：TRASH(Robinhood) 增量更新对抗复核，2026-07-17）
- **gas 边必须做"发本金"性质检查（漏检=集团成员被当独立大户）**：对每条 gas 边算「转账 ETH ÷ 下游该时段买入成本」，比值 ≥1 即"发本金建仓"母子边——比"垫 gas"强一个证据等级（早期币价下千万枚仓位只需 0.05~0.11 ETH，0.065~1.2 ETH 的"gas 转账"实为本金全包）。判据三件套：①金额覆盖下游买入成本（1.35 倍以上实锤）②时序（先收钱、分钟~小时级内首买）③母钱包公共性体检通过。实测漏检后果：某集团 7 址峰值 11.57% 按本金边复核扩到 12 址 17.67%（低估 53%）；二级资金中转（百笔级私人枢纽）同样适用（来源：BEGGAR(Robinhood) 分析对抗复核，2026-07-17）
- **协同检验双面纪律（token 面 + ETH 资金面，缺一即盲区）**：token 转账面的互转/同块/等额/金主首笔四维全阴性≠独立——合并铁证可以 100% 落在 ETH 资金面：wei 级完全等额的批量注资（disperse 类分发合约"单批次归属单一操作者"可作合并边；纯公共桥/存管合约共用不构成边）、同秒多址注资闭环、成员 gas 双向互供（实锤：九址协同工作室现仓 4.71%，token 面全阴性、初判"双址簇 2.98%"，复核以 ETH 面证据扩成整族）。配套：gas 溯源产出的 first_in 列表**逐笔消化**（只看第一笔漏"三马甲同秒供 gas"）；候选净增 <1% 深挖线会被分单建仓系统性穿透——≥1% 候选的资金对手方无条件展开、或深挖线降至 0.5%（两个 0.8-0.9% 马甲恰逃 1% 线即此坑）；同实体判定后按合并口径设观察哨（单址阈值会被分单绕过）（来源：Pointless(Robinhood) 二次增量对抗复核，2026-07-17）
- **金主收敛分析必须"现仓+同时刻合并峰值"双口径过滤**：只按"簇合并现仓 ≥X%"筛深挖对象，**已出货离场的协同集团会被系统性漏掉**（实锤：狙击集团同时刻峰值 5.65%、现仓仅 0.05% 被"现仓 <2%"过滤线筛掉，其共享金主记录就躺在溯源文件里）。正解：私人 funder 服务 ≥2 址的簇一律再算同时刻合并峰值（sig 原子化口径），峰值过标签线或曾为窗口级主力卖压的进深挖名单；"每址最早一笔 funder"人工比对不能替代全笔按 funder 分组（来源：meow(Robinhood) 分析对抗复核，2026-07-15）

**全景完整性与阴性结论（写"无"之前的义务清单）：**
- **发射窗口买家全景必须从第 1 秒扫起**："限购期末仍持仓者"口径会把发射后头 60 秒的快闪客整体漏掉（实锤：头 60 秒内有项目方马甲 5.10%、金主同源闪电簇 5.06% 与多个同窗扫货秒卖的独立 bot，全不在"期末持仓"名单）。狙击/协同识别的扫描窗从发射 tx 下一秒开始，按"窗口内累计买入"而非"窗口末持仓"取全景（来源：meow(Robinhood) 分析，2026-07-15）
- **大户入方溯源必须独立于峰值普查表（低余额高吞吐"隐形管道"盲区）**：按"历史峰值 ≥0.1%"建的普查网会系统性漏掉余额从不过线的执行/中转合约（收→转瞬时过账，峰值≈0 但累计吞吐巨大）——"大户的币从哪来"必须按该大户**全部入账对手方**独立拉清单逐个定性（实测：某大户主力仓位经一个峰值从未上榜的执行合约进货，主分析漏检靠复核补齐）（来源：PING(Base) 分析，2026-07-17）
- **历史静置仓反向扫描硬闸（冻结实体前必做；正向 BFS 不能替代）**：资金流主链只会扩展“从种子可达”的活跃边，系统性漏掉长期不动、已归零、在关键退出日前才激活的平行库存仓与前代仓。每个标的在初步聚类后都要生成 `dormant_warehouse_audit.json`，没有产物或有未裁决候选时禁止冻结实体、算峰值和出图。候选全集至少取四者并集：①逐事件个人历史峰值榜前 200；②个人峰值 ≥总供应 0.1% 的全部地址；③当前余额较个人峰值回落 ≥80% 或连续静置 ≥30 天的历史大仓；④核心实体全部显著入账上游、关键归集/出货窗口的上游供币方，以及最终执行网络边界外一圈自签名地址。阈值只决定人工深挖顺序，不能删除能与核心闭合的低余额高吞吐中转。

  对每个候选逐项反查：建仓币源及前驱链、首次/末次活动、最长静置区间、关键日激活顺序、退出去向、原生币/gas 关系、公共设施属性与冲突证据。`dormant_warehouse_audit.json` 至少记录 `scan_cutoff`、`candidate_address`、`historical_peak_raw`、`current_raw`、`source_path`、`dormancy_intervals`、`key_date_actions`、`facility_checks`、`evidence_grade`、`boundary_decision`、`decision_reason`。裁决只有三类：`strict`（私人币流/资金/gas 或控制权闭环足以纳入严格实体）、`expanded`（币源闭合且关键日独立同步，但法律所有权或跨公共设施控制仍不可证，只纳入强关联体系上限）、`excluded`（公共 CEX/路由/协议设施、仅同日行为或存在反证）。**“同源 + 同日动作”不再自动并入同一主体**；公共设施只作路径节点，不作永久成员和确权证据。

  计量强制双边界：`strict` 联集给严格下限，`strict ∪ expanded` 联集给扩展上限；两者都在各自**同一交易末快照**逐事件重放后取峰值，禁止把各地址或各分支不同时刻的个人峰值相加。报告必须列出两口径各自成员数、峰值时点、峰值构成和相差来源；若没有 expanded 候选，也要在审计文件中显式写空数组，证明扫描做过而不是没做。
- **暴跌/窗口归因必须用"窗口全期净变化"，"同 tx 净额"仍是毛口径**：按"同 tx 净流出且币进池"累加会把窗口内买回的往返客计成大卖家（实锤：初稿"4,363 卖家/最大 1.51%"被撤换——那个 1.51% 的真实窗口净额为 0；修正后 850 卖家/最大 1.24%）。正解=窗口内每地址全部转账净变化、剔设施、再聚类。与 §9"gross/per-tx 双口径"衔接：per-tx 净额适合单笔归因，窗口归因必须再上一层做全窗净额（来源：NOXA(Robinhood) 分析对抗复核，2026-07-15）
- **净盈亏≈0 群体的归因边界（量能虚胖四件套）**：呈现高换手/疑似做量群体的标准件=①占比+多阈值稳健性（净差 2%/5%/10% 阈值下的占比区间）②构成分解（机器式高频 ≥6 笔 / 1-2 笔完整进出的普通交易者 / 已标注实体，防重复计数）③原子性检验（买卖 tx 与同 block 交集——零原子性可排除三明治/原子套利）④群体已实现盈亏（净盈利可反驳"亏损刷量"）。**"客观点火效果"与"主观点火意图"分开表述**："大买速卖客观上引来接盘"可写；"协同做量"在组外存在同模式独立地址时不可写——独立 bot 抢跑失败天然产生分钟级净零往返（来源：NOXA(Robinhood) 分析对抗复核，2026-07-15）
- **出货回款归集排查的表述边界**：本地池侧数据只能证明"池的直接收款人无归集"——回款经公共路由 unwrap/转发后的最终去向不在本地数据内，必须写成"池侧直接收款人无归集；经公共路由之后的去向本地不可证"，否则复核按"超出可证范围"降级（来源：meow(Robinhood) 分析对抗复核，2026-07-15）
- **"其他大户互不关联"阴性结论三查（写"无漏检小庄"前必做）**：①两两互转扫描 ②gas funder 分层（含 gas_in 的 self_alias 字段——L1 桥别名自充值≠独立金主）③同窗注资/同秒建仓/共同下游排查。三查后仍剩的弱信号（同分钟建仓对、若合并将破线）按**"待证关联对"列观察哨重点监控**，不并入也不无视（来源：NOXA(Robinhood) 分析对抗复核，2026-07-15）
- **贴线实体的双口径呈现范式**：疑似关联实体合并份额骑在判级线上时（如硬证据口径 4.99% vs 含弱行为边口径 5.17%，线=5%），**两口径并列呈现、按证据下限判级**（不判庄），同时列观察哨最高优先级+给下次更新"补溯源+重扫"明确指令；跨小组只有工具/面额/时序证据而无资金边时，表述封顶"高度疑似同一工作室"，不写"单一实体"（来源：TRASH(Robinhood) 增量更新，2026-07-14）

**已知系统性偏差：** 互转图聚类的数字**系统性偏低**——同一实体换新钱包续持会被拆成多个独立社区，曾有延续仓被拆成两个社区各自低于报告阈值（来源：SIREN(BSC)，2026-07）。因此："不存在 >X% 集群"永远要写成"**链上可证范围内**无 >X% 集群"。

**措辞锁定：** 聚类结论一律"高度疑似同一实体"，不写确权——共用出纳也可能是做市商/OTC 服务商同时服务多个独立客户；把证据链逐条列出（每条边标日期+金额）让读者自判（来源：IO(Solana)，2026-07）。

**特殊场景手法库：**
- **CEX 注资失效时的隐藏关联识别——跨代币共现聚类**（外部 CZ(BSC) 分析考古，2026-07）：一批钱包全由 CEX 热钱包提现开号、funder 溯源整体失效时，改用"共同买卖历史"聚类：抓每钱包近 1 年全代币流水（BscScan tokentxns ≤1000 行/钱包，见 data-pipeline-evm §7.2）→ 空投过滤 → 支持度 ≥3 频繁项集 → Jaccard 相似度 → 叠加共时首买/首卖时序（6h 窗）→ 并查集分组。**三条判别标准（专防"跟单"误判成"同体"）**：①Jaccard 0.9+ 且买卖双向对称且互有直转 = 同一实体；②**同区块共买比例 ≥85–90%（中位时间差 0 秒）= 同一实体铁证**（共同买入压倒性同块只能是单一控制端成对发单），配套硬指纹：**区块内位置恒差**（两钱包 tx 的块内 index 恒差同一常数，如恒差 7）=同一引擎固定顺序广播；③**跟随者共买永远滞后领头固定秒级（实测 12–110 秒）、从不颠倒 = 程序化跟单不是同一人**（与②互为对照：同块 0 秒=同体，恒定滞后=跟单）。另：交易过 50–500 种币+CEX 开号+无差别狙击每个新币=职业打新号，其存在≠内幕信号，从关联候选剔除
- **逆向找历代马甲（wash-trading 盘专用，跨链通用）**（外部 FyedK(Solana) 分析考古，2026-07）：庄的冷门微盘常自买自卖、外部买家≈0——"最近的同款买家"往往就是庄自己的历代钱包。**总归集口的历史流入地址列表 = 该庄历代马甲归集头的现成名录**（某案总归集口两年 154 个流入地址），比正向 co-buyer 扫描高效得多。适用前提：先确认该盘外部真实买家稀少（否则名录混入真散户）

**行为半枢纽剔除（正式，机制解释：漏斗形状是服务地址的必然形态）**：度数 >200 剔除线与静态标签库之间存在漏网带——度数 47-200 的 MEV bot/私有路由/聚合执行合约，每个携几十条大额边，足以把上千交易者串成一个假实体（实测 3367 址假簇）。补充规则：**对手方数 ≥30 且 |净留存| < 累计流入 2% 的"过手型"地址一律不作合并边**（与 gatekeeper 漏斗守门员互补，覆盖其未拦截的度数带）；vanity 全零前缀的 gas funder 同样不作 R2 种子。剔除后该案最大簇 3367→136（正常长尾）（来源：ASTEROID(ETH) 分析，2026-07-18）

**【正式·两案】"高扇出≠公共服务商"反向判据（实体自有分发网的认定，与半枢纽剔除并存不矛盾）**：扇出度高（LPT 案 508 对手方）**不足以**判公共服务商——LPT 案 R4 复核用三条判据推翻了"高扇出枢纽=服务商剔除"的初判：①**流量集中度**（单一对手占其流量 45%——公共服务商的流量天然分散）②**生命周期同步性**（与所服务实体同日启停——公共设施不随单一客户生灭）③**下游网络跨代连续性**（实体主仓换代后，该枢纽的下游网络无缝延续服务新主仓）。三条全中=实体自有分发设施，应并入实体（吞吐口径）。与既有"行为半枢纽剔除"规则（对手 ≥30 且过手型不作合并边）**分工**：剔除规则管"不能靠它把外人串进来"，本条管"别把实体自家设施排出去"——先按剔除规则不作串联边，再按本条三判据决定枢纽本身是否并入实体（来源：LPT(ETH+Arbitrum) 分析对抗复核，2026-07-21；第二案=QUQ(BSC) 种子枢纽百万笔级专属互转方向印证，2026-07-22；3.15.0 整编转正）

**【候选·单案】公共代买枢纽 vs 实体分仓的裁决法**：当大量新买家的币源集中于单一枢纽地址时（"供货集中度"疑云），按四特征裁决：①进货方极少且几乎全为池子/路由 ②分发对象数百上千 ③自身净持≈0 ④全天候持续运转——四条齐备=公共 bot 代买执行通道（TG bot/前端路由），**通道集中≠实体集中**，收方各自独立不作关联边（同 CEX 热钱包逻辑）；反之（进货含私人地址/分发对象少而固定/有留存）才升实体分仓假设（来源：ASTEROID(ETH) 分析，2026-07-18，1418 个下游的代买枢纽裁决）（整编 3.15.0 标疑：超 8 版仍单案；因与三测/三段法同属活跃的枢纽裁决主题族保留，下次整编若四特征仍无第二案再降档）

**【候选·单案】枢纽两段处理法（枢纽密集盘 BFS 聚类的实操闭环）**：亿级转账/刷量枢纽密集的标的做聚类 BFS 时，对度数 >200 的枢纽节点执行两段处理：①**不作扩散桥**——BFS 抵达枢纽即停，不经它继续扩散（既有"服务枢纽剔除"的 BFS 执行形态，防大杂烩）；②**种子枢纽保留成员资格**——与实体核心强连接的枢纽（互转笔数/量级远超公共服务水平，如百万笔级专属互转）本身保留在成员表（吞吐口径，现仓另计），只剔它的串联边不剔它的身份（=上方"高扇出≠公共服务商"正式判据的第二案，3.15.0 整编已合并转正）。聚类冻结后的公共设施与边界卫生统一走下条正式规则。（来源：QUQ(BSC) 筛查，2026-07-22）

**冻结后实体成员卫生审计（正式·机制解释+两案）**：P0/P1 名单冻结后、算峰值和画图前，对成员全集强制做三查。①**公共设施剥离**：逐址查 `getCode`、标签库、协议角色与全网服务面；公共路由、锁仓协议、批处理器、金库等即使曾承载本金，也不进永久实体成员表。若能逐计划/逐受益人闭合，只在本金被托管的时段做经济归属，协议自身余额与法律所有权分开。②**尘埃成员清理**：仅收到尘埃、没有自签名动作、没有后续等额回流或同步处置的地址移出，禁止靠图可达性凑成员数。③**边界外一圈反查**：从最终执行/归集网络向外再扫一圈，补查自签名 EOA；只有其正额流入能逐笔闭合回既定网络、且不是公共服务时才可补入。任何增删后必须用新集合重算 current/peak/曲线/附录/state；行为闭环仍只证明同一控制程序或严密协同，不自动升级为同一法律所有人。公共设施不代表受益所有人是机制事实；两案分别在冻结后剥离大量执行通道、以及剥离公共锁仓/批处理设施并清尘埃补漏址后复现。（来源：QUQ(BSC) 分析，2026-07-22；SIREN(BSC) 分析，2026-07-24）

**【正式·两案】公共基础设施先验四测（拟判"归集器/专属枢纽/主仓/专用 bot"前的强制前置；原三测 2026-07-24 升级）**：对任何拟判为体系专属设施的高频合约地址，下定性前按序四测——**①DEX 池接口探测（决定性，先做）**：eth_call 四 selector `token0()0x0dfe1681 / token1()0xd21220a7 / fee()0xddca3f43 / factory()0xc45a0155`＋Sourcify 合约名——四个都有像样返回且 factory 指向已知 DEX 工厂=**公共池，直接判设施桶，后续测试免做**；②`getCode` 判合约/EOA；③**部署时间 vs 代币创建时间**：部署**早于**代币创建=强公共信号（QUQ 案两个初判"归集枢纽"分别早于代币 19.7h/23.6h）——**注意此测对池类单向有效**：早于代币→公共，但晚于代币不构成任何专属信号（池必然创建于代币之后，QUQ 两池 100% 通过"晚于代币"关反而强化了"专属 bot"错觉——①测在②③之前做正是为堵这个反例）；④是否服务其他代币（HyperSync 按 address 反查非本币 Transfer）——**④测首个实锤：币种内视角选择偏差（SIREN 案，2026-07-24 GPT5.6 外部复核揭出）**：「该合约生命周期仅此两日、只服务过这批地址」是以**本币种转账史为分母**得出的假专属——跨币种反查一步即碎。SIREN 报告把"专用原子转发合约"（实为 Hedgey BatchNFTMinter）、"归集主仓＝庄家的单一大钱包"（实为 Hedgey TokenLockup 公共锁仓协议，Sourcify 验证名就叫 "Hedgeys"，一查即现形）写进正文，还把"只服务这两天"当归属铁证——**"在本币种内专属"永远不构成专属证据，专属判定的分母必须是合约全局史（跨币种使用+部署者+部署时间）**。**同模板 code size 指纹语义修正（2026-07-24 反向教训）**：code size 逐字节相同的成对/成批合约，**第一优先解释=同一 factory 的标准实例（公共协议池/克隆）**，第二解释才是同一服务商自写 bot 批量部署——"同模板"本身不构成任何同控/专属证据，只构成"去做①测"的触发器。实锤：QUQ 案两个 22962B"同模板 bot 合约对"（`0x9485…`/`0xb2d8…`）被 GPT5.6 外部复核证伪为 **Pancake V3 QUQ/USDT 0.01%/1% 两个公共池**（22962B=Pancake V3 池标准 bytecode 长度；对照 Uniswap V3 池=22142B），RPC 四 selector 复验实锤——误判污染了 215 址成员表、"bot 世代交接"叙事、体系内部调拨量与历史大仓分类，属全案最重错误（来源：QUQ(BSC) 完整版分析对抗复核 2026-07-22；GPT5.6 外部复核采纳＋链上复验 2026-07-24）

**成员表合约地址准入硬闸（pool-probe，定稿前与复核时各跑一遍）**：实体成员表定稿前，对表内**全部合约地址无差别**批跑四测①（四 selector＋Sourcify 名＋公共标签库对撞）——不是只查被质疑的地址：QUQ 案 R2 复核翻案了 449e 公共路由、剥离了 34 址执行通道，却漏掉同性质的两个池，根因就是复核**沿用了主分析的成员表与"bot"标签**、只对被列为质疑点的地址重探测（复核与主分析共享实体表=正交性盲区的又一实例，参照 evidence-wording §10b 立论）。命中设施（池/路由/EntryPoint/托管 Vault/**锁仓·vesting 协议**）的处理：**从成员表剥离，改记为"实体在该设施持有权益"的载体**（如 V3 池由实体持有 LP NFT；锁仓协议由受益地址持有计划 NFT/受益权），权益走经济控制账穿透（见 report-template 三账本分离），身份归设施桶。**锁仓/vesting 协议（Hedgey/Sablier/TeamFinance/Unicrypt 类）是硬闸的第二类必查设施**：四 selector 池探测对它无效，抓手＝Sourcify/Etherscan 验证名＋④测跨币种反查＋行为形态（多址存入→合约长持→到期等额原路赎回）——SIREN 案两个 Hedgey 合约被当"归集主仓/专用中转"收进核心成员表、整套"归集→洗仓换代"机制叙事实为"批量锁仓→到期赎回"，比 QUQ 公共池案更重（不止成员表污染，机制叙事整体反转），且 SIREN 交付（07-19）早于本硬闸设立（07-24）——硬闸对历史报告的追溯核查同样适用（来源：SIREN GPT5.6 外部复核采纳，2026-07-24）。对抗复核材料清单同步硬项：复核者必须对成员表内合约**重新独立探测**，主分析给的标签一律不信。批跑成本几分钟级（sourcify_check.py＋四 selector 脚本），没有任何理由跳过（来源：GPT5.6 外部复核采纳，2026-07-24）。**硬闸覆盖面扩展：凡被叙事引用为"归集点/中转枢纽/分发中心"角色的合约地址，无论是否进成员表，引用前同过四测**——实锤：某案"18 址归集点"实为 2 个 UniswapV3Pool（22142B 同模板 ×2，getCode＋Sourcify 证伪），因未进成员表绕过硬闸、以"归集点"面目误导一轮狙击集团分析；治本另有标签库侧＝DEX V3 池按 factory 事件批量入库（见 labels/MAINTENANCE.md 扩容路线）（来源：SPX6900(ETH) 筛查，2026-07-25）

**【候选·单案】unverified 合约的 EIP-1167 解引用通道（四测的 proxy 补充步）**：Sourcify/Etherscan 双无验证源的合约，先看 `eth_getCode` 是否命中 EIP-1167 minimal proxy 模式（`363d3d373d3d3d363d73<20字节实现地址>5af43d82803e903d91602b57fd5bf3`，45 字节定长）——命中则**取出实现合约地址再跑 Sourcify/四测，实现合约的验证名即其身份**。实测：0.78% 流通的无验证合约经此路实锤为 BitGo WalletSimple 多签（EIP-1167→实现合约→Sourcify 名 WalletSimple＝BitGo 标准托管栈，配合与所方双向流水归入 CEX 体系仓）。注意 proxy 场景下四测①的 selector 探测会被 minimal proxy 无差别转发干扰，解引用应先于 selector 探测（来源：SPX6900(ETH) 筛查 E4 复核，2026-07-25）

**【候选·单案】"庄自转对倒"定性前的订单流成色拆解（结构性翻案高发区）**：纯 Transfer 图上"币在体系地址与池子间日循环"极易读成庄左手倒右手，但 Transfer 的 from/to 是**代币层**视角；下"对倒/自转"定性前必须升到**订单层**四步——①按 tx.from 统计当日 swap 发起人构成（谁发起交易≠币经过谁）；②ERC-4337 账户抽象单再拆一层：EntryPoint 的 UserOperation sender 才是真实用户（bundler 的 tx.from 只是打包者）；③swap 面按单笔美元金额分桶，"恒定金额×币价≈2^n 美元"档位簇=CEX 积分/刷分订单指纹（路由拆单后单腿非整档→整档统计是刷分量**下限**）；④订单流高峰时段体系库存若纹丝不动=庄只是场地维护方。QUQ 案以此把"日成交 90%+ 庄自转"整体翻案为"约 95% 外部刷分订单流、庄造场收租"，连带作废"一次性合约=马仔""调度服务器操作手册"两条叙事——那批数百个单笔生命周期合约实为币安/LI.FI 路由的 per-tx 执行中间件（getCode 非空+资金全过手零留存+服务全市场订单，谁的交易都经过）。教训一句话：**凡要写"对倒/自转/左右手"，先拆 tx.from 再动笔**（来源：QUQ(BSC) 投后量能翻案，2026-07-22）

**【候选·单案】独立量化/MEV 工作室三重判据（非庄马甲、也非散户的第三类实体桶）**：大额挂单墙/高频 bot 群拟并入庄家体系前，做三重独立性检验——①**资金隔离**：与庄体系全成员零直接资金往来（gas 与本金两条线都查）；②**起源早于标的**：运营者/金库活跃史早于代币创建（数年史+数十万笔级老账户不可能是为本币而设的马甲）；③**多币服务面**：同一套合约/金库同时服务多个代币。三条全中=判独立专业玩家，单列第三类桶（"独立做市/量化承接方"），份额不并入庄控盘口径但**必须单独陈述**（它是订单流大买家/流动性承接方，不是"一群散户"）；其**金库撤墙=专业承接方撤出的领先信号**，设人工哨。识别副产品：gas 网络同源+历史 MEV 协同记录可作该实体的内聚边。QUQ 案 0x9a98 系（多面挂单墙+出金口同汇一个金库）以此从"庄家马甲军团"改判独立工作室（来源：QUQ(BSC) 第三批修正，2026-07-22）

**归属证明的证据学：层数封顶原理与双向合龙（BFS 扩散类聚类的呈现与答辩标准件）**：回答"为什么不继续穷尽 5、6…10 代把下游全对上"——**不是工作量问题，是继续追会毁掉证据**。①链上转账图全连通：步数放宽到 ~10 层，从任何钱包都能"走到"全网一半地址（碰到交易所热钱包再走一步即通向数十万无关用户），层数越深"可达"的含金量越低——**穷举更多代数是稀释证据，不是加固**；故 4 层封顶+碰公共设施立即截断。②归属证明的本质从来不是"钱能不能流到"（全连通图上永远能），而是"**这组动作是否只有同一控制者才做得出来**"——多所分钟级同步提币、同凌晨先后注入同一执行网、gas 同源，每条都是极小概率协同的行为指纹，BFS 可达域只是把指纹串在同一河道上的地图。**⚠指纹准入前置：先排除"协议机械行为"（2026-07-24 SIREN 翻案，本条原例证修正）**——"N/N wei 级等额原路返还"曾列为本条协同指纹例证，被外部复核证伪：返还中枢是 Hedgey 公共锁仓协议，等额原路返还是锁仓到期赎回的**机械必然**，任何独立用户群都会呈现同一形态，零协同证明力；SIREN 报告更用它"直接排除 OTC 交割、托管重组等备择解释"——被排除的托管类恰是真相，论证方向整个反了。**任何行为指纹入册前，必须先对动作中枢跑合约身份四测（见上文），"只有同一控制者做得出"以"排除协议机械行为"为前置**；等额返还剔除后，SIREN 行为群归属由 gas 同源（37/47 同金主）＋903 址同窗锁仓/赎回后的整齐编排支撑——行为群结论不塌，但证据链必须重排。③**双向合龙 ≫ 单向穷举**：自上而下的 BFS 扩散（"我主张它们连着"）与自下而上的池子/通道反向穿透（独立挖的另一条线）在中间地址集上重叠，两条互不依赖的证据链合龙——单向追永远可被质疑"挑了条路走过去"，合龙没法这么质疑；未落入交集的成员由行为指纹（同档位分仓/同中转模式/同通道/同节奏）补焊。呈现纪律：报告与答辩按"指纹为主、可达域为图"陈述，禁把"可达"当归属证据（来源：SIREN(BSC) 交付后问答，2026-07-20）

**「同窗大额动作」的稀有性检验——报协同必须同时给分母（2026-07-25）**：
"两实体相隔 X 秒同步动作"单看时间差不足以定性，**决定性的补充是分母**——把时间窗放大到数日、
统计全链超过某阈值的同类动作总数。KOGE 案：大庄取 800,000 枚、**60 秒后**项目方签名人取 300,000 枚，
而**该三天内全链 >50,000 枚的转账就只有这两笔**，偶然性因此被排除。
纪律：报告"两实体 X 秒内同步"时必须并列给出"同期同量级动作的全链总数"，否则读者无法判断巧合与协同；
配合循环位移置换检验给 p 值更佳（该案 p≈5×10⁻⁴）。**注意这仍是行为指纹不是资金硬边**——
按 §6 聚类硬规则不足以合并实体，正确处理＝维持分列计数 + 正面披露协同证据 + 并列给出合并口径份额。
（来源：KOGE(BSC) 分析对抗复核，2026-07-25）

**gas/共同上游证据的基准率陷阱（证伪操作，2026-07-25）**：
KOGE 案复核一度拿到"两个主体的跨链桥退款地址相同"这个看似铁证的发现，但它自己扫 600 个区块算基准率，
发现该地址占该桥转入腿的 **12.5%–25%**——是交易所提币热钱包不是私有出纳，遂主动撤回该证据。
纪律：任何"共同上游/共同 funder"证据，采纳前**必须算基准率**（该地址在同期同类交易中的占比）。
"共同来源是公共设施则不作关联边"这条 §6 已有，本条新增的是**用基准率量化地证伪**这个操作本身。
（来源：KOGE(BSC) 分析对抗复核，2026-07-25）

**EIP-7702 委托目标不是关联证据（反例，2026-07-25）**：
三个大额账户 `getCode` 全返回 `0xef0100…`（codelen=48）且**委托目标完全相同**，极易判为同一实体；
该目标经 Sourcify 查为 **MetaMask 官方 `EIP7702StatelessDeleGator`**——公共实现，任何人升级智能账户
都指向它。纪律：EVM 案见到 codelen=48 且以 `0xef0100` 开头，**先查委托目标是不是公共实现**，
是则该边一律不成立；账户的真实归属另找资金链证据。
（来源：KOGE(BSC) 分析，2026-07-25）
