# 判例册：供给、分母与记账口径（S 册）

> 供给侧错误的共性：**错了不报警**——内部自洽的模型把系统性偏差带进每一个百分比。核心纪律：一切分母与余额都要有对外部真值的锚（链上 totalSupply / 对面链配平 / 恒等自检）。

## S-01 迁移合约静默改账——重放全绿但余额虚高 【机制成立】

- **触发现象**：2016–2017 世代老币、合约带 `migrate()`/升级迁移史。全量重放的**全部内部自检通过**（mint/burn 闭合、无负余额、accounting_gate PASS）。旁证指纹：浏览器深榜加总远超 100%（GNT 1500 名加总 264%）。
- **禁止推断**：自检全绿＝余额可信。`migrate()` 直接改账本不发任何事件，重放余额可虚高 10 倍而无一自检报警（模型错但自洽）。
- **必做区分检验**：重放收尾必跑**供给真值闸**：`mint_total − burn_total` vs 链上实查 `totalSupply()`（`scripts/lib/supply_truth_gate.py`，fail-closed）。FAIL 处置：余额改走 Multicall3 实时直查；地址全集与转账历史仍可用重放（迁移不改历史事件）；重放余额仅可作"≥阈值超集"筛选（migrate 只减不增，数学严格）。
- **证据不足时**：totalSupply 临时查不到＝**不允许交付持仓结论**，等通道恢复（这是硬闸不是软提醒）。
- **权威与出处**：supply_truth_gate.py 头注（exit 语义）；与 playbook-supply-recon 既有条目（OpenZeppelin burn 只发 Burn 不发 Transfer——那条闭合自检会失败、能被兜住）的区别：本条**闭合自检也通过**，是既有 gate 盲区。出处：GNT 2026-07-28 实测。

## S-02 多链镜像供给被相加 【机制成立】

- **触发现象**：多链部署标的，主链上存在桥/锁仓适配器合约，各链都有 totalSupply。
- **禁止推断**：全局总供应＝各链 totalSupply 相加（GMX 案会低估所有占比 5.8%）；用行情站数字当当期链上分母（那是历史快照，GMX 案对应 2024-09-02 状态——引用第三方供给必须注明抓取时点）。
- **必做区分检验**：**镜像恒等式配平**：主链锁仓适配器余额 ≈ Σ镜像链 totalSupply（差值应在在途误差内，GMX 实测差 0.03%）。配平成立→分母取主链 totalSupply，镜像链不另计；不成立→按 mint−burn 口径逐链核再定。
- **证据不足时**：镜像关系无法确证时双口径并列（主链单独/全链合计）并声明差异影响面；禁止静默选边。
- **权威与出处**：playbook-supply-recon §1b 多链分母判据；analyze-workflow A0 多链硬关卡。出处：GMX 2026-07-26。

## S-03 阵营占比序列缺恒等自检 【机制成立】

- **触发现象**：阵营占比表/演变序列生成环节；分母存在多个候选口径（mint 累计 / mint−burn / 第三方流通量）；或改过阵营名册。
- **禁止推断**：脚本跑通＝口径正确（IQ 旧版合计 221% 直接进了报告，管线无断言不报警）。
- **必做区分检验**：①分母统一＝**当期净供应序列**（mint−burn 逐日，与 S-01 真值闸同源）；②序列逐时点 `assert Σ阵营 = 100%±容差`，超差 FAIL 不出图；③改阵营名册后跑**反向断言**（防"0 个庄"变构造性恒真——名册改错应报错而非输出全零；IQ 重做版实践）；④校验脚本计数为 0 时必须硬失败（fail-closed，"没有不一致"≠"通过"）。
- **证据不足时**：分母序列建不出来只交付单时点快照占比（快照分母可实查）；禁止拿行情站流通量硬算历史演变。
- **权威与出处**：playbook-supply-recon §1 分母口径。出处：IQ 2026-07-26（合计 221% 案）。

## S-04 跟踪集按现仓筛选——历史清零层全盲（已装机械闸 wave_scan） 【机制成立】

- **触发现象**：构建深挖/跟踪名单的环节，名单来源是"当前余额 top N"/现仓快照/现役达标实体表；且分析问题涉及全生命周期（演变/换手/第几轮控盘）。
- **禁止推断**：现役名单里没有＝历史上从未存在（按现仓筛选对已清零地址物理不可见，漏检静默发生、无任何自检报警）；阵营图上散户带收缩默认解读为"散户离场"（PYTHIA 案该时段实为 63% 控盘波次换手）；**"有历史大户兜底桶"＝"历史层处理完了"（桶存在≠桶内被检验过——桶里可能藏着整个协同波次）**。
- **必做区分检验**：①重放全期**逐地址 max 持仓**，按 max≥实体门槛筛跟踪集（而非现仓）；②③已代码化为 `scripts/report/wave_scan.py` 四指纹机械扫描（同窗建仓聚类×喂币专属度×集中清仓窗×等额面额组，阈值全用合并口径）——名册定稿前必跑，候选逐条裁决完毕前历史大户兜底桶不准关闸（analyze-workflow A3.6 硬闸；split-run 下 wave_scan_report.json 为 READY 必产件）。回收去向追踪（候选波次的 recycle_top 字段）：回市场还是进后续实体——后者是两轮同一控制人的关键证据（PYTHIA 案 7.85% 直入后续体系吸筹仓）。
- **证据不足时**：无全量历史数据（仅现仓快照）时，结论上限＝"现役结构如下；历史清零层未检测，无法排除已退场控盘波次"；禁写"历史无控盘"。
- **权威与出处**：analyze-workflow A3.6 三道互补防线硬闸＋wave_scan.py 头注（PYTHIA 回测基线）。出处：PYTHIA W1 前置波次 2026-07-29（重做版整体漏检 341 址峰值 63.44% 波次，交叉核实逐位复算翻案，用户终裁）。**2026-08-01 复发记录**：本判例入库＋三道文字闸装好后 48 小时，split-run 重做版对同一标的原地二次漏检（341 址被打散进兜底桶/散户桶）——检验②③是文字从未代码化、复核 prompt 阈值误写单址口径且装闸无原案回测；根治＝wave_scan 机械闸＋"装闸必附原案回测"元规则（retrospective.md）。**v6.8.0 升级（2026-08-01 用户拍板）**：数据验尸证明 W1 另有两条更简单的被漏的路——①Q1 的 20 个直接上家 9 个是 W1（进货单裸露却"找到并入证据就收工"）、②341 址从未进入任何判据输入集（现仓 ≥0.1% 资格线挡在门外，强指纹从没被代码看过）——闸升级为三道互补防线：wave_scan v2 全体扫描（不限清零层）＋flow_anomaly 枢纽扫描＋entity_source_trace 溯源闸（direct_upstream 进货单义务），全候选成员级裁决闭环接入 freeze 前置；配套 camp_jump_audit 删除（覆盖真空——阵营序列输出侧无骤变报警器——用户确认接受，不承诺永久）。**v6.8.1 加固（2026-08-01 codex 独立验收判"不通过"后返工）**：验收抓出三防线首版的实质缺口——溯源 pro-rata 数学错误（累计流入归一化不扣流出，反例 A收100→出90→B收90 算成 52.6/47.4）、freeze 闸只查文件在场不查内容（空壳台账手填 closure=100 可过）、裁决闭环无语义约束（confirmed 全员 excluded 可过）、D 指纹按首收去重吞掉二轮复收；返工＝溯源重写为祖先子图正向模拟＋FIFO/LIFO 上下界阻断、freeze 升四重内容级前置（自报值一概不作数）、裁决八类拒绝（语义交叉＋名册绑定）、背书漏洞的测试全部翻成反例。元规则补一层：**装闸后要请闸外的人来试着绕它**——自己造的 fixture 天然顺着自己的实现走，绕闸测试必须由独立视角出。
