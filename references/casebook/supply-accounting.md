# 判例册：供给、分母与记账口径（S 册）

> 供给侧错误的共性：**错了不报警**——内部自洽的模型把系统性偏差带进每一个百分比。核心纪律：一切分母与余额都要有对外部真值的锚（链上 totalSupply / 对面链配平 / 恒等自检）。

## S-01 迁移合约静默改账——重放全绿但余额虚高 【机制成立】

- **触发现象**：2016–2017 世代老币、合约带 `migrate()`/升级迁移史。全量重放的**全部内部自检通过**（mint/burn 闭合、无负余额、accounting_gate PASS）。旁证指纹：浏览器深榜加总远超 100%（GNT 1500 名加总 264%）。
- **禁止推断**：自检全绿＝余额可信。`migrate()` 直接改账本不发任何事件，重放余额可虚高 10 倍而无一自检报警（模型错但自洽）。
- **必做区分检验**：重放收尾必跑**供给真值闸**：`mint_total − burn_total` vs 链上实查 `totalSupply()`（`scripts/lib/supply_truth_gate.py`，fail-closed）。FAIL 处置：余额改走 Multicall3 实时直查；地址全集与转账历史仍可用重放（迁移不改历史事件）；重放余额仅可作"≥阈值超集"筛选（migrate 只减不增，数学严格）。
- **证据不足时**：totalSupply 临时查不到＝**不允许交付持仓结论**，等通道恢复（这是硬闸不是软提醒）。
- **权威与出处**：supply_truth_gate.py 头注（exit 语义）；与 playbook-supply-recon 既有条目（OpenZeppelin burn 只发 Burn 不发 Transfer——那条闭合自检会失败、能被兜住）的区别：本条**闭合自检也通过**，是既有 gate 盲区。出处：GNT 2026-07-28 实测。

## S-02 多链镜像供给被相加 【机制成立】

- **触发现象**：多链部署标的，主链上存在桥/锁仓适配器合约，各链都有 totalSupply。
- **禁止推断**：全局总供应＝各链 totalSupply 相加（GMX 案会低估所有占比 5.8%）；用行情站数字当当期链上分母（那是历史快照，GMX 案对应 2024-09-02 状态——引用第三方供给必须注明抓取时点）。
- **必做区分检验**：**镜像恒等式配平**：主链锁仓适配器余额 ≈ Σ镜像链 totalSupply（差值应在在途误差内，GMX 实测差 0.03%）。配平成立→分母取主链 totalSupply，镜像链不另计；不成立→按 mint−burn 口径逐链核再定。
- **证据不足时**：镜像关系无法确证时双口径并列（主链单独/全链合计）并声明差异影响面；禁止静默选边。
- **权威与出处**：playbook-supply-recon §1b 多链分母判据；analyze-workflow A0 多链硬关卡。出处：GMX 2026-07-26。

## S-03 阵营占比序列缺恒等自检 【机制成立】

- **触发现象**：阵营占比表/演变序列生成环节；分母存在多个候选口径（mint 累计 / mint−burn / 第三方流通量）；或改过阵营名册。
- **禁止推断**：脚本跑通＝口径正确（IQ 旧版合计 221% 直接进了报告，管线无断言不报警）。
- **必做区分检验**：①分母统一＝**当期净供应序列**（mint−burn 逐日，与 S-01 真值闸同源）；②序列逐时点 `assert Σ阵营 = 100%±容差`，超差 FAIL 不出图；③改阵营名册后跑**反向断言**（防"0 个庄"变构造性恒真——名册改错应报错而非输出全零；IQ 重做版实践）；④校验脚本计数为 0 时必须硬失败（fail-closed，"没有不一致"≠"通过"）。
- **证据不足时**：分母序列建不出来只交付单时点快照占比（快照分母可实查）；禁止拿行情站流通量硬算历史演变。
- **权威与出处**：playbook-supply-recon §1 分母口径。出处：IQ 2026-07-26（合计 221% 案）。

## S-04 跟踪集按现仓筛选——历史清零层全盲（已装机械闸 wave_scan） 【机制成立】

- **触发现象**：构建深挖/跟踪名单的环节，名单来源是"当前余额 top N"/现仓快照/现役达标实体表；且分析问题涉及全生命周期（演变/换手/第几轮控盘）。同族的 12 个可操作触发场景：①常规 factory/pair 清单不含 V4 单例；②目标 Pancake V3 池按 Uniswap V3 topic 采集后无报错但为 0 行；③先排除池/路由的 `key_edges` 又被拿来解释来源去向；④负载均衡 RPC 台账与最新 `balanceOf` 不等；⑤缓存台账只有入腿或出腿被截断；⑥浏览器持有人榜少报或整址漏榜；⑦GPA 错误体或旧缓存被二跑静默复用；⑧大额变动地址只抽样定性；⑨无 sig 边出现同 slot/同双方/同额多笔；⑩锚点采样只覆盖窗口内活动地址且连续多日无观测；⑪末日强制封口后各闸全绿但倒数第二日到末日任一阵营跳变 >1pp；⑫签名提及 ATA、但 `postTokenBalances` 没有该 ATA。
- **禁止推断**：现役名单里没有＝历史上从未存在（按现仓筛选对已清零地址物理不可见，漏检静默发生、无任何自检报警）；阵营图上散户带收缩默认解读为"散户离场"（PYTHIA 案该时段实为 63% 控盘波次换手）；**"有历史大户兜底桶"＝"历史层处理完了"（桶存在≠桶内被检验过——桶里可能藏着整个协同波次）**。同样禁止把常规池清单当全池、把静默 0 行当无交易、把筛选边/缓存/榜单当完整真值、把无 sig 去重当无损、把末日闭合当中段正确，或把缺失 ATA 余额填成 0。
- **必做区分检验**：①重放全期**逐地址 max 持仓**，按 max≥实体门槛筛跟踪集（而非现仓）；②③已代码化为 `scripts/report/wave_scan.py` 四指纹机械扫描（同窗建仓聚类×喂币专属度×集中清仓窗×等额面额组，阈值全用合并口径）——名册定稿前必跑，候选逐条裁决完毕前历史大户兜底桶不准关闸（analyze-workflow A3.6 硬闸；split-run 下 wave_scan_report.json 为 READY 必产件）。回收去向追踪（候选波次的 recycle_top 字段）：回市场还是进后续实体——后者是两轮同一控制人的关键证据（PYTHIA 案 7.85% 直入后续体系吸筹仓）。对新增 12 场景逐案执行：V4 单例补入池清单并核毛量占比；Pancake/Uniswap topic 与 data 布局分开且目标池 0 行即阻断；以 `daily_delta` 对筛选边做缺口审计；RPC 台账逐钱包对最新 `balanceOf`、历史曲线另用 archive 快照重建；浏览器榜只找候选；GPA 返回体须含合法 result、命中缓存报告 mtime、增量前真扫，冲突先用第三通道查 2–3 个关键址；大额变动地址 100% 定性；无 sig 数据不得判重，正负成对差异须用 ATA tx 级真值替换受害地址；中段数值用日采样或全重放并执行末两日 >1pp 阻断；ATA 不在 `postTokenBalances` 就跳过该采样点、保持前值。
- **证据不足时**：无全量历史数据（仅现仓快照）时，结论上限＝"现役结构如下；历史清零层未检测，无法排除已退场控盘波次"；禁写"历史无控盘"。任一新增场景的真值核验做不了时，只能声明相应池/边/地址/时段未闭合并阻断其数值结论；不得用零行、榜单、缓存、插值或填零代替缺失证据。
- **权威与出处**：analyze-workflow A3.6 三道互补防线硬闸＋wave_scan.py 头注（PYTHIA 回测基线）。新增场景的现役动作见 `data-pipeline-evm-channels.md` 与 `data-pipeline-solana-capture.md`。出处：PYTHIA W1 前置波次 2026-07-29（重做版整体漏检 341 址峰值 63.44% 波次，交叉核实逐位复算翻案，用户终裁）；V4 清单哈基米 2026-07-18；Pancake topic SIREN 2026-07-19；筛选边 QUQ 2026-07-22；RPC 单腿 ASTEROID 2026-07；榜单 TOSHI 2026-07-26；缓存 PUB、抽样 CLUDE（均 2026-07-15）；无 sig 去重 TROLL 2026-07-29；锚点末日封口 GOAT 2026-07-26；缺失 ATA 填零 GOAT 2026-07。**2026-08-01 复发记录**：本判例入库＋三道文字闸装好后 48 小时，split-run 重做版对同一标的原地二次漏检（341 址被打散进兜底桶/散户桶）——检验②③是文字从未代码化、复核 prompt 阈值误写单址口径且装闸无原案回测；根治＝wave_scan 机械闸＋"装闸必附原案回测"元规则（retrospective.md）。**v6.8.0 升级（2026-08-01 用户拍板）**：数据验尸证明 W1 另有两条更简单的被漏的路——①Q1 的 20 个直接上家 9 个是 W1（进货单裸露却"找到并入证据就收工"）、②341 址从未进入任何判据输入集（现仓 ≥0.1% 资格线挡在门外，强指纹从没被代码看过）——闸升级为三道互补防线：wave_scan v2 全体扫描（不限清零层）＋flow_anomaly 枢纽扫描＋entity_source_trace 溯源闸（direct_upstream 进货单义务），全候选成员级裁决闭环接入 freeze 前置；配套 camp_jump_audit 删除（覆盖真空——阵营序列输出侧无骤变报警器——用户确认接受，不承诺永久）。**v6.8.1 加固（2026-08-01 codex 独立验收判"不通过"后返工）**：验收抓出三防线首版的实质缺口——溯源 pro-rata 数学错误（累计流入归一化不扣流出，反例 A收100→出90→B收90 算成 52.6/47.4）、freeze 闸只查文件在场不查内容（空壳台账手填 closure=100 可过）、裁决闭环无语义约束（confirmed 全员 excluded 可过）、D 指纹按首收去重吞掉二轮复收；返工＝溯源重写为祖先子图正向模拟＋FIFO/LIFO 上下界阻断、freeze 升四重内容级前置（自报值一概不作数）、裁决八类拒绝（语义交叉＋名册绑定）、背书漏洞的测试全部翻成反例。元规则补一层：**装闸后要请闸外的人来试着绕它**——自己造的 fixture 天然顺着自己的实现走，绕闸测试必须由独立视角出。
  旁证指纹保留：V4 脉冲日可占全网转账笔数 49–88%、毛量 40–76%；RPC 缓存单腿曾仅有 8,000/13,846 行；Blockscout 曾整址漏掉占流通 4.29% 的持仓；TROLL 无 sig 去重使重放差异达 8.127% 总供应且正负成对；GOAT 41 个跟踪址中 28 个锚点裸奔 >90 天、七个阵营中段全错；投毒样本 99 个。以上数字只作触发/回归指纹，不外推新标的。

## S-05 税币模拟、发射台毛流与曲线成本被当真值 【跨案复现】

- **触发现象**：逐案触发：①代币只对 DEX pair 收税，钱包互转的 `eth_simulateV1` 显示零税，或低活跃窗口没有可比事件；②four.meme TokenManager 买卖双向过账，毛流出接近或超过总供应；③pump.fun 虚拟储备公式按标准参数 `vs0=30 SOL / vt0=1,073,000,191` 能逐位还原买入枚数，但 SOL 成本与关键 tx 实付持续偏离（PUB 实测约低 10%，参数约 32.5/1034M），或毕业迁移笔出现在买家列表。
- **禁止推断**：模拟零税不得推出池路径零税；TokenManager 毛流出不得当持仓、bundle 份额或供应占比；标准曲线参数的成本不得当链上实付，毕业迁移不得当独立买入。
- **必做区分检验**：税币走双路：真实事件差值覆盖池路径，低活跃才用 `eth_simulateV1` 兜底，事件差值只取单侧干净样本。four.meme 必须净重放并核毕业时点存量。pump.fun 对关键笔用 `getTransaction` 的 pre/post balances 校准；PUB 同型参数未重估时，批量值按"重建值 +10% 修正区间"报告，并剔除毕业迁移笔。
- **证据不足时**：缺少池路径干净样本时只写"钱包路径未见税，池路径税率未确证"；不能净重放时不报平台份额；成本未用链上关键笔校准时只报代币数量，不报 SOL 成本。
- **权威与出处**：正确动作见 `data-pipeline-evm-channels.md` 税币/TokenManager 规则与 `data-pipeline-solana-capture.md` 曲线成本规则。出处：BabyDoge 型税币实测；BANANAS31 2026-07-22；PUB 2026-07-14。

## S-06 区块时间与文件更新时间被错当事件边界 【跨案复现】

- **触发现象**：逐案触发：①用"块数×当前平均块时长"描述 BSC 历史事件离发射多少分钟；②手算 unix cutoff，或用文件 `meta.updated` 作为增量覆盖起点。
- **禁止推断**：当前块时长可外推历史硬分叉前区段；文件最后写入时间等于数据末行覆盖时间；命令无报错等于 cutoff 正确。
- **必做区分检验**：历史时间一律取两端区块时间戳差；cutoff 用 `datetime.fromisoformat` 解析后反向验算；增量起点读取数据末行的真实事件时间，不读 `meta.updated`。
- **证据不足时**：任一端区块时间戳或数据末行缺失时，不发布分钟级事件顺序，也不启动可能留洞的增量；先补真值。
- **权威与出处**：正确动作见 `data-pipeline-evm-channels.md` 历史块时长规则与 `data-pipeline-solana-capture.md` cutoff 纪律。出处：BANANAS31 2026-07-22；CLUDE 2026-07-15。

## S-07 V3/V4 单例余额、TVL 与 LP 权益混账 【跨案复现】

- **触发现象**：逐案触发：①PoolManager/Infinity Vault 单例 `balanceOf` 被写成某一池或某实体仓位；②V3 `collect−burn`、V4 `callerDelta`、receipt 净现金流被直接写成手续费；③聚合器逐池 TVL 显示近空池巨额流动性，或按 `(pool,tx_from)` 形成 V4 幽灵仓；④集中流动性池 TVL 仍按稳定币侧×2估算。
- **禁止推断**：单例总余额不得归单池/单庄；单笔净提现不得等同手续费；"曾做市"不得推出目标时点仍控制该池；V2 等值假设不得套到 V3/V4。
- **必做区分检验**：单例余额只作上界，按 poolId、position、tick、salt、owner 重放头寸并穿透实体。V3/V4 分开核池子产生、仓位应得、当前未结算、历史已结算四层；官方头寸查 `ownerOf(tokenId)`、NFT Transfer 与状态链，自定义 manager 再穿 receipt/trace/份额账。TVL 用 `slot0`、两侧 `balanceOf` 与第一方价格复算。
- **证据不足时**：头寸归属未闭合时只报单例上界和 unresolved facility exposure；本金/费拆不开时只写净现金流；TVL 未第一方复算时不得引用面板值入结论。
- **权威与出处**：`lp-fee-accounting.md` 为费、权益与八项对账 gate 的唯一权威；经济控制穿透见 `economic-control-accounting.md`。出处：QUQ 2026-07-22/24 外部复核；EGL1 2026-07-28。
