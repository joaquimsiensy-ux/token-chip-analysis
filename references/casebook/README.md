# 判例库（casebook）——判定环节的失败模式库

> **按判定环节组织，不按币组织**——按币存放的教训，下一个币的分析永远不会读到（IQ/LPT/PENGUIN/PYTHIA 四案托管误判同族复发的结构性根因）。

## 这是什么、不是什么（铁律 1 边界）

- 判例＝**方法级失败模式**：某类判定曾经怎么错、靠什么检验区分。允许带案例出处（与 address-book/惯犯库现行惯例一致）。
- 判例**不是结论先验**：它告诉你"查什么、怎么区分"，不告诉你"这个币也是这样"。禁止把任何判例当成对当前标的的预设答案。

## 六字段结构（每条判例固定）

标题另带 **ID+成熟度**：稳定编号只增不改义；成熟度三档＝单案候选 / 机制成立 / 跨案复现。

1. **触发现象**：什么指纹/场景出现时本条生效（这是检索键，写具体）。
2. **失败原因（禁止推断）**：见到触发现象时，哪个“顺理成章”的结论不许直接下。
3. **必做区分检验**：把两种解释分开的具体动作（查什么、比什么）。
4. **证据要求（证据不足时的结论上限）**：检验做不了时允许的最强表述或停止动作。
5. **正确规则指针**：正确判法只放一行权威位置，不在判例重复规则正文。
6. **案源**：单列翻案来源、日期与原样迁入的历史正文。

## 收录纪律

- 入库门槛：翻案经用户终裁，或复盘经 candidate 流程确认。归档候选由复盘流程(retrospective.md 分流决策树)登记,分析会话不触 archive。
- 单册上限 25KB 或 25 条，超限先合并同族模式，不拆新册。唯一例外＝`*-methods.md` 迁移续册：2026-08-05 methods 案例史整编一次性迁入的存量判例，**只出不进**（禁止新增条目；条目合并进主册或转正后只减不增），同受单册上限与 lint 约束。
- 与 playbook/pipeline 重叠：判例只写指纹与区分检验，正确判法一行指向权威位置，不双写。
