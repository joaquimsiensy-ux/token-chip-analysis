# 判例册：供给、分母与记账口径（S 册续）

> 本分册承接 methods 外移判例；现役规则以对应 playbook 与脚本为准。

## S-08 窗口净额与高换手峰值混账 【跨案复现】

- **触发现象**：窗口归因使用逐 tx 毛流，或把高换手地址各自峰值相加。
- **失败原因（禁止推断）**：往返筹码被重复计数，不能代表窗口净变化或同刻持仓。
- **必做区分检验**：按全窗口逐地址净变化、同 slot/同日末余额与设施剔除重算。
- **证据要求（证据不足时的结论上限）**：无同刻快照或全窗口净账时不发布归因规模。
- **正确规则指针**：playbook-entity-cluster-methods 窗口归因与同刻重放规则。
- **案源**：以下两条自 methods 原样迁入：
  - **暴跌/窗口归因必须用"窗口全期净变化"，"同 tx 净额"仍是毛口径**：按"同 tx 净流出且币进池"累加会把窗口内买回的往返客计成大卖家（实锤：初稿"4,363 卖家/最大 1.51%"被撤换——那个 1.51% 的真实窗口净额为 0；修正后 850 卖家/最大 1.24%）。正解=窗口内每地址全部转账净变化、剔设施、再聚类。与 §9"gross/per-tx 双口径"衔接：per-tx 净额适合单笔归因，窗口归因必须再上一层做全窗净额（NOXA 复核，07-15）
  - **【候选·单案】高换手日的峰值和重复计算陷阱** — **触发条件**：事件日瞬时峰值地址清单的峰值和可能超过 100%，或单址累计买入远超峰值持仓。**必做动作**：把该址标为高速换手参与者；狙击/抢筹规模统一用同 slot/同日末的同时持有口径。**阻断语义**：不得把各址峰值相加解释为同时囤仓，也不得把 N 个 2%+ 峰值址写成 N 个独立实体。**权威脚本**：同刻余额重放与峰值审计。案源：TROLL 2026-07-29。
