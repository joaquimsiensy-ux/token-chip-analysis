# 判例册：实体聚类与成员归属（E 册）

> 聚类错误的共同后果：合并方向错＝虚增庄家占比且复核难以发现；混入设施＝污染本案+殃及惯犯库殃及后续所有案子。核心纪律：合并只认**专属性证据**，入表先过**设施先验**。

## E-01 EIP-7702 委托 EOA 误判合约、通用钱包实现被当关联证据 【机制成立】

- **触发现象**：EVM 地址 `eth_getCode` 有返回值，且多个地址 code 完全相同、以 `0xef0100` 开头+20 字节地址。扩展触发：GoPlus 报 `is_contract=1`；或浏览器/WebFetch 给代理地址一个功能名，但页面名、实现代码与行为不一致。
- **禁止推断**：①判这些地址为合约（`0xef0100`+地址＝**EIP-7702 委托 EOA**，是开了智能账户功能的普通人钱包——判"庄组是否纯 EOA""部署者是合约还是人"时会翻车）；②把"共同委托同一实现"当关联证据合并实体（`EIP7702StatelessDeleGator` 是 MetaMask 通用实现，等同"都用 MetaMask"）；③不得把 GoPlus 单字段或代理页抓取文本当最终合约身份。
- **必做区分检验**：①getCode 结果先查 `0xef0100` 前缀；②任何"共用 XX"特征入聚类证据前先做**普及率检验**：这个 XX 是通用基础设施/通用实现（人人可用）还是专属物（vanity、私有模板字节码、专属 funder）？通用的一律豁免出证据集；③代理合约读取 EIP-1967 implementation slot，再从实现字节码提取 PUSH4 selector 并与实际调用行为互证。
- **证据不足时**：无专属证据各自独立计数；禁止"疑似关联先合并"。实现 slot、selector 或行为任一缺失时，标为"代理身份未闭合"，不得按页面名入实体或设施标签。
- **权威与出处**：playbook-entity-cluster-methods §6 聚类硬规则。出处：IQ 2026-07-26；GoPlus 7702 与代理页误标 bibi 2026-07-12。

## E-02 公共基础设施混入庄家实体/惯犯库 【跨案复现】

- **触发现象**：与庄家体系高频互转/瞬时大额持仓的合约地址，被候选进实体成员表（或惯犯库）。同型两连发：QUQ 两个"bot 合约"实为 Pancake V3 公共池（"瞬时峰 46–48%"实为池内瞬时余额）；QUQ 0x238a=PancakeSwap Infinity Vault 混入 215 址成员表；ERC-4337 EntryPoint 同批被误标。新增逐案触发：①GMGN 榜单操作者 EOA 在 Transfer 中不出现；②代理页名称与实现不一致；③大量地址共同首币来源是 Web3 DEX Router/聚合器半枢纽；④vanity 全零地址被标签库标成攻击者但 `getCode` 为 V4 PoolManager；⑤高吞吐地址几乎每笔转入都在同 tx 等额转出；⑥发射窗 owner delta 出现超过供应量的 AMM/路由瞬时余额；⑦Streamflow feePayer 出现在 gas 溯源链。
- **禁止推断**：把"与体系有资金往来/瞬时持仓高"当成员证据——池子、协议金库、入口合约跟**谁都有**往来。榜单操作者、共同首币来源、公共标签、发射窗瞬时 delta 或服务 feePayer 均不得单独当 Transfer 主体、共同控制边或仓库。
- **必做区分检验**：**公共基础设施先验三测**（任一命中即出实体表、按设施单列）：①getCode 与已知协议标准字节码比对（PCS V3 池标准 22,962B 一比便知）；②部署时间早于代币创建＝公共设施；③多币服务检验（同时服务大量其他代币）。惯犯库入库前同一检验。另须：榜单 EOA 回 tx 层核 `msg.sender` 与事件主体；代理查 EIP-1967 slot+selector；共源地址先过标签库和半枢纽排除；vanity 标签用 getCode+行为复核；高吞吐枢纽算同 tx 等额配对率（近 100% 且零滞留＝管道）；发射窗 delta 排除 AMM/路由；Streamflow 只沿代币流穿透去向。
- **证据不足时**：三测做不全时"未定性合约持仓单列，不计入实体合并占比"；禁止默认并入。tx 主体、实现、配对率或服务面未闭合时一律保留为执行端/设施候选，不得成成员边。
- **权威与出处**：entity_identity_gate INFRA_IN_ENTITY flag（G8 物理拦截）；playbook-entity-cluster-methods §6 服务枢纽剔除。翻案：QUQ 2026-07-22 交付后裁决+07-24 外部复核（用户采纳，"bot 世代交接"叙事作废，体系收缩为 strict 四址 EOA）。新增案源：bibi 2026-07-12；哈基米与 ASTEROID 2026-07-18；QUQ 2026-07-22；LAYOFF 2026-07-15。

## E-03 用结果当筛选条件的循环论证 【机制成立】

- **触发现象**：需要论证某集合的行为特征（如"中转层残留极少、收多少转多少"），而该集合本身是**按这个特征筛出来的**（如按"已清空并转入 CEX"筛出的中转地址集）。
- **禁止推断**：拿被筛集合的统计量当发现——"按清空筛出的集合残留≈0"是恒真式，不是证据（IQ 案实测：子集残留 5,485 枚 vs 完整下游真值 520 万枚，差 **948 倍**）。
- **必做区分检验**：论证下游/集合特征必须用**完整集合**（全下游枚举）再看分布；自查句式："这个集合的入选条件，是不是就是我要证明的结论？"
- **证据不足时**：完整集合枚举不动时，明写"仅对 XX 条件筛出的子集成立，不外推全量"。
- **权威与出处**：playbook-evidence-wording §10 复核纪律（备择解释强制构造）。出处：IQ 2026-07-26。

## E-04 位置匹配漏掉跨批次节拍 【单案候选】

- **触发现象**：跨批次钱包顺序近似一致，但成员增删使位置精确匹配骤降。扩展触发：①两个地址在同一分钟末笔充入同一 CEX；②老仓经一次性中转在数十秒内双跳到新址，前端只显示新址 `transfer_in`。
- **禁止推断**：位置未逐项对齐，不等于不存在同一遍历名单；反向也禁止把 CEX 批处理同分钟直接当同人，或把双跳后的新址表象当独立新仓。
- **必做区分检验**：Spearman ρ + 3000 次排列检验；粗扫与候选池细扫配套，另做留存/换手分流。CEX 时间对齐必须拉同窗全量充值作对照组，同窗地址数 >10 时该分钟指纹零区分力；双跳换仓须重放两跳币流、间隔、金额守恒与新址后续行为。
- **证据不足时**：只有单批次顺序，或未剔除零值事件，不得以节拍成边。未建 CEX 同窗对照组不得用充值时序成边；双跳任一腿缺失时只写"疑似换仓链"，不合并新旧址。
- **权威与出处**：playbook-entity-cluster-methods §6.5。出处：EGL1(BSC) 2026-07-26；AKE 复核 2026-07-19；Solana 洗仓双案实见（见 `data-pipeline-solana-capture.md`）。

## E-05 共同 funder 实为服务枢纽 【单案候选】

- **触发现象**：多个历史大户首次注资来自同一地址，合并后出现大额“离场庄”。扩展触发：①funder 流水含大量 $0 vanity 仿冒/盯梢转账；②Solana 候选 funder 持有巨额 SOL，近千签名仅覆盖数分钟；③上游是 Streamflow 自动提取服务 feePayer。
- **禁止推断**：共同 funder 未经公共性核验，不得直接合并收款方。职业投毒者、高频服务热钱包、自动提取服务的同源均不得当控制边。
- **必做区分检验**：`eth_getCode` + 全历史普通/内部交易出账对手数；按 ≤15、16–1000、>1000 三段裁决。Solana gas 只取最早 SOL 入金，候选 funder 查 `getAccountInfo` 余额与近 1000 签名时间跨度（<10 分钟为服务强指纹）；投毒 funder 查 $0 vanity 服务面；Streamflow 通过代币流而非 gas 边穿透终点。
- **证据不足时**：只看本币或样本窗口内共同来源，不得成边。拿不到全历史服务面、千签名跨度或币流终点时，funder 边只作候选，不进入 strict 实体。
- **权威与出处**：playbook-entity-cluster-methods §6 与 §6.6A。出处：GMX 2026-07-26；AKE 2026-07-19；LAYOFF 2026-07-15。

## E-06 vanity 字符数误当字节数 【单案候选】

- **触发现象**：以前后缀相同和极低随机概率主张同控。
- **禁止推断**：短前缀命中或未复算的概率不得作为关联证据。
- **必做区分检验**：按 1 字节 = 2 hex 逐字节计数，计算地址空间随机期望并与实际命中数比较。
- **证据不足时**：命中数与随机期望同量级，或地址被截断，不得成边。
- **权威与出处**：playbook-entity-cluster-methods §6.6B。出处：GMX 2026-07-26。

## E-07 小额试路后大额跟进并非同人专属 【跨案复现】

- **触发现象**：小额测试后 48 小时内向同一目标发送大额，被直接当作同控挪仓。
- **禁止推断**：场外交割同样会先试路；命中该形态不能直接合并双方。
- **必做区分检验**：核美元整数档开票与接收方后续行为分离；命中任一 OTC 侧即记交割关系。
- **证据不足时**：两项均未明确命中时只能作为强证据之一，单独不实锤确权。
- **权威与出处**：playbook-entity-cluster-methods §6。出处：BANANAS31、PYTHIA、EGL1；2026-08-02 复核补闸。

## E-08 Transfer 循环被误写为庄家对倒 【单案候选】

- **触发现象**：体系地址与池子间代币日循环，Transfer 图看似“左右手”。
- **禁止推断**：代币经过谁不等于订单由谁发起；路由和 ERC-4337 bundler 会隐藏真实用户。
- **必做区分检验**：拆 tx.from、UserOperation sender、美元订单档位与高峰时体系库存变化。
- **证据不足时**：四项未完成不得写“对倒/自转”；整档统计只能作为刷分量下限。
- **权威与出处**：playbook-entity-cluster-methods §6。出处：QUQ 2026-07-22。

## E-09 各址历史峰值相加虚增同时持仓 【机制成立】

- **触发现象**：高换手事件日多个地址峰值之和超过 100%，被解释为多个实体同时囤仓。
- **禁止推断**：同一批筹码多次过手会在每个地址留下峰值，峰值和不是同刻持仓。
- **必做区分检验**：以同 slot 或同日末余额重算同时持有；累计买入远超峰值的标为高速换手参与者。
- **证据不足时**：没有同刻快照时不得报告合并峰值或狙击规模。
- **权威与出处**：playbook-entity-cluster-methods §6。出处：TROLL 2026-07-29。

## E-10 尘埃撒网被截成私人出纳网络 【单案候选】

- **触发现象**：共同地址向多名候选发极小额原生币，候选子集看似一母多子。扩展触发：dust 同时伴随 $0 vanity 投毒流水；或从截断 trace/BFS 文本手补出的地址在主边表全史 0 笔。
- **禁止推断**：只看与大户相交的收款子集，会把公共营销 dust 误写成专属出纳。相似前后缀或手工转述地址不得直接进入 camps/实体表。
- **必做区分检验**：拉 funder 全量收款人、跨币同额同窗重叠和注资发生时点；≤0.001 ETH 仅是提示线。投毒者的一切边排除；每个拟入表地址回 `merged.csv` 核存在性与走量匹配，零历史地址按真实节点重新溯源。
- **证据不足时**：收款人全集或跨币服务面缺失，不得把小额 gas 当合并边。地址无法在主边表复现时必须剔除，不得以"疑似拼写差异"保留。
- **权威与出处**：playbook-entity-cluster-methods §6。出处：CASHCAT 2026-07-13；AKE 2026-07-19；2026-08-02 修订。

## E-11 bundle 阴性被误当非协同 【单案候选】

- **触发现象**：发射窗无同 tx/同块 bundle，遂排除协同；旧稿又把连续扫货误写成原子化。
- **禁止推断**：程序化逐块连续扫货可以完全没有 bundle；“无 bundle”不等于“无协同”。
- **必做区分检验**：拆捆绑原子型与程序化连续型；后者须补同窗建仓和后续同步/分工硬边。
- **证据不足时**：只能写连续扫货候选，不得写“捆绑发射”或合并实体。
- **权威与出处**：playbook-entity-cluster-tiering 命名与计数纪律。出处：BANANAS31 2026-07-22。

## E-12 平台派彩藏住 creator 经济流出 【单案候选】

- **触发现象**：creator 零 DEX 卖出，但经自带预测市场下注、结算和派彩把筹码转给赢家。扩展逐案触发：①同创建者短窗连发多币并把大部转给同一收币地址，但收币方可能是被致敬 KOL；②创建 tx 有多条铸造边，dev-buy 直分地址不是 creator；③链上 creator 被 `set_creator` 换成干净地址而历史发币/RugCheck 指向旧 dev；④letsbonk dev 直分数秒卖回形成"creator 清仓"，同时 Raydium Lock 持续 harvest。
- **禁止推断**：只扫 DEX 不足以证明 creator 零出货；赢家身份不明也不妨碍判断利益流向。同收币地址不得直接写项目方马甲；只看 creator 单址、当前余额或新 creator 履历不得推出项目方无仓/无前科/已弃盘。
- **必做区分检验**：PUB 案市场规模为平台中位 624 倍，赢家 42 胜 1 负、覆盖 70% 市场，建市前备币，大额下注后 53 秒由同利益方 ResolveMarket；另核外部参与仅 2 人、当日零宣传、领彩即卖池。新增场景须：列创建 tx 全部铸造受益地址并作为 creator 系起点；同收币实体核公开身份与后续行为；拉 creator 全发币履历、RugCheck 风险并比对 `set_creator` 前后；letsbonk 跟踪 dev 直分去向、Raydium Lock harvest 与毕业迁移平台常数。
- **证据不足时**：出资方、裁判签发者资金归属与结算时点未收敛时，不得写定向派彩铁证。收币方身份、全部铸造边、creator 变更史或 harvest 任一缺失时，分别只写"收币实体/未闭合 creator 系/当前 creator/收益引擎未核"，不得补成项目方结论。
- **权威与出处**：playbook-entity-cluster-tiering 场景范式。出处：PUB 2026-07-15，两路复核 CONFIRMED；four.meme 连环盘/致敬币外部考古 2026-07；LAYOFF 2026-07-15；USELESS 2026-07-21。

## E-13 日净公式漏掉同日建仓清仓峰值 【机制成立】

- **触发现象**：日终接近零，旧 L2 使用 Σmax(单日净变动,0)，同日等额进出被净额对冲。
- **禁止推断**：旧 L2 未报警，不代表盘中从未越过判级线。
- **必做区分检验**：L2 改为昨日日终余额 + 当日毛流入；发射/毕业/价格 ±50%/阵营变动 ≥10pp 日无条件逐笔。
- **证据不足时**：peaks_summary 缺 v2 公式标记或 trigger_days 闭环时，阻断峰值判级发布。
- **权威与出处**：playbook-entity-cluster-tiering 判级确权边界；peaks_daily.py。出处：2026-08-02 codex 反例与用户裁定。
