# 判例册：实体聚类与成员归属（E 册）

> 聚类错误的共同后果：合并方向错＝虚增庄家占比且复核难以发现；混入设施＝污染本案+殃及惯犯库殃及后续所有案子。核心纪律：合并只认**专属性证据**，入表先过**设施先验**。

## E-01 EIP-7702 委托 EOA 误判合约、通用钱包实现被当关联证据 【机制成立】

- **触发现象**：EVM 地址 `eth_getCode` 有返回值，且多个地址 code 完全相同、以 `0xef0100` 开头+20 字节地址。
- **禁止推断**：①判这些地址为合约（`0xef0100`+地址＝**EIP-7702 委托 EOA**，是开了智能账户功能的普通人钱包——判"庄组是否纯 EOA""部署者是合约还是人"时会翻车）；②把"共同委托同一实现"当关联证据合并实体（`EIP7702StatelessDeleGator` 是 MetaMask 通用实现，等同"都用 MetaMask"）。
- **必做区分检验**：①getCode 结果先查 `0xef0100` 前缀；②任何"共用 XX"特征入聚类证据前先做**普及率检验**：这个 XX 是通用基础设施/通用实现（人人可用）还是专属物（vanity、私有模板字节码、专属 funder）？通用的一律豁免出证据集。
- **证据不足时**：无专属证据各自独立计数；禁止"疑似关联先合并"。
- **权威与出处**：playbook-entity-cluster-methods §6 聚类硬规则。出处：IQ 2026-07-26。

## E-02 公共基础设施混入庄家实体/惯犯库 【跨案复现】

- **触发现象**：与庄家体系高频互转/瞬时大额持仓的合约地址，被候选进实体成员表（或惯犯库）。同型两连发：QUQ 两个"bot 合约"实为 Pancake V3 公共池（"瞬时峰 46–48%"实为池内瞬时余额）；QUQ 0x238a=PancakeSwap Infinity Vault 混入 215 址成员表；ERC-4337 EntryPoint 同批被误标。
- **禁止推断**：把"与体系有资金往来/瞬时持仓高"当成员证据——池子、协议金库、入口合约跟**谁都有**往来。
- **必做区分检验**：**公共基础设施先验三测**（任一命中即出实体表、按设施单列）：①getCode 与已知协议标准字节码比对（PCS V3 池标准 22,962B 一比便知）；②部署时间早于代币创建＝公共设施；③多币服务检验（同时服务大量其他代币）。惯犯库入库前同一检验。
- **证据不足时**：三测做不全时"未定性合约持仓单列，不计入实体合并占比"；禁止默认并入。
- **权威与出处**：entity_identity_gate INFRA_IN_ENTITY flag（G8 物理拦截）；playbook-entity-cluster-methods §6 服务枢纽剔除。翻案：QUQ 2026-07-22 交付后裁决+07-24 外部复核（用户采纳，"bot 世代交接"叙事作废，体系收缩为 strict 四址 EOA）。

## E-03 用结果当筛选条件的循环论证 【机制成立】

- **触发现象**：需要论证某集合的行为特征（如"中转层残留极少、收多少转多少"），而该集合本身是**按这个特征筛出来的**（如按"已清空并转入 CEX"筛出的中转地址集）。
- **禁止推断**：拿被筛集合的统计量当发现——"按清空筛出的集合残留≈0"是恒真式，不是证据（IQ 案实测：子集残留 5,485 枚 vs 完整下游真值 520 万枚，差 **948 倍**）。
- **必做区分检验**：论证下游/集合特征必须用**完整集合**（全下游枚举）再看分布；自查句式："这个集合的入选条件，是不是就是我要证明的结论？"
- **证据不足时**：完整集合枚举不动时，明写"仅对 XX 条件筛出的子集成立，不外推全量"。
- **权威与出处**：playbook-evidence-wording §10 复核纪律（备择解释强制构造）。出处：IQ 2026-07-26。

## E-04 位置匹配漏掉跨批次节拍 【单案候选】

- **触发现象**：跨批次钱包顺序近似一致，但成员增删使位置精确匹配骤降。
- **禁止推断**：位置未逐项对齐，不等于不存在同一遍历名单。
- **必做区分检验**：Spearman ρ + 3000 次排列检验；粗扫与候选池细扫配套，另做留存/换手分流。
- **证据不足时**：只有单批次顺序，或未剔除零值事件，不得以节拍成边。
- **权威与出处**：playbook-entity-cluster-methods §6.5。出处：EGL1(BSC) 2026-07-26。

## E-05 共同 funder 实为服务枢纽 【单案候选】

- **触发现象**：多个历史大户首次注资来自同一地址，合并后出现大额“离场庄”。
- **禁止推断**：共同 funder 未经公共性核验，不得直接合并收款方。
- **必做区分检验**：`eth_getCode` + 全历史普通/内部交易出账对手数；按 ≤15、16–1000、>1000 三段裁决。
- **证据不足时**：只看本币或样本窗口内共同来源，不得成边。
- **权威与出处**：playbook-entity-cluster-methods §6 与 §6.6A。出处：GMX 2026-07-26。

## E-06 vanity 字符数误当字节数 【单案候选】

- **触发现象**：以前后缀相同和极低随机概率主张同控。
- **禁止推断**：短前缀命中或未复算的概率不得作为关联证据。
- **必做区分检验**：按 1 字节 = 2 hex 逐字节计数，计算地址空间随机期望并与实际命中数比较。
- **证据不足时**：命中数与随机期望同量级，或地址被截断，不得成边。
- **权威与出处**：playbook-entity-cluster-methods §6.6B。出处：GMX 2026-07-26。

## E-07 小额试路后大额跟进并非同人专属 【跨案复现】

- **触发现象**：小额测试后 48 小时内向同一目标发送大额，被直接当作同控挪仓。
- **禁止推断**：场外交割同样会先试路；命中该形态不能直接合并双方。
- **必做区分检验**：核美元整数档开票与接收方后续行为分离；命中任一 OTC 侧即记交割关系。
- **证据不足时**：两项均未明确命中时只能作为强证据之一，单独不实锤确权。
- **权威与出处**：playbook-entity-cluster-methods §6。出处：BANANAS31、PYTHIA、EGL1；2026-08-02 复核补闸。

## E-08 Transfer 循环被误写为庄家对倒 【单案候选】

- **触发现象**：体系地址与池子间代币日循环，Transfer 图看似“左右手”。
- **禁止推断**：代币经过谁不等于订单由谁发起；路由和 ERC-4337 bundler 会隐藏真实用户。
- **必做区分检验**：拆 tx.from、UserOperation sender、美元订单档位与高峰时体系库存变化。
- **证据不足时**：四项未完成不得写“对倒/自转”；整档统计只能作为刷分量下限。
- **权威与出处**：playbook-entity-cluster-methods §6。出处：QUQ 2026-07-22。

## E-09 各址历史峰值相加虚增同时持仓 【机制成立】

- **触发现象**：高换手事件日多个地址峰值之和超过 100%，被解释为多个实体同时囤仓。
- **禁止推断**：同一批筹码多次过手会在每个地址留下峰值，峰值和不是同刻持仓。
- **必做区分检验**：以同 slot 或同日末余额重算同时持有；累计买入远超峰值的标为高速换手参与者。
- **证据不足时**：没有同刻快照时不得报告合并峰值或狙击规模。
- **权威与出处**：playbook-entity-cluster-methods §6。出处：TROLL 2026-07-29。

## E-10 尘埃撒网被截成私人出纳网络 【单案候选】

- **触发现象**：共同地址向多名候选发极小额原生币，候选子集看似一母多子。
- **禁止推断**：只看与大户相交的收款子集，会把公共营销 dust 误写成专属出纳。
- **必做区分检验**：拉 funder 全量收款人、跨币同额同窗重叠和注资发生时点；≤0.001 ETH 仅是提示线。
- **证据不足时**：收款人全集或跨币服务面缺失，不得把小额 gas 当合并边。
- **权威与出处**：playbook-entity-cluster-methods §6。出处：CASHCAT 2026-07-13；2026-08-02 修订。

## E-11 bundle 阴性被误当非协同 【单案候选】

- **触发现象**：发射窗无同 tx/同块 bundle，遂排除协同；旧稿又把连续扫货误写成原子化。
- **禁止推断**：程序化逐块连续扫货可以完全没有 bundle；“无 bundle”不等于“无协同”。
- **必做区分检验**：拆捆绑原子型与程序化连续型；后者须补同窗建仓和后续同步/分工硬边。
- **证据不足时**：只能写连续扫货候选，不得写“捆绑发射”或合并实体。
- **权威与出处**：playbook-entity-cluster-tiering 命名与计数纪律。出处：BANANAS31 2026-07-22。

## E-12 平台派彩藏住 creator 经济流出 【单案候选】

- **触发现象**：creator 零 DEX 卖出，但经自带预测市场下注、结算和派彩把筹码转给赢家。
- **禁止推断**：只扫 DEX 不足以证明 creator 零出货；赢家身份不明也不妨碍判断利益流向。
- **必做区分检验**：PUB 案市场规模为平台中位 624 倍，赢家 42 胜 1 负、覆盖 70% 市场，建市前备币，大额下注后 53 秒由同利益方 ResolveMarket；另核外部参与仅 2 人、当日零宣传、领彩即卖池。
- **证据不足时**：出资方、裁判签发者资金归属与结算时点未收敛时，不得写定向派彩铁证。
- **权威与出处**：playbook-entity-cluster-tiering 场景范式。出处：PUB 2026-07-15，两路复核 CONFIRMED。

## E-13 日净公式漏掉同日建仓清仓峰值 【机制成立】

- **触发现象**：日终接近零，旧 L2 使用 Σmax(单日净变动,0)，同日等额进出被净额对冲。
- **禁止推断**：旧 L2 未报警，不代表盘中从未越过判级线。
- **必做区分检验**：L2 改为昨日日终余额 + 当日毛流入；发射/毕业/价格 ±50%/阵营变动 ≥10pp 日无条件逐笔。
- **证据不足时**：peaks_summary 缺 v2 公式标记或 trigger_days 闭环时，阻断峰值判级发布。
- **权威与出处**：playbook-entity-cluster-tiering 判级确权边界；peaks_daily.py。出处：2026-08-02 codex 反例与用户裁定。
