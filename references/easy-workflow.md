# 简化筛查工作流（/token-easy-analysis 专用）

> 用途：批量候选的筹码结构**筛查**——分析引擎与完整版同强度（采集/对账/深度关联/对抗复核一分不减），砍掉背景调研（问 4）与完整报告，交付**两件套单页 HTML**（图 1 含价格右轴 + 阵营划分快照表 + 判定块）。用户人工看完决定是否跑 /token-analyze，**本模式绝不自动升级**。v3.12.0 新增（2026-07-21 用户定，档 A：引擎全保留、交付极简；场景=币安 Alpha/现货初筛候选批量找高控盘标的）。
>
> **省什么、不省什么**：省=背景调研 workflow（整路不做）、完整报告（四问行文/图 2 图 3/P0 流转路径图/附录四件套/监控包）、全套复盘仪式（有发现才走）。不省=全量采集、对账关卡三查、深度关联全套（金库归因/gas 溯源/行为指纹/女巫深挖/关联聚类/P0P1 判级）、对抗复核路数、六条铁律、一币一会话。**省的是交付排版，不是判断质量**。

## 三命令分工

| 命令 | 场景 | 交付 |
|---|---|---|
| /token-easy-analysis | 新标的首次筛查（批量候选） | 两件套单页 HTML + analysis-state.json |
| /token-analyze | 筛查命中转正式，或用户点名深挖 | 完整四问 HTML 报告 |
| /token-update | 已有研报增量刷新 | 轻量更新简报 |

批量候选清单场景注意：**一币一会话铁律不变**——每个候选各开一个会话跑本命令；跨币汇总矩阵不在任何分析会话里做（如需要，由用户在独立轻会话用各币 analysis-state.json 纯机械拼表，不做跨币推理）。

## E0 画像与链路由（=完整版阶段 0，原样执行）

合约地址多源核定 / 总量与流通量多口径分开标注 / **多链硬关卡**（≥2 链先做链分布盘点 + AskUserQuestion 选定范围，禁止拿到地址就按其所在链直接开工）/ 解锁表核定 / 开工版本自查。全文见 SKILL.md 阶段 0。

筛查场景特例：用户常从初筛清单发起并直接给出合约地址与链——地址可直接采信（免多源核定），但**多链硬关卡与供给口径核定不可跳**（初筛表已知有桥版分支陷阱：某链侧 top10 逾 99% 实为桥/设施持仓，主战场在原生链）。

## E1 采集（砍背调路，余三路原样）

三路并行：
1. **全量链上转账**（按链走对应 `data-pipeline-*.md`；EVM 首选 HyperSync Starter 付费 key + 官方客户端 v2，见 pipeline-evm §1 决策树）。**先查预采集**：工作目录已有 /collect-data 产物（`data/v2/` 或 `data/soltx-*`）时直接复用+断点续拉增量，只付增量成本（SKILL.md 阶段 1 预采集衔接段）
2. **标签与安全面**（标签库 lookup + GMGN + 浏览器标签页）
3. **价格序列**（CoinGecko / binance.vision / GT OHLCV——图 1 右轴与判定进场窗口都要用，日线粒度即可）

✂️ **不做**：背景调研 workflow（research-workflows §1 整节不进入）；不碰 Firecrawl / 推特；问 4（项目方背景/官推/大V/水军）不回答，交付物里以一行局限声明代之。

## E2 对账关卡（硬性，三查原样）

余额对账 / 供给闭合 / 时间抽查，形态见各链 pipeline 文档。**不过关不进 E3**——图 1 与阵营表本身就是重放产物，重放有洞则筛查结论整体作废。

## E3 深度分析（引擎与完整版同强度）

按 `analysis-playbook.md` 全序执行：地址身份标注三级兜底 → 金库与核心实体逐笔归因 → 关联聚类全套（playbook-entity-cluster：gas 同源/行为指纹/女巫归集/服务枢纽剔除）→ **庄级实体识别与 P0/P1 判级**（§6a 阈值原样）→ 全量重放出阵营占比序列 → 庄家当前状态评估（§7 结论融入阵营表行描述与判定块，不单独成章）。

- 阵营表的行划分**按实际实体结构细分**（如项目方可拆托管桶/运营分发系/投资人系），粒度与完整版一致——这正是深挖不省的产出物。
- 默认不跑：建仓成本（§6b）、CEX 净流工具（异常时仍可按需启用）。
- 币安 Alpha 在架标的必算 **Alpha 黑箱占比**（场内托管不可见部分），进判定块——黑箱过大时链上可见结构失真，本身就是筛查结论。

## E4 对抗复核（路数不减，面自然缩）

N 路怀疑者（给数据文件路径让其**自己重算**，强制构造备择解释）+ 1 完整性批评，三档判定 CONFIRMED/WEAKENED/REFUTED，纪律同完整版（research-workflows §2）。复核对象=筹码结构结论（实体判级/关联边/阵营划分/重放序列）；无背调结论与长报告文案可核。修正顺序同完整版：先数据管线后文案，图表同步改；修正要点并入判定块下方一行（无附录可印）。

## E5 交付两件套（单页 HTML）

工作目录沿用完整版习惯（`<代币>分析/`，含 data/ charts/），转正式零搬迁。产物三件：

1. **`<代币>筹码筛查_<日期>.html`**（build_html.py 管道，WARN=0 才交付）。md 骨架自含，不套 report-template 全模板：
   - 标题 + 元信息行（数据截止 / 覆盖链与占全局供给% / 供给口径一句）
   - **图 1**：`plot_camp_evolution(..., price_series=...)` 必传价格（右轴黑线，v3.12 规格）+ 斜体题注
   - **阵营划分快照表**：阵营 | 地址数 | 现仓（枚 +【总量X%】）| 定义（实体状态与关键行为融入描述）
   - **判定块**（蓝框 3–5 行）：有无庄及判级结论 / 控盘集中度 / Alpha 黑箱占比（在架必填）/ 一句"是否值得跑完整版"参考意见。**仅参考，不自动转**。
   - 复核修正一行 + 局限声明一行（固定含"未做项目方背景调研（问 4 未覆盖）"）
2. **`analysis-state.json`**（schema 同 report-template「默认交付的机器状态文件」节，**必落盘不可省**——转正式/update 的实体表原料，也是"正文零地址"下的可验证性支点）
3. charts/ 下图 1 png

措辞纪律沿用完整版：【总量X%】/ 正文零地址 / 证据强度分级用词 / 零外部代币名。

## E6 复盘（按需触发，迭代机制不变）

有工具性增量（新坑/脚本变更/管道修正/方法论发现）→ 按 `retrospective.md` 走完整复盘，写入 references + CHANGELOG 版本 +1，与完整版零区别。确无增量 → 会话末一行"E6：无新增"即收，免全套清单仪式。判断标准=是否产生可复用白名单知识（铁律 1 口径）。滚动批量下前几个币复盘会很实，后段同链同形态币自然变薄——按需即可，不硬凑。

## E7 转正式衔接（用户人工决策后）

新会话跑 /token-analyze，同目录开工：

- **直接继承**：全量转账数据 / 对账结论 / 实体聚类与判级 / 阵营序列 / analysis-state.json。同为本次筛查产物（非旧研报），不适用 update-workflow 的"沿用须经检验"条款；但**隔日以上**才转正式的，先按 update-workflow U1 做增量段拼接（筛查 data_cutoff → 现在）再继承，新庄扫描在拼接后的最新持仓榜上做。
- **需补**：背景调研 workflow（问 4）/ 图 2 图 3 / P0 流转路径图 / 完整报告四问行文 + 附录四件套 / 复核扩面（背调结论与新增段结论；已 CONFIRMED 的筹码结构项不重跑）。

## 实测成本基准（滚动更新）

- 首战 QUQ(BSC)：1.03 亿条转账的 Alpha 在架刷量盘，单币全程 **~2.5h**，其中采集 67min 占大头（HyperSync v2 付费档），分析+复核+交付 ~1.5h。亿级刷量盘属重型样本，普通量级候选预期显著更短（来源：QUQ(BSC) 筛查首战，2026-07-22）
