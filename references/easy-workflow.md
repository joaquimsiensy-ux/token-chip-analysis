# 简化筛查工作流（/token-easy-analysis 专用）

> 用途：批量候选的筹码结构**筛查**——分析引擎与完整版同强度（采集/对账/深度关联/对抗复核一分不减），砍掉完整报告（v5.0 起问 4 已从框架整体删除，不再是本模式与完整版的差异点），交付**两件套单页 HTML**（图 1 含价格右轴 + 阵营划分快照表 + 判定块）。用户人工看完决定是否跑 /token-analyze，**本模式绝不自动升级**（档 A：引擎全保留、交付极简，2026-07-21 用户定；场景=币安 Alpha/现货初筛候选批量找高控盘标的）。
>
> **省什么、不省什么**：省=完整报告（三问行文/图 2 图 3/流转路径图/附录四件套/监控包）、复盘（仅用户要求时走）。不省=全量采集、对账关卡四查、深度关联全套（金库归因/gas 溯源/行为指纹/女巫深挖/关联聚类/标签判级/大户排查双闸）、对抗复核路数、全部铁律、一币一会话。**省的是交付排版，不是判断质量**。

## 三命令分工

| 命令 | 场景 | 交付 |
|---|---|---|
| /token-easy-analysis | 新标的首次筛查（批量候选） | 两件套单页 HTML + analysis-state.json |
| /token-analyze | 筛查命中转正式，或用户点名深挖 | 完整三问 HTML 报告 |
| /token-update | 已有研报增量刷新 | 轻量更新简报 |

批量候选清单场景注意：**一币一会话铁律不变**——每个候选各开一个会话跑本命令；跨币汇总矩阵不在任何分析会话里做（如需要，由用户在独立轻会话用各币 analysis-state.json 纯机械拼表，不做跨币推理）。

## E0 画像与链路由（=完整版阶段 0，原样执行）

合约地址多源核定 / 总量与流通量多口径分开标注 / **多链硬关卡**（≥2 链先做链分布盘点 + AskUserQuestion 选定范围，禁止拿到地址就按其所在链直接开工）/ 解锁表核定 / **记账模型准入 gate（3.19 硬闸：accounting_gate 一分钟裁决，BLOCK=硬停报用户，详见 analyze-workflow.md A0）** / 开工版本自查。全文见 analyze-workflow.md A0。

筛查场景特例：用户常从初筛清单发起并直接给出合约地址与链——地址可直接采信（免多源核定），但**多链硬关卡与供给口径核定不可跳**（初筛表已知有桥版分支陷阱：某链侧 top10 逾 99% 实为桥/设施持仓，主战场在原生链）。

### E0b 前置 CEX 黑箱关卡（用户点名时执行；连续三案手写要求后固化，2026-07-22）

用户在命令里附加「CEX 托管黑箱 ≤N% 才继续」类要求时（历史默认 N=20），在 E1 采集**之前**做托管黑箱快照，超线即 AskUserQuestion 停等裁决——防止对"筹码大头躺在所内账本"的标的白烧全量采集（先例：CLANKER 37.6% 中止、Fartcoin 确证 36.97%+疑似 11.15% 中止、GOAT 过关继续、BANANAS31 17.2% 过关继续）。标准动作（Solana 版实测 ~15 分钟；**BSC/EVM 版首战实测 ~30 分钟**，通道对应替换：top100=GMGN holders 快照，认所=标签库 lookup（盲化）+address-book，溯源=HyperSync 定向流水**三层溯源**——未认大仓逐层上溯 1-3 跳中转直到落到已知所热钱包，方向判定"提出出所→链上囤仓"则不算黑箱、是 E3 深挖对象；大额 BNB/gas 币未认址加热钱包画像）：

1. **top 榜快照**：GMGN `token holders --limit 100 --raw`（含 native_balance/transfer 流水/exchange 字段）+ RPC `getTokenLargestAccounts`→owner 映射互验；
2. **三通道认所**：①本地标签库 label_lookup.py（盲化开启）②Vybe v4 top-holders ownerName（Solana CEX 标签荒最大补丁，只用标签不用余额，见 pipeline-solana §4）③历史案 cex_map / address-book 合并表；**币安 Alpha 在架的 Solana 标的**加做④：先对撞 address-book 的 Alpha 托管体系已知地址（库存仓/执行仓/BN111 程序），未命中再对未认多币种大仓跑"Alpha 集齐率判别法"（pipeline-solana-scan §3，一次调用分四档）——Alpha 托管仓常为第一大持仓，漏认会把最大黑箱当成"神秘巨鲸"（PENGUIN 关卡 20.66% 库存仓实证，2026-07-22）；
3. **行为画像分层补认**（标签缺口所兜底）：对未命中大仓查「token account 数 + SOL 余额 + 双向流水」——百余币种+万级 SOL+大流水=热钱包画像（高度疑似 CEX）；「SOL=0+个位数币种+纯转入+金额相近」的分仓群=冷储形态，trace 对手方找统一调度枢纽（命中已知热钱包即实锤归属，Fartcoin 案 11 分仓由 Coinbase 热钱包 3 调度）；
4. **分层报数**：确证（标签多源）/高度疑似（画像未认所）两档分开加总，占流通量口径；桥型托管（Hyperunit 等可跨链穿透者）单列注明；附 Solana CEX 标签缺口纪律（OKX/Bybit/Upbit 免费源基本查不到→真实黑箱只高不低，BSC 侧同款缺口）。**方向判别补强（BSC 首战复核教训）：提出方向≠非所方**——从所提币的下游仓仍可能是所方冷储/运营仓，判别须叠加**跨币种画像**：单币种纯收零 gas 自理=私人囤仓；多币种大额高频进出+与所热钱包双向流水=疑似所方运营仓（实证：某"提币囤仓"复核改判为围绕 Bitget 的 20+ 币种高频运营仓）（BANANAS31，07-22）。**"两可"档纪律（E0b 快照结论的时效边界）**：归属未穿透的单列两可档（如"CEX 提币下游囤仓群——所方冷储 or 个人自托管待定"）**不是终态**——①报数时两可档必须以**保守上限口径同时报数**（中性口径＋保守上限两口径并列，让用户按保守线裁决）；②超线裁决继续后，**E3/E4 必须对两可档复核定向**（gas 供给方溯源＋批量激活窗＋单 tx 等额分发三件套，见 playbook-entity-cluster-methods 托管反转通道条），**E0b 快照结论禁直接沿用进交付**。实证：SPX6900 两可群 E0b 判个人 DCA、E4 经 gas supplier 通道翻转为机构托管，黑箱终值 16.72%→22.19% 过线——用户已按保守上限裁决过、翻转不构成流程事故，保守上限并列报数正是为翻转买的保险（SPX6900 07-25）；
5. **超线问询**：AskUserQuestion 给「中止 / 继续（接受所内大户盲视局限）」两选项并引用先例；中止则落 findings.md 存档（关卡明细+数据资产清单+重启衔接），数据留 data/ 备复用，**不交付两件套**。地址一律从落盘文件取（截断补全=编造，此关卡已实踩一次返工）。

6. **EVM 版通道与流程修正（五币批量实证，2026-07-26：GMX/Arbitrum、TOSHI/Base、IQ/ETH、EGL1/BSC、APU/ETH，四链一轮约 2.5h）**：
   - **通道**：持有人榜 ETH/Base/Arbitrum＝Blockscout v2（免 key，带公共标签，**不支持 `limit` 只能 next_page_params 翻页**）、BSC＝BscScan 网页 §7.2（无 Blockscout 实例）、Avalanche＝Routescan（snowtrace 已 403）；认所＝`label_lookup.py`（盲化）+ 浏览器公共标签；画像＝Blockscout `/addresses/{a}` + `/tokens` + `/counters`。详见 data-pipeline-evm-channels §7.6/§7.7。
   - **⚠ 流程级修正：持有人榜只用于找候选，不能作为占比数字的来源。** Blockscout 榜实测有滞后与遗漏（TOSHI 案漏掉两个共 244 亿枚的大仓、另一仓少报 105 亿），**只靠榜单会系统性低估黑箱**（该案 36.62% → 全量重放后 43.96%）。**正解：E0b 直接对标的拉一次 HyperSync 全量 Transfer 重放**——EVM 小市值标的成本极低（实测 IQ 28.8 万条/29 秒、APU 94 万条/62 秒、EGL1 707 万条/413 秒、TOSHI 1661 万条/865 秒），换来的是①全地址余额（不受榜单覆盖率限制）②一次算清**所有**地址的"资金来自 CEX 比例/转出留存率"③顺带完成供给闭合对账④产物直接留给 E1 复用零重采。榜单+逐地址 Blockscout 溯源只作无采集条件时的降级路径。
   - **GMGN 的 `exchange` 字段只标 DEX 池**（uniswap_v3/pancake_v3/sushi 等），对 CEX 认所**无用**——别拿它当认所通道，它的价值是快速标出"可穿透的 DEX 池"从分母侧剔除。
   - **两可档的判定升级（本案新增，见 playbook-entity-cluster-methods §6）**：筛出"资金≥60% 来自 CEX + 转出≤流入 5%"的静置大仓后，**必须再跑 nonce 基准率法**才能定性——取该热钱包全部同量级收款方随机抽样做基准池，对比 nonce=0 比率（实测普通提币址 0/40，目标群 8/8）。只报"从 CEX 提币后不动"是**不足以判托管的**（外部复核在此点上判我方高估，成立）；补上 nonce 基准率后才能排除"用户提币自托管"这一备择。
   - **分母命名纪律**：`totalSupply − 销毁` 应称"**该链调整后供应量**"而非"流通量"（后者还需排除锁仓/未解锁/金库）。销毁占比大的标的必须扣（APU 案 dEaD 持 19.68%，不扣则黑箱比例被系统性低估约 1/4）。
   - **禁止表述**：「未覆盖部分使真实值只会更高」——该推断只对**确证下限**成立；疑似档归因若被推翻会向下走，方向不定（外部复核指出，成立）。

## E2 对账关卡（硬性，四查原样）

余额对账 / 供给闭合 / **供给真值闸** / 时间抽查，形态见各链 pipeline 文档。**不过关不进 E3**——图 1 与阵营表本身就是重放产物，重放有洞则筛查结论整体作废。

**供给真值闸（v6 起重放收尾必跑，与完整版 A2 同责）**：`python3 scripts/lib/supply_truth_gate.py --chain <链> --token 0x…|--mint <mint> --replay-stats <replay_stats.json> --out supply_truth.json`——重放净供给 vs 链上实查 totalSupply，治静默改账盲区（内部自检全 PASS 但余额虚高，casebook S-01）。exit 0 放行；exit 2＝余额禁用重放改链上实时直查；exit 1＝修通道重跑禁当 PASS。

## E3 深度分析（引擎与完整版同强度）

按 `analysis-playbook.md` 全序执行：地址身份标注三级兜底 → 金库与核心实体逐笔归因 → 关联聚类全套（playbook-entity-cluster：gas 同源/行为指纹/女巫归集/服务枢纽剔除）→ **庄级实体识别与标签判级**（§6a 阈值原样，v5.0 不分 P0/P1）→ **其他大户排查前置双闸**（§6a：≥0.1%/≥0.2% 逐个过批量排查层；实体成员完整性扫描不设持仓下限）→ 全量重放出阵营占比序列 → 庄家当前状态评估（§7 结论融入阵营表行描述与判定块，不单独成章）。

- **重点实体素材装配照跑（3.39.1 补；v5.0 对象改为达到流转图门槛的实体=当前 ≥20% 总供应或 ≥20% 流通的大庄/项目方）**：判级冻结后按 research-workflows §二b 每实体一路并行外包，**`model:'opus'` + `effort:'high'`**。easy 模式下 §二b 的**第 3 节（flow spec 草稿）免做**（本模式不出流转路径图），第 1/2/4 节（逐址持仓时间线、内部转移矩阵、疑点清单）照做——它们正是下一条"阵营表按实体结构细分"的素材源，也是 E4 怀疑者的复核靶子。
- 阵营表的行划分**按实际实体结构细分**（如项目方可拆托管桶/运营分发系/投资人系），粒度与完整版一致——这正是深挖不省的产出物。
- 默认不跑：建仓成本（§6b）、CEX 净流工具（异常时仍可按需启用）。
- 币安 Alpha 在架标的必算 **Alpha 黑箱占比**（场内托管不可见部分），进判定块——黑箱过大时链上可见结构失真，本身就是筛查结论。
- Solana 混合重建标的：**锚点两扫描为建议必做步**——全 owner 峰值普查（≥1.5% 档，出历史大仓名单含已离场者）+ 全史前三涨跌日×锚点对照（事件日实体动作），零边际成本，防完整性复核 must_add 批量翻案（单案经验：GOAT 2026-07-22；操作见 pipeline-solana §11.3）。

## E4 对抗复核（路数不减，面自然缩）

N 路怀疑者（给数据文件路径让其**自己重算**，强制构造备择解释）+ 1 完整性批评 + 1 路外部异构怀疑者（codex/GPT-5.6-sol 横扫全部结论，3.40.0，见 research-workflows §2），三档判定 CONFIRMED/WEAKENED/REFUTED，纪律同完整版（research-workflows §2）。复核对象=筹码结构结论（实体判级/关联边/阵营划分/重放序列）；无长报告文案可核。修正顺序同完整版：先数据管线后文案，图表同步改；修正要点并入判定块下方一行（无附录可印）。执行顺序注意：**cluster_sensitivity 扰动前置件依赖 analysis-state.json**——easy 模式 state 是 E5 交付物，跑 E4 前先把 state 骨架落盘（实体表定稿即可生成，不必等判定块），否则扰动敏感度报告做不出来（BANANAS31，07-22）。

## E5 交付两件套（单页 HTML）

工作目录沿用完整版习惯（`<代币>分析/`，含 data/ charts/），转正式零搬迁。口径注：**"两件套"指 HTML 页面的两大内容件（图 1＋阵营划分快照表）；落盘产物为三件**：

1. **`<代币>筹码筛查_<日期>.html`**（build_html.py 管道，WARN=0 才交付）。md 骨架自含，不套 report-template 全模板：
   - 标题 + 元信息行（数据截止 / 覆盖链与占全局供给% / 供给口径一句）
   - **图 1**：`plot_camp_evolution(..., price_series=...)` 必传价格（右轴黑线，v3.12 规格）+ 斜体题注
   - **阵营划分快照表**：阵营 | 地址数 | 现仓（枚 +【总量X%】）| 定义（实体状态与关键行为融入描述）
   - **判定块**（蓝框 3–5 行）：有无庄及判级结论 / 控盘集中度 / Alpha 黑箱占比（在架必填）/ 一句"是否值得跑完整版"参考意见。**仅参考，不自动转**。**④的理由纪律（GOAT 外部复核教训）**：“不推荐完整版”的理由**禁止引用本次未确证/被复核降级的定性**（“大仓是调度商所以不用深挖”——该定性证据没落盘时理由即塌）；≥20% 级实体**身份未确证**时禁写“不推荐”——20%+ 的未知身份实体本身就是跑完整版的最强理由，用数据缺口反证“无价值”是循环论证。此时改写“完整版增量点=确证该实体身份/补 X”，把决定留给用户（GOAT GPT5.6 外部复核采纳，07-24）。
   - 复核修正一行 + 局限声明一行。**阴性结论覆盖披露**：混合重建/锚点抽样标的写"无其他庄/离场实体共 N 个"前，先出锚点观测峰值 ≥1% 历史地址的清点数（已深挖 N/M），阴性结论必挂"已深挖 N/M、锚点为抽样"限定——抽样数据禁用"共/无其他"全量普查用词（对照表有行）（GOAT GPT5.6 外部复核采纳，07-24）
