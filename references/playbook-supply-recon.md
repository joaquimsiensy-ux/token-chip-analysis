> v3.5.0 整编由 analysis-playbook.md 主题拆分而来（2026-07-18，ASTEROID(ETH) 复盘会话）；**规则逐条原样迁移、零改写**，来源注记均在原行尾。四问框架总纲与分册路由见 `analysis-playbook.md`（索引）。

## 1. 供给基线核定（一切百分比的分母）

**三套口径必须分开拿、分开标注、分开使用，禁止混用：**
- **链上实查口径**：totalSupply/getTokenSupply 直查，精确到最小单位；扣减烧毁地址后得链上可流通基数。
- **第三方流通口径**：CoinGecko/CMC 的 circulating supply（含其对锁仓的人工认定），只作对外可比口径引用，标明"XX 口径"。
- **名义已解锁口径**：tokenomist/DropsTab 类解锁表的"累计已释放额度"——这是**额度**不是**流通**，已解锁未必已进入市场。

**口径混淆是五次分析中最高频的结论级错误源**，四种实翻车形态（来源：五会话共见（IO/OPN/FIL/SIREN/HYPE），2026-07）：
- 把解锁表的"名义已解锁"当成"当前实际流通"，两数可差近一倍（来源：OPN(BSC)，2026-07）
- 现货持仓快照不含质押部分，直接用会得出大户"几乎全员清仓"的假象（来源：HYPE(Hyperliquid)，2026-07）
- 浏览器榜单存在"过滤后 account 榜"与"全量富豪榜"两种口径，前者漏掉 miner/multisig/合约类大户（来源：FIL(Filecoin)，2026-07）
- 链上实查总供应与 CMC 流通量是两套数，报告里必须分开注明来源（来源：IO(Solana)，2026-07）

**执行规则：**
- 引用任何第三方指标前，先核对该字段的原始标签和定义，再决定它对应三套口径中的哪一套（来源：OPN(BSC)，2026-07）
- 一切"占流通 %"的结论必须写明分母口径；基于快照的指标必须声明含不含质押/锁仓（来源：HYPE(Hyperliquid)，2026-07）
- 被用户质疑数字时，用可复算的拆数回应（各分项相加还原总数），不直接改口；同时主动复查相邻数字，有出入即修正（来源：OPN(BSC)，2026-07）
- **★权限双轨核验（Ownable 弃权 ≠ 无增发权，AccessControl 是第三方安全面的口径盲区）**：GMGN/GoPlus 的 renounced=true 只读 Ownable 的 owner()——对 AccessControl 合约不查角色。凡合约源码含 AccessControl：DEFAULT_ADMIN/MINTER 等角色逐个 `hasRole` eth_call 亲验（selector `0x91d14854`），角色授予史用 RoleGranted 事件 topic0（keccak of `RoleGranted(bytes32,address,address)`）从**部署块**起全史拉取；且"角色在手"与"能否增发"分开验证——实测 creator 仍持 ADMIN+MINTER 但 mint 计数器 immutable 打满、增发链上不可能，两层各自查完才可写"增发已锁死/未锁死"（供给分母的未来变化必须由这两层共同决定）（来源：PING(Base) 分析，2026-07-17）
- **【候选·单案】vesting 工厂枚举法（自建解锁表，精度比第三方源高一个量级）**：项目用 VestingFactory/TempHoldingFactory 类工厂批量部署锁仓时，拉工厂合约的创建事件全史（Etherscan V2 getLogs 1000 条/页即可）→ 一次拿全全部子合约地址+受益人+声明额度+期限（SQD 案 257 个 vesting 合约一次枚举）；工厂地址从官方合约仓库 README/文档取。配套口径纪律：**事件里的额度是"声明额度"（expected），实际注入以链上转账为准**——两口径分开列，缺口本身就是发现（声明了没打款/超额注入都值得追）（来源：SQD(Arbitrum) 分析，2026-07-20）

## 2. 对账关卡（硬性 gate，不过不进分析）

**总原则：重建/采集结果必须与独立数据源精确对表后才允许进入分析。对不上 = 数据有洞 = 回去补数据，不是调整阈值或口头解释。** 各链 gate 形态并列如下，做哪条链就执行哪套：

**EVM（全量事件重建路线）三重校验：**
- 全网余额和 = 0（mint 计负、burn 计正后逐笔累加）（来源：SIREN(BSC)，2026-07）
- 重建余额 vs GMGN top10 逐个对比，要求 **10/10 精确到个位**；实测数据到 97% 时对账 4/10 MISMATCH、补扫完成后 10/10 全过——证明该 gate 能兜住数据缺口（来源：OPN(BSC)，2026-07）
- 多链部署的代币做跨链总量对账（A 链余量 + B 链流通 ≈ 总量），wei 级闭合（来源：OPN(BSC)，2026-07）
- 加分项：重建出的实体控盘占比若与第三方分析师独立披露的同口径数字偏差 <1 个百分点，即构成互证，是结论可信度的最强背书（来源：SIREN(BSC)，2026-07）

**Filecoin（浏览器 API 准全量路线）：**
- 总量恒等式自检：totalSupply = vested + mined + reserveDisbursed（来源：FIL(Filecoin)，2026-07）
- 榜单抓完立即做唯一性断言（assert 无重复地址）+ 跨页自洽校验（如 pageSize=100 第 2 页首条 == pageSize=50 第 4 页首条），别等分析阶段才发现分页参数失效（来源：FIL(Filecoin)，2026-07）
- 流水加总出的净流量用"链上余额变化"独立复核；高频地址流水有截断时，以余额差校正净流并如实标注（来源：FIL(Filecoin)，2026-07）

**Hyperliquid（官方 API + 快照路线）：**
- 同一指标用两个独立来源对表（第三方面板逐日数据 vs 链上快照差分），**偏差 <1%（实测 0.7%）才可按最高证据级措辞呈现**，否则措辞降级（来源：HYPE(Hyperliquid)，2026-07）

**Solana（免费 RPC 无历史回放时的轻量形态）：**
- 至少做：双口径核定（§1）+ 机械解锁金额整除自证——月转出额能被"配额总额 ÷ 归属月数"整除，即反推还原出 vesting 合约参数，数据自洽性由此自证（来源：IO(Solana)，2026-07）
- 无系统性对账 gate 本身要写进报告局限（历史部分依赖第三方口径）（来源：IO(Solana)，2026-07）

**时机纪律：** gate 以数据补扫完成（remaining=0）后的那一轮为准；数据未齐时预跑对账只作提前预警口径问题用，不作放行依据（来源：OPN(BSC)，2026-07）。

## 8. 创世/空投 cohort 留存 + 质押修正

- cohort 定义：创世分配/空投名单（有官方全量表的直接用，如 genesis 余额表；没有的用首批 claim/分发接收地址重建）（来源：HYPE(Hyperliquid)，2026-07）
- 留存率 = 当前持有（含质押）/ 初始分配，分档统计（如 ≥90% / ≥50% / ≥10% / 清零）
- **快照口径必须声明含不含质押**：现货快照不含质押中的部分时，把币质押了的大户会被误判为清仓——曾出现修正前后"保留≥50% 的大户数量"相差近一个数量级、结论从"几乎全员清仓"整体反转的案例。凡链有原生质押/锁仓，留存与集中度指标一律先做质押修正（逐地址查质押余额合并）再计算（来源：HYPE(Hyperliquid)，2026-07）
- **top-N 快照做留存有幸存者偏差**：掉出榜外 ≠ 卖出（可能只是被质押挪出现货榜或被稀释）；留存分析要用全量快照或逐地址点查，不能只看榜单变化（来源：HYPE(Hyperliquid)，2026-07）
- **【候选·单案】质押/worker 押金桶的内部人构成分解（"协议锁仓"表面中性、实际可能高度内部化）**：把质押押金合约的存入方逐个分层——①官方自营地址直押（硬边）②官方 vesting 合约直押 ③vesting 受益人地址直押 ④真外部 EOA——前三层都是内部人押金，只有④是外部参与。SQD 案 2.395 亿押金中真外部仅 3,940 万，"协议质押"桶按表面口径会被读成社区参与度的证据。呈现用区间：内部化程度给"硬边下界（仅①②）~ 含受益人上界（①②③）"两档，避免受益人归属争议把结论打死（来源：SQD(Arbitrum) 分析，2026-07-20）
