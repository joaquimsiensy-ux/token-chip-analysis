# 报告结构与写作纪律（庄家行为分析版）

> 框架版本：v2.0（2026-07-14，用户指定九条修改定型；由 v1.1 五问版迭代而来）。
> 本版核心变化：五问改四问（删建仓成本命题、官推改项目方背景调查）；庄级实体改
> P0/P1 标签体系（取代旧"庄#N"扁平计数）；图 1/图 2 前置到 TL;DR 顶部；P0 实体
> 必配全周期流转路径图；正文钱包一律标签制、代币数量一律带【总量X%】；取消行内
> 置信度 tag；观察哨后必须给两档监控建议。

**交付物：自包含单文件 HTML**（图 base64 内嵌 + 末尾机器可读 JSON 附录），输出到用户工作目录。
管道：先写 `报告.md` + `charts/*.png`（标准图用 `scripts/report/standard_charts.py`，流转图用 `scripts/report/lifecycle_flow.py`）+ `appendix.json`，复核修正全部落定后：

```bash
python3 scripts/report/build_html.py --md 报告.md --out 报告.html --json appendix.json
```

**先审 md 再出 HTML**——复核 agent 和用户都直接读 md，别拿 HTML 当第一稿。PDF 不再默认交付，仅当用户点名要 PDF 时用 `md2pdf.py`（语法兼容）。

## 四问框架（每次分析的固定命题，TL;DR 必须逐问直答）

1. **有几个庄？**（按下节标签体系识别与分级计数：项目方 / 大庄 / 小庄 / 离场庄 / 狙击集团 / 刷量地址）
2. **每个庄什么类型？** ①单地址明牌 ②多地址·互转/gas 同源·明牌 ③伪装分散·行为指纹一致（类型学见 analysis-playbook §6a）
3. **各阵营全历史持仓占比如何演变？**（占**总供应量**的比例；锁仓/销毁必须单列体现；标准图 1/2 呈现，含建仓后加减仓与拉升期是否出货的解读）
4. **项目方背景调查**（创始人与项目历史含黑历史、推特/Discord/Telegram 运营情况、大V关注量、互动数与浏览量、热度综合评估与水军嫌疑；无项目方的看 dev。方法见 research-workflows §1 背景调查路线）

**建仓成本不再是固定命题**（v2.0 删除旧问③）：不再设独立章节；仅当某实体的出货获利、浮盈状态等结论需要成本参照时，按 playbook §6b 方法按需计算并就地引用。

**开放条款——四问之外必答第 5 条"本次特有发现"**：TL;DR 在四问直答后必须带第 5 条——链上任何不属于四问的显著结构性异常（暴跌/暴涨归因、假量对倒矩阵、流动性池异动、治理/权限异动、跨链桥异常等）在此给一句话结论，并单列正文章节展开；确无特有发现时明写"无"（这也是结论，防读者误以为没查）。禁止因"框架未覆盖"而略去。

**问 3 的 vesting 附加要求**：标的带解锁表/vesting 的（阶段 0 已判定），问 3 必须包含"**未来 6–12 个月解锁日程与量级**"小节（数据源见 research-workflows §1 路线 1，多源交叉；与观察哨联动——下一个解锁日就是天然检验点）。纯 meme 币无解锁结构的，此小节免除。

## 标签体系与重要度分级（v2.0 核心，问 1 的呈现标准）

操作定义（认定规则、峰值取法、合并口径细则）见 analysis-playbook §6a；本节管报告怎么写。

| 标签 | 重要度 | 认定标准（实体合并口径=含全部疑似关联地址，同一时刻合并计算） |
|---|---|---|
| **项目方** | **P0** | 金库、创始人、团队、基金会、vesting 托管、项目方做市仓等一切与项目方相关的实体，**无论持有份额** |
| **大庄** | **P0** | **当前**持仓 ≥20% 总供应 或 ≥20% 流通 |
| **小庄** | P1 | **当前**持仓 ≥5% 总供应 或 ≥10% 流通（未达大庄线） |
| **离场庄** | P1 | **同一时刻历史峰值** ≥10% 总供应 或 ≥15% 流通，且当前既非大庄也非小庄 |
| **狙击集团** | P0 或 P1 | 发射/开盘窗口协同狙击的实体，只要识别出就单独打标签、**不与"庄"混排**；当前持仓 ≥20% 总供应或 ≥20% 流通为 P0，否则 P1（历史峰值曾达标但已大幅出货的按 P1，其出货路径仍需完整分析并在正文注明峰值规模） |
| **刷量地址** | P1 | 对倒刷量执行地址（集群），单独打标签；可证明与其他集团关联时标复合标签"大庄#N·刷量地址""离场庄#N·刷量地址" |

- **报告只对以上标签实体展开分析**。其他大户（当前 ≥1% 总供应或 ≥2% 流通、未入任何标签）与散户只作为阵营出现在标准图 1 中，正文不单独分析、不逐个溯源。
- 编号规则：大庄/小庄按当前持仓降序编号（大庄#1、小庄#1…），离场庄按历史峰值降序，狙击集团仅一个时不编号、多个时 #1/#2；项目方不编号（内部钱包编号区分）。
- **钱包标签制（正文与图例的唯一写法）**：`项目方钱包#1`、`大庄#1钱包#2`、`小庄#2钱包#1`、`狙击集团钱包#3`、`离场庄#1钱包#1`。**报告正文（含表格、图、题注）一律用标签，不出现任何形式的地址（截断的也不行）**；标签 ↔ 完整地址对照只放附录 B 与 JSON 附录。类型三分类（问 2）作为实体属性写在小节标题与 JSON，如"大庄#1（类型②·多地址互转）"。

## 全周期流转路径图（P0 级实体必配，v2.0 新标准图）

**触发**：每个 P0 级实体（项目方、每个大庄、P0 级狙击集团）各配一张，放在第三章对应实体小节内。P1 实体不强制，其流转结构复杂且承载关键结论时也可配。

**内容要求**：
- 覆盖该实体全生命周期：币从哪来（铸造/金库/市场买入/接收分配）→ 中转/拆分结构 → 去向终点（CEX / 休眠仓 / 销毁 / 续持 / 在途）
- 节点命名一律钱包标签制（不出现地址）；关键转移标注时点 + 数量【总量X%】
- 底部账目行必须配平（总量 = 各去向之和，各项带【总量X%】）；意图不可区分时在账目行并列写（"高位变现 或 做市备货，链上不可区分"）

**工具**：`scripts/report/lifecycle_flow.py` 的 `draw_lifecycle_flow()`——数据驱动自动布局（框高自适应/箭头标签白底垫片/账目行独立灰条），不要再用 chart_style.flow_box 手摆坐标。样图（通用化、数字虚构）：`references/examples/lifecycle-flow-sample.png`。

**防拥挤排版纪律（画前自查，超限就精简或拆图）**：节点标题 ≤14 全角字符；框内每行 ≤16 字符；边 label ≤2 行、每行 ≤14 字符；每列节点 ≤5 个、列数 ≤5；更复杂的结构拆成"主路径图 + 细节图"两张。

## JSON 附录 schema（`appendix.json`，供后续监控脚本消费）

### 监控抽取块硬性标准（用户看板方指定格式，2026-07-13，逐字执行）

报告 HTML 末尾必须内嵌机器可读 JSON 附录，嵌入形式**固定**为：

```html
<script type="application/json" id="report-extract">…</script>
```

- **id 必须是 `report-extract`**：用户的看板/监控系统只认这个 id——历史教训：曾有报告写成自定义 id 导致自动抽取失败。一律走 build_html.py 管道出 HTML，别手写嵌入。
- **JSON 顶层四键必备**（看板按键取值，键名一字不可改；build_html.py 缺键会打 WARN 拒绝交付）：

```json
{"chip_summary": {"zhuang_count": 庄家组数,
                  "total_share_pct": 庄家合计持仓占总供应的百分数,
                  "total_tokens": 合计枚数,
                  "last_action": "庄家最后一次链上动作一句话"},
 "addresses": [{"address": "0x开头的完整地址，绝对不要缩写省略",
                "chain": "bsc|eth|base|sol|robinhood",
                "role": "钱包标签+一句话角色（如：大庄#1钱包#2·拆分中枢）",
                "balance_est": 当前持有枚数,
                "group": "同一关联集群填相同组名（组内互转不算流出），独立地址留空",
                "sentinel": true或false,
                "watch": true或false,
                "why": "一句话：为什么要监控/为什么跳过",
                "round_target": 可选_整数橱窗仓的整数目标枚数,
                "watch_return": 可选_true}],
 "unlock_events": [{"date": "YYYY-MM-DD", "label": "解锁内容一句话"}],
 "source_line": "数据截至时间+口径"}
```

**addresses 字段纪律（交付前逐条对照）**：
- **address 必须完整**，绝对不要缩写省略——一律从落盘数据文件复制；build_html.py 见省略号/星号会 WARN
- **chain** 小写枚举：bsc / eth / base / sol / robinhood；新链沿用小写简名扩展（如 hyperliquid、filecoin）
- **role 以钱包标签开头**（与正文、附录 B 一致），后接一句话角色——看板卡片直接显示，正文读者拿标签来这里反查地址
- **group**：同一关联集群填相同组名（看板视组内互转为内部调仓、**不算流出**）；独立地址留空 `""`
- **sentinel=true 只给「理应长期沉睡、任何转出都是重大事件」的地址**（锁仓合约、从未动过的金库、零卖出囤仓鲸）；会周期性正常动的地址（空投池、税池、做市、持续发放的奖励池）**必须 sentinel=false**，否则看板天天误报红卡——sentinel 布尔值与第七章"转出即预警清单"一一对应
- **watch=false 的也要列出**便于审计（交易所热钱包、流动性池、纯 gas 资金源），why 写清为什么跳过
- **round_target**（可选）：该地址是「整数橱窗仓」（持仓刻意停在 1000万/500万 这类整数上的操盘指纹，playbook §6a）时填整数目标枚数，看板在它「破整」时红卡告警；不是就**省略该字段**
- **watch_return**（可选）：已清仓离场但值得盯「回场」的地址（如发射团队、历史主庄）填 `true`，看板在它重新持币时红卡告警；不是就省略

**阵营演变图的抽取约定**：各阵营持仓占比演变图（标准图 1）在 HTML 里内嵌为 `<img id="chart-camps" src="data:image/png;base64,...">`（或 alt 含「阵营」二字），看板会自动抽出独立 png 使用。build_html.py 已自动给 alt/题注含「阵营」的第一张图加该 id——md 里图 1 题注用标准名"各阵营持仓占比演变"即天然满足（图 1 前置到 TL;DR 不影响该约定，仍是全文第一张匹配图）。

## 证据强度呈现（v2.0：取消行内置信度 tag）

- **不再使用任何行内置信度/证据 tag**——[HIGH/MED/LOW]、[单源, MED]、[INFERRED]、[UNPROVABLE]、"TAG：链上实查"这类方括号标注全部取消（用户 2026-07-14 定）。
- 纪律本身全部保留，改用自然语言融入行文：证据强度用固定分级用词（**链上铁证 / 高度疑似 / 疑似 / 未能确证**）写进句子；意图判定两种解释并列写；单源信息在句中注明"此为单源信息（来源：XX），未获独立佐证"；不可观测项写"链上不可见/无法证明"。
- JSON 附录等机器可读字段不受影响。
- REFUTED=0 也如实写进修正记录——"复核没推翻任何结论"本身是信息。

## md 排版约定（build_html.py 与 md2pdf.py 共同支持的语法）

- `> i 文字` → 蓝色信息框（TL;DR/图下结论解读）；`> ! 文字` → 红色警示框（风险提示/"该图未绘制"说明）；`> 文字` → 普通灰引用
- `![题注](charts/fig1.png)` 独立成行，后紧跟一行 `*斜体题注*` → 图与题注绑定
- 表格列数不限但超 6 列考虑拆分（HTML 可横滚，PDF 会裁切）
- **正文（含表格）不出现地址**——一律钱包标签；完整地址只在附录 B 与 JSON 附录（v2.0，取代旧"表格可截断为前6…后4"规则）
- 事件清单行首用 ①②③（`plot_price_events` 返回值已带）
- 关键数字（地址/哈希/金额）一律从落盘数据文件复制，禁止凭记忆敲
