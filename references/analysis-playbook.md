# 分析方法学 Playbook（链无关）

本文档是 token-chip-analysis skill 的核心方法文档：从"数据已到手"到"结论可发布"的全部分析规则。数据通道与采集工程见 `data-pipeline-evm.md` / `data-pipeline-filecoin.md` / `data-pipeline-hyperliquid.md`，环境坑见 `environment.md`，报告产线见 `report-template.md`。

**来源会话代号**（正文行尾标注用）：SIREN(BSC)、OPN(BSC)、FIL(Filecoin)、HYPE(Hyperliquid)、IO(Solana)、bibi(BSC)、CLAW(Solana)、GME(Robinhood)、RAXOL(Robinhood)，均为 2026-07；后续新增来源按行尾全名+日期标注，不再回改本表。注：IO 会话原始记录（Windows jsonl）已于 2026-07-12 由用户找回并逐条比对，本文档所有 IO 来源条目均获实录确认，实证强度与其余各份等同。

**四问框架**（每次分析的固定命题，报告必须逐问直答；v2.0 起取代五问，2026-07-14 用户定）：
1. **有几个庄**（按 §6a 标签体系识别与分级：项目方/大庄/小庄/离场庄/狙击集团/刷量地址）？→ §3 §6 §6a
2. **每个庄什么类型**（①单地址明牌 ②多地址·互转/gas 同源 ③伪装分散·指纹一致）？→ §6a
3. **各阵营全历史持仓占比如何演变**（占总供应量；锁仓/销毁单列；建仓后动没动、拉升期有没有出货）？→ §4 §5 §7 §8 + report-template 标准图 1/2/3（图 1/2 前置于报告 TL;DR 顶部）
4. **项目方背景调查**（创始人/项目历史含黑历史、推特/Discord/Telegram 运营、大V关注量、互动数与浏览量、热度综合评估与水军嫌疑；无项目方看 dev）？→ research-workflows §1 背景调查路线

**建仓成本自 v2.0 起不再是固定命题**（旧五问之③删除，2026-07-14 用户定）：§6b 方法保留为按需工具——出货获利、浮盈状态等结论需要成本参照时就地计算引用，不再单设章节、不强制每实体四件套。

**开放条款——四问是下限不是上限**：链上任何不属于四问的显著结构性异常（暴跌/暴涨归因、假量对倒矩阵、流动性事件、治理/权限异动、跨链桥异常等），必须单列章节报告并在 TL;DR 加"本次特有发现"条目（无则明写"无"）。四问保证下限（不漏答该答的），不设上限（不许因框架未覆盖而略去）——一份报告的真正标准不是"答完四问"，而是"读者看完不再有重大未知"。

旧三问（吸筹派发/关联集群/弃盘）的分析内涵全部并入四问：吸筹派发=问 3 的演变解读（§5 净流方法仍是其工具），关联集群=问 1/2，弃盘=问 3 的当前状态评估（§7）。§1 §2 是所有结论的数据地基；§10 §11 是发布前的质量闸门，任何一问的答案未过 §10 对抗复核、未按 §11 措辞纪律改写，不得进入报告。

## 1. 供给基线核定（一切百分比的分母）

**三套口径必须分开拿、分开标注、分开使用，禁止混用：**
- **链上实查口径**：totalSupply/getTokenSupply 直查，精确到最小单位；扣减烧毁地址后得链上可流通基数。
- **第三方流通口径**：CoinGecko/CMC 的 circulating supply（含其对锁仓的人工认定），只作对外可比口径引用，标明"XX 口径"。
- **名义已解锁口径**：tokenomist/DropsTab 类解锁表的"累计已释放额度"——这是**额度**不是**流通**，已解锁未必已进入市场。

**口径混淆是五次分析中最高频的结论级错误源**，四种实翻车形态（来源：五会话共见（IO/OPN/FIL/SIREN/HYPE），2026-07）：
- 把解锁表的"名义已解锁"当成"当前实际流通"，两数可差近一倍（来源：OPN(BSC)，2026-07）
- 现货持仓快照不含质押部分，直接用会得出大户"几乎全员清仓"的假象（来源：HYPE(Hyperliquid)，2026-07）
- 浏览器榜单存在"过滤后 account 榜"与"全量富豪榜"两种口径，前者漏掉 miner/multisig/合约类大户（来源：FIL(Filecoin)，2026-07）
- 链上实查总供应与 CMC 流通量是两套数，报告里必须分开注明来源（来源：IO(Solana)，2026-07）

**执行规则：**
- 引用任何第三方指标前，先核对该字段的原始标签和定义，再决定它对应三套口径中的哪一套（来源：OPN(BSC)，2026-07）
- 一切"占流通 %"的结论必须写明分母口径；基于快照的指标必须声明含不含质押/锁仓（来源：HYPE(Hyperliquid)，2026-07）
- 被用户质疑数字时，用可复算的拆数回应（各分项相加还原总数），不直接改口；同时主动复查相邻数字，有出入即修正（来源：OPN(BSC)，2026-07）
- **★权限双轨核验（Ownable 弃权 ≠ 无增发权，AccessControl 是第三方安全面的口径盲区）**：GMGN/GoPlus 的 renounced=true 只读 Ownable 的 owner()——对 AccessControl 合约不查角色。凡合约源码含 AccessControl：DEFAULT_ADMIN/MINTER 等角色逐个 `hasRole` eth_call 亲验（selector `0x91d14854`），角色授予史用 RoleGranted 事件 topic0（keccak of `RoleGranted(bytes32,address,address)`）从**部署块**起全史拉取；且"角色在手"与"能否增发"分开验证——实测 creator 仍持 ADMIN+MINTER 但 mint 计数器 immutable 打满、增发链上不可能，两层各自查完才可写"增发已锁死/未锁死"（供给分母的未来变化必须由这两层共同决定）（来源：PING(Base) 分析，2026-07-17）

## 2. 对账关卡（硬性 gate，不过不进分析）

**总原则：重建/采集结果必须与独立数据源精确对表后才允许进入分析。对不上 = 数据有洞 = 回去补数据，不是调整阈值或口头解释。** 各链 gate 形态并列如下，做哪条链就执行哪套：

**EVM（全量事件重建路线）三重校验：**
- 全网余额和 = 0（mint 计负、burn 计正后逐笔累加）（来源：SIREN(BSC)，2026-07）
- 重建余额 vs GMGN top10 逐个对比，要求 **10/10 精确到个位**；实测数据到 97% 时对账 4/10 MISMATCH、补扫完成后 10/10 全过——证明该 gate 能兜住数据缺口（来源：OPN(BSC)，2026-07）
- 多链部署的代币做跨链总量对账（A 链余量 + B 链流通 ≈ 总量），wei 级闭合（来源：OPN(BSC)，2026-07）
- 加分项：重建出的实体控盘占比若与第三方分析师独立披露的同口径数字偏差 <1 个百分点，即构成互证，是结论可信度的最强背书（来源：SIREN(BSC)，2026-07）

**Filecoin（浏览器 API 准全量路线）：**
- 总量恒等式自检：totalSupply = vested + mined + reserveDisbursed（来源：FIL(Filecoin)，2026-07）
- 榜单抓完立即做唯一性断言（assert 无重复地址）+ 跨页自洽校验（如 pageSize=100 第 2 页首条 == pageSize=50 第 4 页首条），别等分析阶段才发现分页参数失效（来源：FIL(Filecoin)，2026-07）
- 流水加总出的净流量用"链上余额变化"独立复核；高频地址流水有截断时，以余额差校正净流并如实标注（来源：FIL(Filecoin)，2026-07）

**Hyperliquid（官方 API + 快照路线）：**
- 同一指标用两个独立来源对表（第三方面板逐日数据 vs 链上快照差分），**偏差 <1%（实测 0.7%）才可按最高证据级措辞呈现**，否则措辞降级（来源：HYPE(Hyperliquid)，2026-07）

**Solana（免费 RPC 无历史回放时的轻量形态）：**
- 至少做：双口径核定（§1）+ 机械解锁金额整除自证——月转出额能被"配额总额 ÷ 归属月数"整除，即反推还原出 vesting 合约参数，数据自洽性由此自证（来源：IO(Solana)，2026-07）
- 无系统性对账 gate 本身要写进报告局限（历史部分依赖第三方口径）（来源：IO(Solana)，2026-07）

**时机纪律：** gate 以数据补扫完成（remaining=0）后的那一轮为准；数据未齐时预跑对账只作提前预警口径问题用，不作放行依据（来源：OPN(BSC)，2026-07）。

## 3. 地址身份标注（批量标签库前置 + 三级兜底）

**第零步（强制前置，先于一切人工定性）：批量标签库过一遍。** 全部候选大户/关联地址先跑
`python3 ~/.claude/skills/token-chip-analysis/scripts/labels/label_lookup.py --chain <链> --file <地址清单>`（加 `--json` 得机器可读 JSONL）。
七段输出的处置纪律（v4）：[SERIAL] 惯犯庄家命中=最高优先级，立即调案源比对手法（跨案命中必写报告）；[RISK] 定性风险命中=必写进报告；[RISK-CANDIDATE] 社区候选=降权提示不作定性；[RISK-UNKNOWN] 白名单外旗标=人工核验后扩白名单或修数据，不自动定性；[EXCLUDE] 设施=不计入实体持仓/大户榜（资金路径叙事保留）；[IDENTITY] 身份=不剔除、报告标注（locker/airdrop-distributor/token-sale/charity 禁作聚类合并边；locker/分发器持仓按 bucket 单列桶）；[PRIVACY] Tornado 使用记录=陈述事实不定性。
**库无记录≠白户**——未命中的仍走下面三级兜底；cross_chain 联查命中只是提示，定性前须现场核验（普通合约同址≠同实体）。EVM cluster.py / analyze_holdings.py、SOL replay_edges.py / build_evolution.py（阵营体检）、HL main_metrics.py 已内置该库自动兜底（`--no-labels` 关闭；缺表显式报 degraded_mode——看到该警告说明本次运行无标签防线），但对"人工逐个定性"环节，第零步照跑。Robinhood 链疑似公共 bot 合约再加跑 `fingerprint_check.py --chain robinhood <地址>`（字节码模板指纹，命中=candidate 级、行为复核后才按设施处理）。对未命中库的候选大户可选跑 `goplus_check.py --chain <链> --file <清单>` 做恶意地址体检（candidate 级降权提示，EVM 主力可用、SOL 覆盖未证实——纪律见 labels/README「运行时风险通道」）。分析收尾把 miss-queue 新增条目扫一眼（跨 token 反复出现者优先核验回填）（来源：标签库 v4 接入 2026-07-17；v4.1 GoPlus 通道同日）。

对 Top 持有人逐个定性，把 CEX 托管/路由/池子/官方金库从"疑似庄家"中剥离——五次分析中这一步多次直接改写筹码结构结论（来源：五会话共见，2026-07）。证据强度按级递减，用哪级就按哪级措辞。

**第一级：官方/浏览器标签（最强）**
- EVM：WebFetch 区块浏览器地址页取 Public Name Tag——曾靠它把"疑似老庄分仓""神秘大户"改判为 CEX 储备合约与热钱包，把占供应近四成的 Top1 识破为 CEX 场内托管路由。**大户定性必须查官方标签，不能只看链上行为猜**（来源：SIREN(BSC)，2026-07）
- GMGN holders 自带 tags / start_holding_at / native_transfer.from（gas 来源），是免费标签与聚类线索的复合来源（来源：OPN(BSC)，2026-07）
- Filecoin：扫描创世 actor ID 低位段（f00–f0126）批量取全部官方标签地址（基金会/PL/Faucet/Burn/挖矿储备）——免费获取项目方地址库的关键手法（来源：FIL(Filecoin)，2026-07）
- Hyperliquid：Hypurrscan globalAliases 数百条实体标签 + 官方 API nonCirculatingUserBalances 直接点名团队/基金会地址（来源：HYPE(Hyperliquid)，2026-07）
- Solana：Solscan 公开标签；托管类型可从 token account 的 owner 程序直判（多签程序=官方金库、vesting 程序=解锁托管 PDA）（来源：IO(Solana)，2026-07）
- **标签冲突裁决：以区块浏览器官方标签为准**——聚类工具/子代理/第三方 tracer 转述的 CEX 标签与浏览器官方标签不一致时（曾有 tracer 报 MEXC、Etherscan 官方标签实为 Binance 20），一律以浏览器页面亲验为准，转述值不落库（来源：外部 ASTEROID(ETH) 考古，2026-07）

**第二级：外部证据（次强，逐条留 URL）**
- CEX 的 Proof-of-Reserve 审计 PDF：免费、权威的交易所钱包地址来源（来源：IO(Solana)，2026-07）
- 媒体报道与链上侦探推文的地址指认；链上行为与官方分配文档对表（排放节奏、配额结构吻合即可定性官方金库）（来源：IO(Solana)，2026-07）
- 后台子代理批量考证：给统一 JSON schema（标签/首笔注资来源/钱包年龄/是否仍持仓），强制每条论断带来源 URL + 置信度、查不到就明说（来源：FIL(Filecoin)/SIREN(BSC)，2026-07）

**第三级：行为特征兜底（只够"疑似"级，措辞必须降级）**
行为特征库（来源：IO(Solana)/FIL(Filecoin)，2026-07）：
- 整数余额、长期只进不出 → 冷储特征
- 同时是多个热门代币的最大持仓者 → CEX 归集钱包特征
- 多对象、小额、规律发放 → 运营/发薪钱包
- 固定周期向大量小地址发奖 → 排放/奖励金库
- 每月同日 + 金额分毫不差 + 金额整除还原出归属参数 → 机械 vesting 解锁（区分"机械解锁"与"主观卖出"的硬指纹）
- 一组地址只进不出且按固定额度顺序填充 → 同一实体拆分冷储

**兜底级的边界教训：**
- "单向把币打进某 CEX 热钱包"只能证明客户存币关系，**不能证明该地址归属该 CEX**——交易所内部冷热调拨与客户充值是两种不同链路，归属判定被对抗复核降级过（来源：FIL(Filecoin)，2026-07）
- 免费标签覆盖不全（部分 CEX 的钱包无人标注）时，表格里明写"未能免费确证"，合计数旁标注"可能低估"（来源：IO(Solana)，2026-07）
- **transfer_in 型大户可能是质押/托管 PDA，程序归属判别必须先于庄家定性**——"多地址转入+短期大额累积+transfer_in 标签"表面完全符合归集庄画像，PUB 案 13.57% 供应的"疑似 dev 系分仓"经 owner 程序两跳判别反转为官方质押池（币的主人是各质押用户）。Solana 完整判定链见 data-pipeline-solana §2a 五步法（含升级权限风险必查）；EVM 同理先查合约身份再谈归集（来源：PUB(Solana) 分析，2026-07-14）

## 4. 金库与核心实体逐笔归因

**建清单：** 项目方金库、vesting 托管、做市商、官方回购/护盘基金、外部披露指认的操盘实体，全部进实体清单，逐地址拉全量流水。

**逐笔归因规则：**
- 每笔大额流出对应到一个公开活动（上所划拨、做市补给、公告解锁、生态发放、回购执行）；**对不上的单列成"未解释流出"清单重点追查**（来源：五会话共见，2026-07）
- 解锁/分发款穿透中转层追到终点，按终点二分：进 CEX = 进入可售状态；进囤币钱包 = 被收走。终点未定型的标注"在途"（来源：IO(Solana)，2026-07）
- 按时间轴对比同一来源的去向变化：同一 vesting 源不同月份从"进交易所"变为"进囤币鲸"（或反向）即行为拐点——这是单份报告里最强的证据形态（来源：IO(Solana)，2026-07）
- **轮换出货通道也是行为证据**：同一来源每期固定经同一中转、但每期更换下游终点地址（本月 CEX、下月新地址 A、再下月新地址 B）= 刻意轮换路径规避追踪——处置行为+隐匿意图的组合指纹，单列报告（来源：IO(Solana) 实录核验，2026-07-12）
- 接收方是实体地址时再追一跳并分类（转 CEX / 市场卖出 / 再质押 / 桥出），逐类计数而非笼统描述；注意"第一跳没卖"不等于"没卖"，追到几跳就说几跳（来源：HYPE(Hyperliquid)，2026-07）

**结构指纹与意图克制：** "长期沉寂后在拉升次日突然划出大额 → 拆成面额规整的一次性新地址 → 收币后分钟级充所"这类完整链路要逐环节记录并画图；但结构成立≠意图成立——高位变现与做市/所内活动供库存在链上不可区分，定性只写"协调投放"，两种意图并列（来源：OPN(BSC)，2026-07）。

**杠杆手法：**
- 外部情报→链上复核范式：先拿第三方分析师披露的实体地址清单，再用批量余额查询（EVM 用 Multicall3）核验现仓，直接量化实体当前持有——绕过自建聚类的冷启动（来源：SIREN(BSC)，2026-07）
- 大额批量分发交易可直接解码提取全部接收地址（一笔近千地址的分发交易即一份现成实体名单）（来源：SIREN(BSC)，2026-07）
- vesting 是链原生结构的（如 Filecoin multisig actor），锁仓明细（initialBalance/unlock 起止）链上直读，无需外部解锁表（来源：FIL(Filecoin)，2026-07）
- "官方解锁新增流量归零"≠"卖压消失"——已解锁未处置的存量仍在，必须分开表述（来源：FIL(Filecoin)，2026-07）

- **平台出纳机器人的自动分发名单=官方关联仓发现通道**：发射台类标的的平台出纳（高频自动归集费用的 EOA，万笔级）会以机器节奏给极少数地址发 dust 级 ETH——把「出纳的 ETH 出账收款人全集」作为官方阵营标准排查项，名单上的非金库地址是"运营侧隐性关联仓"候选（实测借此发现官方系隐性仓位 0.15%，其在利好日/风波日三次买入零卖出；定性注意：买入资金若来自其自身提款则写"运营侧关联地址的自发买入"而非"官方出资自买"）（来源：BEGGAR(Robinhood) 分析对抗复核，2026-07-17）
- **【候选·单案】"CEX 上线事件驱动"做市商的身份判定纪律**：多地址在某 CEX 上线公告后、开盘前窗口集体激活并高频作业，只构成**事件驱动型做市实体**；"受该 CEX 委托做市"必须另查其全部流水与该 CEX 全部已标注钱包（热/冷/托管）的直接往来笔数——零直接往来时委托关系"不能确认也不能排除"，降级表述并把独立高频商作同等备择并列；上线时间强相关是行为证据不是身份证据（来源：VIRTUAL(Base+ETH) 多链分析，2026-07-18）

## 5. CEX 充提净流 × 价格（吸筹/派发判定）

**指标构造：** 用已标注的 CEX 钱包清单算每日/每周净流，与价格序列对齐画图；多组并列（池子/场内托管/CEX/实体/新集群）比单一总线更能定位谁在动（来源：SIREN(BSC)/OPN(BSC)，2026-07）。

**语义边界（写进报告的固定口径）：**
- 净充入 CEX = 筹码进入可售状态，**不等于已卖出**（来源：OPN(BSC)，2026-07）
- 热钱包流出 = 全体用户提币的总吞吐，**不等于原主提走**；币充进热钱包后链上追踪即断（来源：OPN(BSC)，2026-07）
- 所内成交链上不可见，对 CEX 内部行为不下强结论，只能靠量价结构与衍生品间接推断（来源：IO(Solana)，2026-07）

**两个伪影防护（不做防护整条指标可能报废）：**
- **同 CEX 内部调仓**：同一交易所钱包间的划转被误计成充提净流，曾叠加 top-N 快照的幸存者偏差把整条"净提币=吸筹"指标做成假象，被对抗复核整条推翻、图表删除——复用该指标必须先剔除同 CEX 内部对倒（来源：HYPE(Hyperliquid)，2026-07）。同类：两地址间"每日对倒、单向各巨额"的过账模式要识别为内部过账，不计入净流（来源：FIL(Filecoin)，2026-07）
- **官方自充 vs 用户变现**：金库/团队向 CEX 的充值单列一条曲线，不与普通持有者净流混算——两者对价格的含义完全不同（来源：OPN(BSC)，2026-07）

**吸筹侧判据：**
- **从 CEX 大额提币后长期自持，是链上唯一可证实的吸筹形态**（来源：五会话共见，2026-07）
- 机构托管专用通道（如 Coinbase Prime）的提币直接锚定机构身份，散户不走该通道（来源：IO(Solana)，2026-07）
- 叠加衍生品指标（OI、资金费率）区分现货驱动与杠杆驱动的反弹（来源：IO(Solana)，2026-07）

**黑箱声明：** CEX/场内托管黑箱占供应比例要显式量化，并给出"单一实体份额上限无法排除至 X%"的表述——黑箱占比近半时，任何"不存在大实体"的结论都只能限定在链上可证范围（来源：SIREN(BSC)，2026-07）。

## 6. 关联地址聚类规则

**前置硬步骤：聚类候选先过批量标签库**（§3 第零步；cluster.py 已默认内置 resolver 拦截——
tier=exclude 设施与 locker 禁作合并边，被拦地址写入 clusters.json 的 label_excluded_nodes 供对账）。
手搓聚类脚本或新链临时脚本时同样必须先过 `label_lookup.py`，防 CEX/桥/路由被串进实体簇（来源：标签库 v3 接入，2026-07-16）。

**证据边类型（多类证据构边，连通分量 + 证据打分）：**
- 大额直转 / 共同资金来源（首笔注资同源）/ 来自金库一跳 / 时序同步（如 72h 内共同注资）/ 共用中转地址（来源：五会话共见，2026-07）
- 共用中转 = "共用出纳"：两个"独立"大户在各自解锁日汇入同一中转、中转链路又闭合归集到同一终点，是集群判定最经典的强证据（来源：IO(Solana)，2026-07）
- **小额测试转账紧跟大额 = 同人验证铁指纹**：先转小额（如 1 万枚）、分钟级内跟进大额（如 899 万枚）到同一目标——这是转账人在验证自己控制的新地址，比"同额多胞胎"更硬的直转边强化（来源：外部 bibi(BSC) 考古，2026-07）
- 成边条件：≥2 类证据，或 1 类强证据（来源：HYPE(Hyperliquid)，2026-07）；注资/gas 同源边的强度分级与"私人 funder"公共性三步体检见下方「gas/资金面溯源纪律」块（未过体检不得计为"强证据"）

**硬规则（违反任何一条都产出过垃圾结论）：**
- **服务枢纽剔除**：与超过 15 个不同地址有边（度>15），或出度>200 的节点（DEX 路由/空投分发器/归集服务/部署者），视为服务商剔除其边。不剔除的实测后果：单个"实体"聚出 848 个成员的大杂烩（来源：HYPE(Hyperliquid)/OPN(BSC)，2026-07）
- **同模板 bot 路由同样剔除（与上条互补——模板孪生体单个度数可能不超线）**：同一字节码模板批量部署的 bot 路由（双胞胎/多胞胎合约，各自数千对手方）会把互不相关的用户粘成两位数百分比的假"大实体"——设施剔除名单必须含"同模板高对手方合约"排查（getCode 哈希分组 + 度数阈值）（来源：PING(Base) 分析，2026-07-17）
- **CEX 热钱包不可作为共同资金来源证据**：从同一热钱包提币的地址不构成关联（热钱包是全用户共用资金池）（来源：OPN(BSC)/HYPE(Hyperliquid)，2026-07）
- **DCA 定投服务合约会伪装成"化整为零分发器"**：出方是数百个互不相关用户、形似庄家分仓网——**入方构成检验**一步拆穿：入方 99%+ 是池子（服务代买）=定投服务；真分发器的入方是金库/母仓。判定为服务后其用户间不构成任何关联边（来源：PING(Base) 分析，2026-07-17）
- **两跳下游追踪每跳节点先做合约体检**（eth_getCode 批查 + 度数阈值）：下游集合混入公共 swap 执行合约时，"经合约买币的散户"会被批量误判为马甲——实测 132 址体检出 14 个合约，剔除后目标口径 21.9%→12.7%、96 址"大集群"拆为三个独立星座（来源：CASHCAT(Robinhood) 分析，2026-07-13）
- **"标签库命中 registry 官方地址"优先级高于"行为像私有合约"**：跨链桥履约地址（deBridge taker 类）行为形似私有执行合约（低余额、定向转账、少数对手方）——裁决规则：labels 库/官方 registry 亲验命中即判**履约管道**、禁作合并边，行为学证据不得推翻 registry 身份（来源：PING(Base) 分析对抗复核，2026-07-17）
- **最大集群必须回查首笔资金来源验证性质**（官方资助网络 vs 操盘实体是两种完全不同的结论）（来源：HYPE(Hyperliquid)，2026-07）
- 区分"官方控制"与"来源官方"：从金库拿过币 ≠ 被官方控制，两种标签分开打（来源：OPN(BSC)，2026-07）

**伪造与投毒防护（对抗性数据环境的免疫层）：**
- **地址投毒防护**：资金上游归因只认大额转账（设阈值过滤尘埃转账），且比对完整地址而非前缀——曾把伪造 vanity 前缀的投毒攻击地址误判为大户资金上游（来源：FIL(Filecoin)，2026-07）
- **vanity 定制地址的两种操盘方用法**（与上条"被投毒"相反，这是操盘方自用）：①**配对自证**——注资金主与收币大户地址共享 8–26 位十六进制**中段**（前后缀不同），=批量定制的配对地址，同一实体最硬指纹之一（铁证级；识别看中段不看前缀）；②**仿冒基建伪装**——生成前 12+ 位仿冒 LiFiDiamond/Relay 等真实路由的假基建 EOA 分发筹码，专骗肉眼排查。识别：与真基建地址逐位比对（前缀同、中段不同）+ `is_contract=false` + 无浏览器标签 + tx 数少。三条 vanity 规则合一：**凡涉 vanity 一律完整地址逐位核对**（来源：外部 CASHCAT/GME(Robinhood) 考古，2026-07）
- **外部尘埃投毒可伪造"出纳网络"/gas 边**：第三方营销 dust（批量撒 0.0006 ETH 级）曾把 19 个互不相关大户伪造成完美的"一母多子出纳"假象，据此误判出"庄家组"、被对抗复核用收款人构成证伪（REFUTED）。**出纳网络判定三查（缺一不可）**：①拉出纳地址**本体全量 tx**核验收款人全集（只看 gas_in 里与大户相交的子集会把无差别撒网误读成定向名单）②查收款人构成：含"从未持仓/已清仓/公开 bot 农场"地址=非庄家名单（庄家出纳只养自己的仓位地址）③与同链其他代币的空投/dust 名单查同额同期重叠（重叠=撒网服务）。旁证：真出纳特征=**低频专职**+发射前注资+建仓级金额（0.1-1 ETH 级）；dust 是持仓形成**后**的尘埃级（<$2）。**尘埃级金额（≤0.001 ETH）的 gas 边默认不作聚类证据**（来源：CASHCAT(Robinhood) 分析，2026-07-13；同案两路复核独立触发，条目合并于 v3.0 整编）
- **实体启动 gas 的上游可以是灰产资金边（背景画像，不是合并边）**：实测某吸筹中枢的启动 gas 上游带 ChainPatrol 投毒 bot 资金池标记——可入报告作背景画像与风险提示，但公共灰产池逻辑同公共热钱包，不构成实体合并边（来源：PING(Base) 分析，2026-07-17）
- **关键地址字符串一律从落盘数据文件取完整值**，禁止从终端打印的截断输出复制再凭记忆补全——地址末段是校验和，补全即编造。覆盖一切来源的文字转述，**包括自己派出的复核 agent**（复核报告里的截断前缀落地到附录/JSON 前必须回落盘文件反查完整值——曾凭前缀补全出后 32 位全错的地址、险些进监控名单）；脚本打印涉及后续引用的地址时直接输出完整 42 字符（来源：FIL(Filecoin)，2026-07；CASHCAT/NOXA(Robinhood)，2026-07-13/15）

**行为指纹判定（同步/面额/委托类——每条指纹先问误报率）：**
- **"同秒等额买入"矩阵指纹三要素法**：①"同一秒 ≥3 地址从池买入且金额相近"只是**初筛**——公共交易 bot 用户多时同秒常见（对照组实测：311 个同 bot 用户剔除目标矩阵后仍有 11 例"同秒≥3"）；②有效指纹=三重叠加：**wei 级面额一致** + **重复共现富集**（成员两两活跃秒重合度对随机期望的富集倍数 >1000 倍级才算硬；单次共现只作外延不并入硬边）+ **资金边/币流边闭环**；③检验任何行为学指纹前先造**对照组**（同工具全体用户）——指纹在对照组中的出现率就是它的误报率（来源：TRASH(Robinhood) 增量更新对抗复核，2026-07-14）
- **面额指纹的环境依赖性（分母检验）**：同一面额指纹的效力取决于**同时段全场同面额买家数**——死盘环境（实测正例：当时段全场仅 9 笔买入、其中 0.1 ETH 整 3 笔全是目标组）独占性成立=有效指纹；bot 潮环境（同面额全场 672+ 独立用户）零区分力。"整数×99%"（bot 抽 1% 费后净额）是**通道指纹非实体指纹**。引用面额指纹必须同时报告分母；同次分析中同一指纹可在 A 集团成立（死盘窗）而在 B 集团被击穿（bot 潮窗）（来源：NOXA(Robinhood) 分析对抗复核，2026-07-15）
- **同秒面额指纹必须比对"报价币输入面额"，禁止比对 token 输出面额**：swap 的 token 输出量由池子瞬时价格决定，同秒两笔输出面额**必然不同**——拿输出面额得出"无一致性"是方向性错误；操作者指纹在**报价币输入侧**（同程序同参数下单，WETH 输入可 wei 级逐位全同——实测 144658800000000000 两笔同秒逐位一致）。输入面额也要过上条分母/独占性检验（来源：meow(Robinhood) 分析对抗复核，2026-07-15，初稿曾据输出面额漏掉一个伪装分散集团）
- **低档同秒共现扫描（防"分仓贴线钻候选线"漏检，新庄扫描硬步骤）**：候选榜按份额设线（如 ≥0.8%）可被"多址分仓、单址全部压线下"钻空（实锤：9 址协同族单址全部压 0.55% 以下，两轮分析均漏检，合并 3.69%）。对策=份额线之外**必须补行为线**：对 0.1%–候选线档全体地址按"从池买入时间戳"聚集扫描，同一秒 ≥5 址买入即翻出整族（等差递减面额是程序化批量的附加指纹）；零额外采集成本。**参数补强**：仅扫"同块 ≥3 buyer 且重复共现 ≥3 次"会漏"仅 2-buyer 共现但买入额 wei 级同额"的强指纹对——2-buyer 块纳入扫描+wei 同额检测（同额对才升边）；BSC 出块 ~0.45s 同块≈同秒（来源：TRASH(Robinhood) 增量更新，2026-07-17；哈基米(BSC)，2026-07-18）
- **EIP-7702 delegate 指纹的正确用法**：不能笼统以"是通用/参考实现"驳回同 delegate 关联信号——判据是**产品分发面**：主流钱包各用自家 delegate 合约，无产品前端的参考实现 singleton（如 Simple7702Account）使用面极窄，多个大户委托字节级一致恰是小众指纹；单独同 delegate 仍不足成边，须与其他证据组合（来源：bibi(BSC) 分析，2026-07-12，复核曾据此翻出漏检的 PLAUSIBLE 集群：同 delegate + 同跨链通道 + 归集硬边 + 时间同步四指纹）

**gas/资金面溯源纪律（正查+反查+性质分级）：**
- **注资证据分级（gas/资金同源边的强度标尺）**：**私人 gas 钱包**（本体 <20 笔交易）供养多个母钱包＝强证据；**同窗批次注资**（多地址在同一 ~90 分钟窗集中入金、多波重复）＝中等证据；**公用桥 solver / CEX 热钱包同源**默认剔除，仅当"同 48h 窗 + 行为指纹一致"才升中等。报告按分级分开计数/画图，强证据簇与同窗批次簇不混在一个数里（来源：外部 GME(Robinhood) 考古，2026-07）
- **gas funder 判"私人"前必过公共性三步体检**（总笔数→余额量级→时窗收款人分散度，操作见 data-pipeline-robinhood 坑表）：App 类链的平台托管提款热钱包（万笔级/千 ETH 级/时均数十收款人）形态酷似私人母钱包，曾致四址聚类整体误判；据单一 gas 边建的聚类，funder 被证公共后整体作废（来源：Pointless(Robinhood) 增量更新复核，2026-07-14）
- **gas 档案必须双向用（正查金主 + 反查下游）**：只查"候选的金主是谁"会漏"候选自己是别人的金主"（实锤：某"独立新面孔"实为已知庄家集团最大成员的 ETH 金主，发射前 6 笔 8.7 ETH，这条边一直躺在档案里）。gas_in 档案建 funder→下游反向索引，聚类前对全部候选跑"它给谁供过金"；已知实体成员的 funder 也回头对照候选集（来源：TRASH(Robinhood) 增量更新对抗复核，2026-07-17）
- **gas 边必须做"发本金"性质检查（漏检=集团成员被当独立大户）**：对每条 gas 边算「转账 ETH ÷ 下游该时段买入成本」，比值 ≥1 即"发本金建仓"母子边——比"垫 gas"强一个证据等级（早期币价下千万枚仓位只需 0.05~0.11 ETH，0.065~1.2 ETH 的"gas 转账"实为本金全包）。判据三件套：①金额覆盖下游买入成本（1.35 倍以上实锤）②时序（先收钱、分钟~小时级内首买）③母钱包公共性体检通过。实测漏检后果：某集团 7 址峰值 11.57% 按本金边复核扩到 12 址 17.67%（低估 53%）；二级资金中转（百笔级私人枢纽）同样适用（来源：BEGGAR(Robinhood) 分析对抗复核，2026-07-17）
- **协同检验双面纪律（token 面 + ETH 资金面，缺一即盲区）**：token 转账面的互转/同块/等额/金主首笔四维全阴性≠独立——合并铁证可以 100% 落在 ETH 资金面：wei 级完全等额的批量注资（disperse 类分发合约"单批次归属单一操作者"可作合并边；纯公共桥/存管合约共用不构成边）、同秒多址注资闭环、成员 gas 双向互供（实锤：九址协同工作室现仓 4.71%，token 面全阴性、初判"双址簇 2.98%"，复核以 ETH 面证据扩成整族）。配套：gas 溯源产出的 first_in 列表**逐笔消化**（只看第一笔漏"三马甲同秒供 gas"）；候选净增 <1% 深挖线会被分单建仓系统性穿透——≥1% 候选的资金对手方无条件展开、或深挖线降至 0.5%（两个 0.8-0.9% 马甲恰逃 1% 线即此坑）；同实体判定后按合并口径设观察哨（单址阈值会被分单绕过）（来源：Pointless(Robinhood) 二次增量对抗复核，2026-07-17）
- **金主收敛分析必须"现仓+同时刻合并峰值"双口径过滤**：只按"簇合并现仓 ≥X%"筛深挖对象，**已出货离场的协同集团会被系统性漏掉**（实锤：狙击集团同时刻峰值 5.65%、现仓仅 0.05% 被"现仓 <2%"过滤线筛掉，其共享金主记录就躺在溯源文件里）。正解：私人 funder 服务 ≥2 址的簇一律再算同时刻合并峰值（sig 原子化口径），峰值过标签线或曾为窗口级主力卖压的进深挖名单；"每址最早一笔 funder"人工比对不能替代全笔按 funder 分组（来源：meow(Robinhood) 分析对抗复核，2026-07-15）

**全景完整性与阴性结论（写"无"之前的义务清单）：**
- **发射窗口买家全景必须从第 1 秒扫起**："限购期末仍持仓者"口径会把发射后头 60 秒的快闪客整体漏掉（实锤：头 60 秒内有项目方马甲 5.10%、金主同源闪电簇 5.06% 与多个同窗扫货秒卖的独立 bot，全不在"期末持仓"名单）。狙击/协同识别的扫描窗从发射 tx 下一秒开始，按"窗口内累计买入"而非"窗口末持仓"取全景（来源：meow(Robinhood) 分析，2026-07-15）
- **大户入方溯源必须独立于峰值普查表（低余额高吞吐"隐形管道"盲区）**：按"历史峰值 ≥0.1%"建的普查网会系统性漏掉余额从不过线的执行/中转合约（收→转瞬时过账，峰值≈0 但累计吞吐巨大）——"大户的币从哪来"必须按该大户**全部入账对手方**独立拉清单逐个定性（实测：某大户主力仓位经一个峰值从未上榜的执行合约进货，主分析漏检靠复核补齐）（来源：PING(Base) 分析，2026-07-17）
- **暴跌/窗口归因必须用"窗口全期净变化"，"同 tx 净额"仍是毛口径**：按"同 tx 净流出且币进池"累加会把窗口内买回的往返客计成大卖家（实锤：初稿"4,363 卖家/最大 1.51%"被撤换——那个 1.51% 的真实窗口净额为 0；修正后 850 卖家/最大 1.24%）。正解=窗口内每地址全部转账净变化、剔设施、再聚类。与 §9"gross/per-tx 双口径"衔接：per-tx 净额适合单笔归因，窗口归因必须再上一层做全窗净额（来源：NOXA(Robinhood) 分析对抗复核，2026-07-15）
- **净盈亏≈0 群体的归因边界（量能虚胖四件套）**：呈现高换手/疑似做量群体的标准件=①占比+多阈值稳健性（净差 2%/5%/10% 阈值下的占比区间）②构成分解（机器式高频 ≥6 笔 / 1-2 笔完整进出的普通交易者 / 已标注实体，防重复计数）③原子性检验（买卖 tx 与同 block 交集——零原子性可排除三明治/原子套利）④群体已实现盈亏（净盈利可反驳"亏损刷量"）。**"客观点火效果"与"主观点火意图"分开表述**："大买速卖客观上引来接盘"可写；"协同做量"在组外存在同模式独立地址时不可写——独立 bot 抢跑失败天然产生分钟级净零往返（来源：NOXA(Robinhood) 分析对抗复核，2026-07-15）
- **出货回款归集排查的表述边界**：本地池侧数据只能证明"池的直接收款人无归集"——回款经公共路由 unwrap/转发后的最终去向不在本地数据内，必须写成"池侧直接收款人无归集；经公共路由之后的去向本地不可证"，否则复核按"超出可证范围"降级（来源：meow(Robinhood) 分析对抗复核，2026-07-15）
- **"其他大户互不关联"阴性结论三查（写"无漏检小庄"前必做）**：①两两互转扫描 ②gas funder 分层（含 gas_in 的 self_alias 字段——L1 桥别名自充值≠独立金主）③同窗注资/同秒建仓/共同下游排查。三查后仍剩的弱信号（同分钟建仓对、若合并将破线）按**"待证关联对"列观察哨重点监控**，不并入也不无视（来源：NOXA(Robinhood) 分析对抗复核，2026-07-15）
- **贴线实体的双口径呈现范式**：疑似关联实体合并份额骑在判级线上时（如硬证据口径 4.99% vs 含弱行为边口径 5.17%，线=5%），**两口径并列呈现、按证据下限判级**（不判庄），同时列观察哨最高优先级+给下次更新"补溯源+重扫"明确指令；跨小组只有工具/面额/时序证据而无资金边时，表述封顶"高度疑似同一工作室"，不写"单一实体"（来源：TRASH(Robinhood) 增量更新，2026-07-14）

**已知系统性偏差：** 互转图聚类的数字**系统性偏低**——同一实体换新钱包续持会被拆成多个独立社区，曾有延续仓被拆成两个社区各自低于报告阈值（来源：SIREN(BSC)，2026-07）。因此："不存在 >X% 集群"永远要写成"**链上可证范围内**无 >X% 集群"。

**措辞锁定：** 聚类结论一律"高度疑似同一实体"，不写确权——共用出纳也可能是做市商/OTC 服务商同时服务多个独立客户；把证据链逐条列出（每条边标日期+金额）让读者自判（来源：IO(Solana)，2026-07）。

**特殊场景手法库：**
- **CEX 注资失效时的隐藏关联识别——跨代币共现聚类**（外部 CZ(BSC) 分析考古，2026-07）：一批钱包全由 CEX 热钱包提现开号、funder 溯源整体失效时，改用"共同买卖历史"聚类：抓每钱包近 1 年全代币流水（BscScan tokentxns ≤1000 行/钱包，见 data-pipeline-evm §7.2）→ 空投过滤 → 支持度 ≥3 频繁项集 → Jaccard 相似度 → 叠加共时首买/首卖时序（6h 窗）→ 并查集分组。**三条判别标准（专防"跟单"误判成"同体"）**：①Jaccard 0.9+ 且买卖双向对称且互有直转 = 同一实体；②**同区块共买比例 ≥85–90%（中位时间差 0 秒）= 同一实体铁证**（共同买入压倒性同块只能是单一控制端成对发单），配套硬指纹：**区块内位置恒差**（两钱包 tx 的块内 index 恒差同一常数，如恒差 7）=同一引擎固定顺序广播；③**跟随者共买永远滞后领头固定秒级（实测 12–110 秒）、从不颠倒 = 程序化跟单不是同一人**（与②互为对照：同块 0 秒=同体，恒定滞后=跟单）。另：交易过 50–500 种币+CEX 开号+无差别狙击每个新币=职业打新号，其存在≠内幕信号，从关联候选剔除
- **逆向找历代马甲（wash-trading 盘专用，跨链通用）**（外部 FyedK(Solana) 分析考古，2026-07）：庄的冷门微盘常自买自卖、外部买家≈0——"最近的同款买家"往往就是庄自己的历代钱包。**总归集口的历史流入地址列表 = 该庄历代马甲归集头的现成名录**（某案总归集口两年 154 个流入地址），比正向 co-buyer 扫描高效得多。适用前提：先确认该盘外部真实买家稀少（否则名录混入真散户）

## 6a. 标签体系、类型三分类与阵营划分（问1/问2 的操作定义）

**标签体系与重要度分级（用户定义 2026-07-14，v2.0 硬性；取代旧"庄#N + 5% 历史峰值"单门槛体系）：**

一个实体 = 可合并为单一持仓集群的全部地址。**合并口径含全部疑似关联地址（无论证据程度），同一时刻合并计算，禁止把各地址不同时刻的峰值跨时刻相加（会高估）**；单个成员不必各自过线。按下表打标签：

| 标签 | 重要度 | 认定标准 | 判定口径 |
|---|---|---|---|
| **项目方** | **P0** | 金库/创始人/团队/基金会/vesting 托管/项目方做市仓等一切与项目方相关实体，**无论持有份额** | 身份判定（§3 §4），非份额判定 |
| **大庄** | **P0** | **当前**持仓 ≥20% 总供应 或 ≥20% 流通 | 当前快照 |
| **小庄** | P1 | **当前**持仓 ≥5% 总供应 或 ≥10% 流通（未达大庄线） | 当前快照 |
| **离场庄** | P1 | **同一时刻历史峰值** ≥10% 总供应 或 ≥15% 流通，且当前既非大庄也非小庄 | 历史峰值 |
| **狙击集团** | P0 或 P1 | 发射/开盘窗口协同狙击的实体，识别出即单独打标签、**永不与"庄"混排**；当前持仓 ≥20% 总供应或 ≥20% 流通为 P0，否则 P1（峰值曾达标但已大幅出货的按 P1，正文注明峰值规模并完整分析其出货路径） | 当前快照定级 |
| **刷量地址** | P1 | 对倒刷量执行地址（集群），单独打标签；可证明与其他集团关联时打复合标签（"大庄#N·刷量地址""离场庄#N·刷量地址"） | 行为判定（§9） |

- 双门槛满足其一即认定；流通门槛是低流通盘防漏判条款。总供应分母用 §1 核定口径；流通分母用 §1 核定的流通口径，vesting 持续解锁的标的峰值判定用**峰值时刻**的已流通量（可用已解锁量近似）；报告须声明触发口径与分母取值。
- 峰值从全量重放的历史持仓序列上取（阶段 3 演变重放的副产品），**不得只看当前快照**。
- **未达任何标签门槛的候选不投入深挖资源**——分析出来也没有决策价值；在阴性排查小节一句话带过（"候选集群 X 合并峰值仅总供应 y% / 流通 z%，低于全部标签门槛"）。**其他大户（当前 ≥1% 总供应或 ≥2% 流通、未入任何标签）与散户只作为阵营出现在标准图 1，正文不单独分析、不逐个溯源。**
- 计数分级呈现与离场庄亚型分层见下方「命名与计数呈现纪律」块。

**类型三分类（定型自 bibi 分析实战 + 用户定义，2026-07-12）：**

| 类型 | 定义 | 证据形态 | 措辞上限 |
|---|---|---|---|
| **① 单地址明牌** | 单一地址直接持有大份额 | 持仓本身即证据 | 链上铁证 |
| **② 多地址关联·明牌** | 多地址持有，但互转过 / gas 同源 / 首笔注资同源，链上可实锤合并 | 互转 tx + gas 溯源 + 注资路径（§6 聚类边） | 链上铁证 / 高度疑似 |
| **③ 伪装分散** | 地址间无直接链上关联，靠行为指纹合并：同窗口建仓、金额模式一致（面额规整/等比）、同一来源路径（同 CEX 同时段提币不算，见 §6）、同步操作、洗仓双跳痕迹 | 指纹证据清单（逐条列，≥3 条独立指纹才升"高度疑似"） | 高度疑似（永不实锤） |

- **类型③的判定必须走 §6 聚类硬规则**（服务枢纽剔除/CEX 热钱包不作共源/完整地址比对——行为指纹不得绕过硬规则直接成边），且**指纹清单印进报告让读者自判**。

**命名与计数呈现纪律：**
- 命名与标签格式（v2.0）：大庄/小庄按当前持仓降序编号（大庄#1、小庄#1…），离场庄按历史峰值降序编号，狙击集团仅一个时不编号、多个时 #1/#2，项目方不编号；类型作为属性写在小节标题与 JSON（如"大庄#1（类型③·伪装分散）"）。钱包一律标签制（`大庄#1钱包#2`），**正文不出现任何形式的地址**，完整地址只在附录 B 与 JSON 附录（report-template「标签体系」节）。离场庄的历史持仓照常计入阵营演变曲线（现仓为零只体现在序列末端）
- **计数呈现必须分级**：TL;DR 问 1 直答按"P0：… / P1：…"分级列出；实锤（类型①②）与高度疑似（类型③）分开报，禁止混在一个数里断言"共 N 个庄"
- **离场庄亚型分层呈现**：峰值门槛下会混入持币仅数秒~数分钟的发射日闪电狙击 bot——打标签照打，但报告按持有时长分亚型呈现（闪电 bot / 小时级波段 / 数日波段），否则计数给读者的印象失真（来源：PUB(Solana) 分析，2026-07-14）
- **【候选·单案】非关联组触达庄级门槛的双口径披露**：按"同源同行为"归组展示的非关联组（如创世空投头部持有人组，各自独立、无互转闭环）不判庄级；但组**合并峰值**触达离场庄门槛字面时，必须在阴性结论旁如实双口径披露（"单一实体口径无离场庄 + 组口径峰值 X%/现减持 Y%"），否则"无离场庄"结论对读者有误导性（来源：VIRTUAL(Base+ETH) 多链分析，2026-07-18）
- **同型协同结构≠同一实体（狙击生态标的的计数纪律）**：发射同块多组"买手→同秒零对价整仓转卖手→切片出货"结构完全同型，不构成合并证据——同型是**生态标准作业模式**（职业狙击工具趋同）；独立性可用执行栈指纹互斥证明（自建执行合约 vs 私有 sell 合约 vs 预部署狙击合约 vs 拆分中转，各组工具链不同）+组间 token/ETH 层零直接资金往来；共用同一 CEX 热钱包提币备弹药按 CEX 纪律不作关联边（来源：jesse(Base) 分析，2026-07-18）
- **多组合计数的重算义务（传播级数字防错）**：TL;DR/图注引用的"N 组合计 X%"类数字，**实体表每次增删成员后必须整体重算**（实锤：4 组时算的 18.4% 在第 5 组定案后未更新，被两路复核同时抓出，真值 20.19%）；此类数字建议由脚本从 groups.json 自动汇总输出，禁止手工累加后散落正文（来源：jesse(Base) 分析，2026-07-18）
- **同秒/同块狙击全景纪律**：报告某狙击者时必须同时给出发射同 slot/同块全部买家的全景表——否则"庄#N 是最大狙击者"的隐含印象可能失真（实测同秒 8 买家中最大者 20.96% 并非已归组集团，而是当日离场的独立 bot）；全景成员是否归组按聚类硬规则各自独立判（来源：CLUDE(Solana) 分析，2026-07-13）
- **假桥拆分后的双层呈现范式**：大集群经合约体检清洗拆成多个星座时（各自有铁证内核、星座间仅剩行为指纹），按"N 个实锤庄（各自过门槛才计数）+ 高度疑似同一实体的合并主张（单独陈述，注明'实锤计数是下限拆分'）"两层报告；合并口径的峰值/现仓照算并声明口径（来源：CASHCAT(Robinhood) 分析，2026-07-13：96 址 53.97% 清洗拆为 40/15/5 三星座，合并主张保留 76.5% 协同系口径）
- 阴性结论也要写：**"未发现第 N 个庄"是结论**，注明排查了哪些形态（对照类型三分类表逐一说明）

**峰值与分母口径（问 1 判级的数字地基，错一处翻一级）：**
- **同时刻合并峰值必须 sig 原子化（对抗复核必查）**：算多地址簇的"同时刻合并峰值"时，若不先结清同一 tx 内的簇内互转，喂料/中转转账当刻会被同时计入转出方与接收方，**虚增约一倍**（实测某簇虚高 4.61%、原子化后实为 2.78%）。正解：簇内成员逐笔事件按 tx 合并、先净掉同 tx 内互转再累积取峰值。此坑是复核 REFUTED"伪小庄"的最常见来源（来源：LAYOFF(Solana) 分析，2026-07-15）
- **峰值声明必须有数据点**：写"历史峰值 ≥X%"前先查演变序列的 max——持仓单调增的实体峰值=现值，"≥X%"若无数据点支撑会被复核直接推翻；峰值时刻精确到具体时点并给构成（哪些仓、各多少）（来源：CLUDE(Solana) 分析，2026-07-13）
- **"无实体曾持有超 X%"类断言必须用瞬时峰值口径，期末净买口径会漏人**：内盘/窗口期"净买排名"只反映期末存量——快进快出者（实测单址 24 分钟瞬时建到 1.12%、当日回吐大半，期末口径只显示 0.46%）在净买榜上隐形；阴性断言必须对全量重放的逐事件持仓序列取每地址 max 后检验，报告措辞区分"期末净买最大 X%"与"瞬时峰值最大 Z%"（来源：HAN(Robinhood) 分析对抗复核，2026-07-16）
- **贴线集群的流通分母双口径检验**："≥10% 流通"类门槛的分母有两义——名义流通（总量−锁仓）与真实外部浮筹（再扣项目方系统与池子，两者可差 2.6 倍）；官方持仓占比极高的盘用名义流通做分母会把门槛虚高到永不触发。贴线判定按两口径并列检验、结论一致才收笔；报告声明所用分母（来源：HAN(Robinhood) 分析对抗复核，2026-07-16）
- **满贯池标的（铸币 100% 入池、零预留）的判级分母**：发射后早中期绝大部分供给锁在池内，总供应口径把一切实体占比压低到永不触发庄级门槛——历史峰值判级必须并行算"池外流通"口径（分母=总量−主池−销毁，逐时点重放取值）；实测同一实体两口径差 2.6 倍（8.33% 总量 vs 21.9% 池外流通）。两口径并列、注明触发口径；发射后极早期（池外 <15% 总量）流通分母病态放大，该窗口内瞬时峰值不适用流通口径判级（防发射秒杀 bot 全体被判庄）（来源：DUMBMONEY(Robinhood) 分析，2026-07-17）

**实体合并指纹库（类型②③的证据形态，按强度标注）：**
- **发射台 bundle 型庄家（类型②）的账本级实锤三件套**：①同块从发射台 TokenManager 拿币（logIndex 紧贴 createToken）②CEX 热钱包在 createToken **广播前**分钟级精准注资 nonce=0 烧钱包（独立狙击者无法预知未广播的发射——预谋铁证）③卖币回款短窗口归集到同一金库。三件齐=账本级同一实体，措辞可到"链上铁证"（来源：bibi(BSC) 分析，2026-07-12）
- **"售罄参数整数"不作关联证据**：bundle 各买家合计恰等于发射台 saleAmount（如 80% 整）是曲线售罄的必然结果，不是协同证据；曲线残量买家（毕业触发者）可能是独立扫尾 bot，须用注资来源/回款去向/行为节奏单独判归属——曾据此把初判的第 4 名 bundle 成员改判为独立 bot 除名（来源：bibi(BSC) 分析，2026-07-12）
- **整数配额橱窗指纹（跨链反复出现，ETH/BSC/Solana 三链均见）**：多钱包持仓恰好整数或精准凑整——精准百分比配额（4 钱包各持 1.000%/1.000%/0.998%/0.996% 并用零碎数额精准补仓凑回）、整数枚数仓（恰 1500/1000/900/700 万）、整数比例锁仓（24%/10%/6%）——同一实体按配额管理仓位的行为指纹，属类型③指纹清单一员（需与其他指纹组合，单独不成边）；与 §7"整数橱窗被打破=派发信号"联动成对使用。注意与"售罄参数整数"（上条）区分：后者是发射台机制的必然结果不是指纹（来源：外部 ASTEROID/bibi/CLAW 考古，2026-07）
- **同窗建仓"留存率二分"统计鉴别器（热点日背景噪声分离件）**：热点日的"同窗建仓"指纹被"当晚人人都在买"稀释——正解是对同窗全体大买家（分母）与长期留存者（分子）做**模式比例的超几何检验**：留存者若高度集中于某一注资/买入模式（实测 42 个大买家中留存 ≥80% 者仅 7 个、7/7 全为 L1 同址 alias 自桥+8-20 秒/笔机器节奏，P≈2.4×10⁻⁴），显著性成立才升"观察组"披露；留存分布不二分则维持背景噪声判定。该检验产出的是"行为指纹显著"而非实体合并——跨组并组仍须币流/gas 硬边（来源：CASHCAT(Robinhood) 增量更新对抗复核，2026-07-15）
- **"目标余额驱动"镜像指纹（类型③新指纹，比"同额同步"强一档）**：两地址卖出量**互不相同**，但卖后余额**双双精确修剪到同一整数**（实测 30,000,000.000000，raw 级零误差）——驱动变量是各自的目标余额而非互相跟随。价值：**直接排除"跟单 bot"备择解释**（跟单复制动作量，会产生"卖出量相同、余额不同"，与观测恰好相反）；配合动作先后方向翻转（多组同步操作中先后手互换）双重排除跟单。判定链强度排序：同额整数仓 < 秒级同步 < **目标余额驱动**——三者叠加为账本级实锤。边界纪律：gas 不同源时只能写"行为级同一实体"，禁写"资金同源"（来源：PUB(Solana) 分析，2026-07-14）
- **"喂料对"指纹（类型②硬证据，币流+零对价）**：买手钱包从池买入后，**零 SOL/ETH 对价**把大额币（如 2% 供应）转给另一持仓钱包——独立主体间不会零对价转 2% 供应的币，这是同一实体（买手+持仓分工）的**链上铁证**，强度等同 gas 同源。识别：转出笔 `对价≈0` 且转出量占供应显著。与 gas 同源互补——喂料对可能 gas 不同源，但币流零对价已足以实锤（来源：LAYOFF(Solana) 分析，2026-07-15）
- **"归集代卖"指纹（类型②硬证据）与"同窗批次转入"单指纹反例**：①A 把全部持仓零对价直转给 B，B 在 1 分钟内连同自有仓合并卖池——**归集代卖=A/B 同一实体的链上铁证**（独立止盈者不会把币交给别人卖），强度等同喂料对；在"同窗集体清仓"地址群里抓到一对归集代卖，可把该群措辞从"疑似"抬升为"内部分层的关联集群（一对实锤+其余中等置信）"。②反例实证：两个大仓"相邻两日先后收到上游归集转入"经上游全史溯源，实为两个独立交易者在产品事件期各自归集——**同窗批次转入单指纹不成边**；排除依据的正确写法是"关键期零转账交集边+第三方 feePayer 零重叠"（可量化可复验），不是行为画像描述（来源：CLUDE(Solana) 增量更新，2026-07-15）
- **洗仓识别**（老仓→一次性中转→全新地址、双跳间隔秒级、批量链条分钟级完成）：新仓表面是"新钱包新成本"，必须重放溯源拆穿并归回原实体（来源：CLAW(Solana)，2026-07；模式已两见）

**场景范式（特定盘型的标准分析件）：**
- **CA 公开前窗口量化（"官宣延迟发射"币标准件）**：发射→数日后官方才公开合约地址的币，必做三件：窗口内净买 ≥阈值的地址清单、合计占供应比、各地址现持仓归零率。呈现纪律：发射台站内列表是公开的，此窗口**不是封闭内幕**——措辞用"信息不对称窗口"不写"内幕交易"；但"窗口受益者现持仓归零率"是刻画"低价筹码是否已换手给散户"的硬指标（来源：PUB(Solana) 分析，2026-07-14）
- **"无控盘庄"分散盘的判定范式（单实体峰值全 <5% 时的收尾）**：核心悬案=转账相连的中小仓是否马甲网络——**决定性证据是 gas funder 收敛判定**：全部大户 gas 溯源，funder 高度分散=真分散盘；收敛到少数母钱包=伪装分散庄。**但转账相连 ≠ 同一实体**（可能是买手→买家交易、做市/OTC 中转）。呈现纪律：即使判"无实锤庄"，凡有转账相连簇现持越过小庄线（≥5%），**必须正面披露为"高度疑似同一操盘手但同源未证实"边界案例+列监控哨兵，禁止静默剔除**（实锤：6.26% 转账簇被静默剔除遭复核 WEAKENED；改披露+协同哨兵后才严谨）。同一实体概率给区间，协同出货是坐实的检验点（来源：LAYOFF(Solana) 分析，2026-07-15）
- **媒体驱动型 meme 的分析权重调整**：dev 先建媒体号、价格拉升全对应营销/新闻事件的"自建媒体漏斗"模式——问 4 背景调查是这类币的**核心而非附属**，价格由叙事事件驱动而非链上筹码运作驱动，拉升逐一与营销/新闻对表是标准件；最大风险是运营停摆而非庄家砸盘（来源：LAYOFF(Solana) 分析，2026-07-15）
- **拍卖型发射台（CCA 连续清算拍卖）协同集团识别**：递减清算价拍卖里，**"前 N 分钟零出价→末分钟同窗挤兑出价"不是协同实锤**——独立狙击者也会理性等到心理价位才末分钟涌入（时间聚集是机制诱导）。协同定性**必须靠资金硬边**：①出价户之间/与下游漏斗的私有 ETH 直连②同秒同额跨桥入金（wei 级精确同额才算硬边，差 0.03% 只算弱边）③私有出纳母钱包发射前 3–5 天预注资矩阵（<500 tx 低频专职钱包）④组内 gas 互供。**内部分簇纪律**：多个硬边簇之间若无直接币流边、仅靠公共 gas 分发台中等强度相连——"全网络是单一实体"链上无法定案，按"N 个硬边簇+疑似成员"分层报，"单一实体"作合并主张单独陈述注明下限拆分（来源：TRASH(Robinhood) 分析，2026-07-14：18 址拆 3 簇+3 疑似）。**拍卖内盘成本=出价净额不是毛额**：逐块统一清算价+多付退款——集团总成本用毕业 tx 内部转账实际注入池子的 ETH（净募额），退款从毕业 tx internal-transactions 的 launcher→出价户 value 反查（实测毛 3.26/净 2.84/退 0.42 ETH）
- **内置对赌/预测市场平台的"做局出货"识别与定性范式**：标的自带下注/市场功能（escrow 托管、程序化结算）时，creator 的大额"下注/注入"可能是变相变现通道——表面保住"creator 零 DEX 卖出"，实际筹码经市场派彩定向流出。**识别指纹**（满足越多越硬）：①creator 大额转出走平台程序通道（同 tx 带固定费率费边——"转出+平台费边"是平台通道指纹，"creator 零卖出"核查必须单独扫这类，DEX 卖出扫描抓不到）②该市场规模远超平台中位（实测 624 倍）③赢家在市场创建**之前**精确备好下注币（预知时序）④赢家全平台高胜率分布（42 胜 1 负——真实用户有输有赢）⑤赢家领彩即刻卖池⑥赢家钱包出生早于代币发射、资金链经一次性中转刻意隔断。**定性三事实收敛法（不需证明赢家钱包归属）**：出资方（creator）+裁判（结算指令签发者的资金归属）+结算时点（大额下注后秒级结算，实测 53 秒）三个链上事实收敛于同一利益方 ⇒ "单方面意志决定流向的定向转移，非市场博弈结果"，可用"链上铁证"级措辞；赢家是自家马甲还是知情协同者标注不可区分（最高"高度疑似"），但两种情形定性相同。取证链：getAccountInfo 查 escrow owner 程序→创建 tx 看指令名与签名者（**CreateMarket 双签**）→注入 tx 看指令语义（BuyShares=下注勿写"注入奖池"）→结算 tx 看签发者与时距（**ResolveMarket**）。指纹④的量化第二维：赢家胜局覆盖平台市场的比例（实测覆盖 70%——真实用户做不到）。营销大奖备择的反证三件套（各自量化）：外部参与人数（仅 2 人无展示效应）、官方当日宣传（零）、赢家资金去向（即刻砸池非留存）（来源：PUB(Solana) 增量更新，2026-07-15；两路复核 CONFIRMED，ResolveMarket 自家裁判与预知备币两环为复核新增取证）
- **桥接代币（CCIP/OFT 跨链版）分析范式**（标的是大市值币在新链的桥接分支时）：①分母=**本链时变供给**（mint−burn 逐日序列），历史占比按当时供给算，报告开头声明分母口径；②**桥流双向同等强度归因**——桥出发起人=转给桥出通道的直接上游，"只讲桥入不讲桥出"是系统性盲区（实测近半桥出恰来自已识别做市商且集中在拉升日撤资，漏报直接击穿"拉升期无人出货"叙事；复核者定调：筹码分析的本质是资金流守恒记账，验证了存量守恒却不对流出侧做同等归因是所有漏报的共同根源）；③"庄家"命题重心转向**流动性控制权**（LP 集中度/撤池权/有锁无锁对照）——报价币型桥接币的大户层天然由做市商/LP 构成，传统囤庄可能缺位；④先跑池子识别（token0/token1 批量 RPC）再划阵营，否则计价池污染大户榜（来源：VIRTUAL(Robinhood) 分析，2026-07-16）
- **V2 LP 控制权分析标准件**（报价币/主池型标的必做）：主池 LP token 全量 Transfer 重放持有人分布 → 前 N 集中度 + 整数 LP 仓指纹（恰 X000.0000 LP 与整数枚数仓同族）+ LP 份额×池内代币的穿透口径；LP 持有人榜同时喂给溯源候选（防 LP 层盲区，见 data-pipeline-robinhood 坑表）（来源：VIRTUAL(Robinhood) 分析，2026-07-16）
- **桥接范式的多链全量版（全局合并口径）**：标的多链部署且要求全局结论时——①全局分母=原生链恒定总量，分链各自逐笔重放后按统一日轴合并（分支链阵营序列并入全局分母口径）；②供给拓扑先行：原生链桥锁量↔分支链桥铸量逐对 wei 级闭合，"总量−金库−流锁=流通"恒等式对 CoinGecko 流通口径复核；③CCIP（CCT 架构）分支的背书池所在链**必须实查勿假设在原生链**（实测 Solana+Robinhood 分支的 LockReleaseTokenPool 背书锁在 Base 侧而非原生链 ETH）；④未展开实体分析的分支链在"范围声明"与"局限性"双处登记（供给占比+"仅登记未穿透"）（来源：VIRTUAL(Base+ETH+全局) 多链分析，2026-07-18；供给恒等式为机制性知识，合并操作口径单案）

## 6b. 建仓成本估算（v2.0 起为按需工具，不再是固定命题）

**定位变化（2026-07-14 用户定）**：建仓成本已从固定命题中删除——不再单设报告章节、不强制每实体估算。仅当某实体的**出货获利额、浮盈状态、砸盘动机**等结论需要成本参照时，按本节方法就地计算并在正文引用；JSON 附录 whale_groups 的成本三字段（est_cost_usd/avg_cost_price/cost_method）相应改为可选（算过才填）。

**输出四件套（按需算时的完整交付形态）：** 建仓窗口（起止时间）| 总投入 USD | 平均成本价 | 现价浮盈倍数。

**配价方法优先级（写明用的哪种 + 粒度）：**
1. **DEX swap 逐笔对价**（最准）：swap 事件里直接有配对代币量，逐笔折 USD 加总
2. **分钟 K 配价**：非 swap 的转入/无法解析对价时，按成交时刻分钟 K 中价配价（GT `/ohlcv/minute?aggregate=1&limit=1000&before_timestamp=` 翻页，池创建起就有；来源：CLAW(Solana)，2026-07）；小时 K 兜底但精度声明降级
3. **发射平台特例**：pump.fun 类"发射即迁移"币无内盘 K 线，内盘成本用 GMGN dev avg_cost 近似（来源：CLAW(Solana)，2026-07）
4. **影子成本**：币非买入而是转入（来源不明/接收分配）时，按转入时点市价计"影子成本"并显式标注 `[影子成本]`——它是持有人的机会成本不是实付成本；能溯源到源头买入的用源头实付成本

**口径与纪律：**
- 成本口径 = 净买入逐笔配价：`Σ(买入量×当时价) − Σ(卖出量×当时价)`，除以现持仓得均价；中途清仓再回补的分段算
- 配价粒度粗（小时K/事件稀疏）时给区间不给点估计，用 K 线 high/low 定界（§11 点估计改区间纪律）
- **配价合理性下界自检**：任何一笔的配价不得低于成交所在 K 线的 low（也不得高于 high）——配出低于 low 的数说明方法有 bug（用了错误时区/错根 K/凭印象），这是复核最容易抓的硬伤（来源：CLUDE(Solana) 分析，2026-07-13，三处配价低于当小时 low 被怀疑者推翻）
- **流量 vs 存量口径自问（高频错误源）**：说"累计收入/累计获得 XX 枚"必须按**流量**计（领取/买入笔逐笔加总），"当前仍持有的 XX"是**存量**——两者可差一倍以上（费可以边领边花/边锁）。写"累计"前自问：这个数是加总出来的还是快照读出来的？（来源：CLUDE(Solana) 分析，2026-07-13，创作者费 33M(存量) 被误作累计、实际流量 56M）
- **出货量报双口径**：庄家组"已出货"分毛卖出（对池总卖）与净流出（扣中途买回）两口径，回收金额同理——单口径会把"边买边卖"实体的真实派发量报错（来源：CLUDE(Solana) 分析，2026-07-13）
- **★染色(taint)比例分摊闭合口径（开盘扫货型集团出货量化，Index(Robinhood) 分析 2026-07-18）**：对开盘从池扫货的集团，用染色追踪（买入即染色、转出按 `min(taint, amt×taint/bal)` 比例分摊）能得到**闭合恒等式：注入% = 净退出% + 现钱包留存%**，比"名单口径现仓"严谨（名单口径含马甲用自有 clean 币买的部分，会偏高）。**关键防坑**：净退出 ≠ gross 卖出——gross 卖出（对池/路由的总卖量）含中途买回的往返，会 >净退出（本案 gross 77% vs 净退出 71%），二者**不可相加**（初稿"已卖 77% + 现存 17% = 94% > 注入 88%"口径不自洽，被对抗复核抓出）。报告须并列标注两口径并说明差额=往返买卖。配套：开盘窗内成员间零互转时，同时刻合并峰值可直接相加不重复计数（本案 88.29%）。
- 浮盈倍数 = 现价 ÷ 平均成本价，注明现价时点
- 庄家组地址在多个场所（DEX+CEX 充提）混合建仓时，CEX 场内买入不可见——写"链上可见部分成本"，别把观测边界吞掉
- **退出深度比（建议随四件套一并给出）**：庄家持仓账面价值 ÷ 全部池子可承接的退出深度（如 70:1，即"卖出 0.5% 供应量即可砸掉五成价格"）——比"持仓占比"更有决策含义的呈现维度，直接回答"他要跑的时候市场接得住吗"（来源：外部 TCC(BSC) 考古，2026-07）。**双口径升级**：双边 TVL 口径系统性低估击穿程度——TVL 里目标币侧本身不是承接力，卖出方向真实承接=对手币侧深度（口径可差一倍）；再给恒定乘积滑点模型下"全仓砸入实际可提取额/账面价值"比（CLUDE 实测仅 18%），三层递进呈现（来源：CLUDE(Solana) 分析，2026-07-13）

## 7. 庄家当前状态评估（服务问3 的解读；观察哨买入后按需）

弃盘判定是综合评估而非单点断言。**只按维度逐项收集证据，输出概率化判断，禁止套用任何历史案例的分数做锚点**；结论天然带的检验点正文一句话点出，观察哨清单 v3.2 起买入后才展开（§11 观察哨机制、monitoring-package.md「买入后监控包」）。 评估维度：

- **金库/做市活性**：核心实体地址近期是否仍有主动操作（调仓、划拨、做市补给、参与治理），还是完全沉寂；沉寂时长与代币事件（拉升/崩盘）的相对位置
- **回购或护盘动作**：有无链上可证的回购；**必须核成色**——公开市场买入与"排放池自燃式销毁"完全两回事，年销毁量与年排放量的比例、销毁启动时点是否精准踩在解锁日（叙事管理信号）都要查（来源：IO(Solana)，2026-07）
- **发射台币的创作者费现金流**：dev 的真实收入通道可能是平台创作者费而非卖币——费领取额持续增长 + 归集多签 + 零卖出甚至回购 = "靠费吃饭"型动机结构（与"靠卖币变现"对状态判定含义完全不同）；费领取停止/归集通道沉寂 = 弃盘先兆。把费收入与卖币收入分开算（来源：外部 CLAW(Solana) 考古，2026-07）
- **★"项目方零留仓/纯公益"叙事的三查陷阱（外部资产分红盘/满贯池型标的，Index(Robinhood) 分析对抗复核 2026-07-18）**：项目方对外宣称"零预留 + LP 永久锁死 + 税/费 100% 分红"时，硬安全内核（撤池封死、税金 immutable 搬不走）可能确实成立，但"零参与"叙事常有暗门——**费收款钱包可能是项目方的做市钱包而非销毁地址**：①查 `collect(to)`/费分发的实际去向（本案费的 Index 腿只销毁 65%、其余留存做市钱包+转池做市，非"全销毁"）②查该收款地址 `rewardsExcluded` 标志（=0 则项目方钱包在领本应分给散户的分红）③`eth_getCode` 判是否 EIP-7702 做市钱包（`0xef0100` 前缀）。这类 0.4% 级持仓不改变"项目方不是庄"，但"纯公益"定性必须弱化。配套：单个 EOA（非多签/Timelock）握全部 owner 权限（addStock 注册假股票池、setRewardsExcluded 改分红名单）是"存在但未激活的隐蔽提取通道"，报告陈述其存在与当前是否激活。
- **解锁执行纪律**：机械解锁是否仍按表执行；解锁款处置方式有无变化（拐点方向见 §4）
- **大户留存变化**：早期大户/创世 cohort 留存率趋势（必须用 §8 的质押修正口径）
- **链上流动性撤留**：主池深度变化、LP 是否撤出、做市商库存进出方向

**行为归因纪律（谁在买/谁在卖/为什么——时点精度决定定性对错）：**
- **暴涨暴跌归因必须逐笔价格对齐，禁止粗时段贴标签**："拉升时段内的卖出"≠"顶部出货"——主升浪的启动分钟才是分界（实锤：某协同组在主升浪启动前 12 分钟以约开盘价一半清仓、完美错过其后 7 倍主升浪，初判"顶部精准出货"被复核反转为"恐慌卖飞"）。标准动作：①出货/买入按逐笔时间戳对齐逐笔价格（swap sqrtPrice 或分钟K），算加权成交均价与顶部/底部的比值；②"顶部出货"只授予均价 ≥ 顶部 70% 的卖方；③设施穿透（经 App 金库/代卖合约的"转出"先判卖出 vs 移仓）。同理"崩跌归因"：首卖时点距顶的时长与价位决定是"砸盘者"还是"割肉者"（实锤：被指"回砸引发崩跌"的最大买家首卖在距顶 5.7 小时、价格已 -75% 处，均价对比为亏损 40% 割肉——非操盘）（来源：TRASH(Robinhood) 增量更新对抗复核，2026-07-17）
- **行情归因的最小单元是"分钟级价格路径上的时点"，不是"日"**：日级净额把"卖飞在日内低点"与"借涨出货"混为一谈。凡"XX 行情=XX 出货"类结论：先锚定暴涨起爆分钟（单分钟涨幅突变点），再分层归因起爆前/起爆后的卖家；并列统计当日净买盘（新资金接盘强劲时，"出货窗口"必须改写为"双向大换手"）。实测：初判"回归行情=老仓出货窗口"，分钟级重放后三处被推翻（狙击尾仓实际卖在当日最低点分钟=卖飞；另一实体同样卖飞；当日净买盘还略占上风）（来源：BEGGAR(Robinhood) 分析对抗复核，2026-07-17）
- **窗口净额口径原则（归因义务）**：窗口净额榜衡量"窗口内谁的余额变了"，**不是"谁在市场上买卖了"**——移仓、马甲、AA 代付都会让两者背离（实锤两案：全窗"最大净卖方"实为公告后 24h 最大净买家、其卖出全在其后崩塌段=止损非派发；"第二净卖方"实为向自家整数仓移仓、对外反而净买）。纪律：①暴涨/公告脉冲的买卖方向必须"事件后 24h 窗"与"全窗"双口径分开报；②卖方榜逐条过实体级检验（接收方是否自家仓、是否即刻转卖）后才可写"谁在出货"；③"借新闻出货"的正主认定看**卖出时点价位与事件时点的关系**（公告后分钟级闪电清仓的沉睡旧仓才最像收到风声，追高后止损的不是）（来源：jesse(Base)/哈基米(BSC) 归因复核，2026-07-18 固化）
- **喊单类利好必须对齐"推文精确时刻 vs 链上建仓时刻"**："利好日回补"与"公告前夜进场"是完全不同的定性（后者才有知情嫌疑）。实测：初判"利好日回补"，精修后实为推文前 4.5 小时进场、另一实体同夜推文前 7 小时建仓——"两个老手同夜提前进场"的时序事实比单实体"疑似知情"更有信息量。备择纪律：当夜价格本就放量上涨时，知情与动量追买链上不可区分，按不可区分并列写（来源：BEGGAR(Robinhood) 分析对抗复核，2026-07-17）

**出货形态识别（市价砸盘之外的隐蔽形态，逐个建档）：**
- **挂单式慢出货（加集中流动性 = 卖出的等价形态）**：实体把收到的币**加成集中流动性区间单**（Aerodrome/UNI V3 类 CL 池窄区间头寸），再把 LP position 质押进 gauge 挖矿——币经"加 CL 位"进池被买家逐步吃走，撤位收回对价稳定币/ETH+挖矿补贴，等价于限价挂单出货（低滑冲、顺手赚补贴）。完整判定链=收币→加 CL 位→质押 gauge→撤位收对价；实测初判"11 分钟内卖出"被复核推翻——误读会把"精细限价慢出货"写成"市价砸盘"，节奏定性完全不同。识别：Transfer 对手方是 CL pool/gauge 合约、伴随 position NFT mint；定性写"挂单式出货"，量计入卖压但与市价出货分开叙述（来源：PING(Base) 分析对抗复核，2026-07-17）
- **派发预备的前兆指纹**：头号大户把整仓按机械节奏拆成 N 个亚阈值仓（如 1 亿枚拆 20 笔×整 500 万、每分钟一笔）转入零历史新钱包、**且转后不卖**——本尊从持有人榜"消失"、筹码化整为零成 N 个匿名仓，是"派发前整备/隐身"的强信号（属换仓续持而非离场，勿计入清仓）。配套观察哨：这批新钱包的首次卖出/转 CEX = 派发正式启动；"整数橱窗"被打破（整数仓首现非整数余额）同为派发信号（外部 bibi(BSC) 分析考古，2026-07）
- **前兆指纹族谱（多币汇总，任一出现都值得设观察哨）**：①**藏仓归位**——自建中转钱包藏匿大仓数周，拉升前夜全数收回本尊；②**拆仓隐身**（上条）；③**蚂蚁搬家喂 bot 代卖**——中转仓每日小额等额切片持续出货（每笔精确 10 万枚×30+ 笔），单笔不显眼、累计量可观；④**沉睡收币大户"通电"**——长期只进不出的钱包突然首现转出/授权。两个易误判变体：**换仓双钱包**（高抛大部后剩余转新钱包+gas 注资、新钱包 nonce=0 纯持有=换仓续持非离场，重置了表面"仓位年龄"）；**"边小额回买边大额卖出"**=刷量掩护阴跌式出货（按净流向定性不看买单表象）（来源：外部 bibi/CASHCAT/GME/ASTEROID/CLAW 考古，2026-07）
- **ERC-4626 杠杆金库存款=承诺验证与监控的双盲区**：项目方/大户把币存入 Wasabi 类借贷金库时——①**定性**：Deposit 事件+份额未转让=保留完全赎回权的生息仓位，**不是赠与也不是卖出**（初判"赠与社区"被复核推翻）；但金库的币会被交易池借出直接卖上 DEX（实测存入后 2.9 小时即被借出卖出），"本人没卖"与"其库存为市场卖压提供弹药并赚利息"两个事实并列写；②**追踪**：金库混合池内"谁的币被卖了"不可逐枚指认，用**最低水位法**（存入后金库余额最低点 vs 存入前存量之差）给流出下限；③**监控**：只盯本币 Transfer 看不到份额赎回——sentinel 必须加金库份额 token（ERC-4626 share）的 Transfer/Withdraw 事件层；"零卖出"承诺主体的完整监控=本币转出+金库份额+vesting 收款地址变更三层（来源：jesse(Base) 分析，2026-07-18）

**离场判定与出金监控（"归零"与"离场"之间隔着一次换仓检测）：**
- **核心反例防护——"名单归零 ≠ 离场"**：已知实体清单余额字面清零，可能是①经切片分发器真实卖出②换新钱包续持（老钱包整数额原封转新地址）③转入 CEX 黑箱。三种去向对"弃盘"含义完全不同，必须逐笔追认后再下结论（曾有"完全清仓离场"被复核用延续仓硬证据推翻）。**操作化检测（写"完整离场"前必跑）**：对初判离场实体的清仓 tx 接收方做**两跳内等额沉淀扫描**——实测某内盘最大买家清仓 7 个月后经中转两跳等额转 813.7 万枚续持，初判被推翻（来源：SIREN(BSC)，2026-07；哈基米(BSC) 对抗复核，2026-07-18）
- **出金/利润监控盯"本尊转出"，不盯历史收款地址**：项目方出金模式会代际升级（实锤三代：冷藏一批 22 址→冷藏二批 6 址→**一次性跳板批 23 址全 nonce=1，收款即 depositNative 存跨链桥离场**）；每批全新地址，"盯上一批收款地址"的哨兵天然失效（该案 28 个冷藏址哨兵全静默，出金实际进行了 13 ETH）。正解：threshold 哨直接盯**本尊的任何 value>0 原生币转出**，收款方身份作事后分类而非触发条件（来源：TRASH(Robinhood) 增量更新，2026-07-17）
- **滚动锁仓/vesting 的观察哨三规则**：①**锁仓协议参数标志位必查后才写风险提示**：cancelable/transferable/automatic_withdrawal 三标志决定"解锁表是硬日程还是软约束"——不查就套通用话术会被 raw 实证推翻；②**续锁基率量化**：不写"每次到期均续锁"，按枚数口径数清"N 批到期、M 笔续锁、基率 X%"，未续锁的例外单独交代去向；③**到期观察哨设过渡窗**：automatic_withdrawal=0 时到期后币不自动离开 escrow，过渡窗取历史"到期→再处置"最长空窗（实测 9 天），窗内无动作不判弃锁、不发告警（来源：CLUDE(Solana) 分析，2026-07-13）

## 8. 创世/空投 cohort 留存 + 质押修正

- cohort 定义：创世分配/空投名单（有官方全量表的直接用，如 genesis 余额表；没有的用首批 claim/分发接收地址重建）（来源：HYPE(Hyperliquid)，2026-07）

## 9. 机器人/刷量识别的克制原则

- **buy≈sell、余额≈0 是原子套利/三明治机器人结构的必然结果**，不能据此推"付费刷量做数据"——亏损刷量与 MEV 机器人在链上特征上无法区分，曾有"亏损刷量"表述被对抗复核判定超出证据而撤回（来源：OPN(BSC)，2026-07）
- **GMGN 卖出榜/交易者榜是操作者 EOA 口径**（机器人执行地址），不是终端资金主人口径，据此指认"谁在出货"会张冠李戴（来源：OPN(BSC)，2026-07）
- **"机器人"标签的地址可能是组织化吸筹的执行层**：派发窗口内单向净买、买入数千笔仅个位数卖出、至今满仓的"机器人"，实为定向反向吸筹并锁仓——判别看净持仓变化与留存，不看交易频率（来源：SIREN(BSC)，2026-07）
- 转账笔数与市值的异常比例本身是分析信号（高频机器人/刷分生态盘踞），写进报告作为生态特征，同时它也意味着数据量预估要按事件密度抽样外推而非按市值臆测（来源：SIREN(BSC)，2026-07）
- **拉升日买家集中度必须 gross / per-tx 净额双口径**：gross（从池累计买入）会被套利/路由环路虚增；per-tx 净额（同 tx 内净变动，环路自动清零）是最干净口径，两口径并报且以后者为准——曾出现 gross 最大 1.23% 实为三层套利合约环路、per-tx 口径最大仅 0.37% 的量级差（来源：bibi(BSC) 分析，2026-07-12）
- **疑似原子环路必须验 tx 重叠后才定性**：同一批地址链上"买入→中转→卖回"若买入 tx 与卖出 tx 集合零重叠、卖出跨多日，则是"狙击→中转隐藏主体→持续出货"的真实流水线而非 MEV 原子环路，其量计入真实狙击与卖压——两位复核者曾对同一链路得出相反定性，靠 tx 重叠数与卖出时间分布裁决（来源：bibi(BSC) 分析，2026-07-12）
- **克隆工厂被动镜像空投 ≠ 主动收币**（外部 TCC/bibi(BSC) 分析考古，2026-07）：走红盘常被克隆/抢名工厂向同一 KOL 或名人钱包**被动镜像空投**同款币来蹭持仓榜（该钱包 out=0、零 gas 消耗、非自愿接收）；分析"连环做盘 / KOL 是否参与"时必须把它与"主动收币建仓"区分开——只因持仓榜出现某知名钱包就断言其参与操盘会张冠李戴（同源逻辑见 §6a"售罄参数整数不作关联证据"）。
- **wash bot 合约指纹**（外部 ASTEROID(ETH) 分析考古，2026-07）：nonce=1 的一次性合约 + gross 成交巨大但当前 `balanceOf`≈0 + 合约 name 常为 vanity（Diamond/MainnetSet 类）= 刷量机器人合约，不计入真实持仓/成交。配套**地址身份速查四件套**（一次并排打出快速定性）：`eth_getCode`（判合约）+ `eth_getTransactionCount`（nonce 判活跃/职业户）+ `balanceOf`（判是否留货）+ Blockscout name/tags。
- **★"毛流量巨大+净 0"指纹用前必须先排除配对池合约（对抗复核实锤翻案）**：WETH/本币小池的吞吐形态与 wash bot 完全同貌（单址毛流量可达供应量 23 倍、数万笔、净留存 0）——把"wash bot 铁指纹"套上去会**把池子当成 bot 写进实体表**（实测 5 个"刷量 bot"中 4 个经 RPC `token0()/token1()` 证实为池子合约，阵营图把池内流动性算成了 bot 仓位）。纪律：凡拟标"wash/往返 bot"的合约地址，先 eth_call token0/token1（有返回=池子→流动性池桶）+ Blockscout smart-contracts 名核验；短命池（建池数日刷完流水即撤光流动性）本身是做量场地证据，但对倒操盘者是**在池中交易的 EOA**，识别不出就如实写"操盘者未识别"，不许把池子顶上（来源：jesse(Base) 分析，2026-07-18）
- **LP 做市行为者的买卖口径要单独声明**：从 V3 NonfungiblePositionManager 收到大额代币 = LP collect/burn 提取而非买入；此类地址的"池卖出"含流动性撤出，不能与普通卖压混算——识别到即在成本/出货统计处注明口径（来源：CASHCAT(Robinhood) 分析，2026-07-13）
- **外盘 wash 毛流量口径三件套（量能真实性标准检查）**：①主池毛流出/总供应比（PUB 实测 6.8x）②单址双向毛流量 top 榜（头部单址可达供应量 17.8~21.5%/址）③净变动≈0 判定往返 bot——三件套合起来刻画"链上成交量几成是人造"。配套措辞纪律：**wash bot 贡献毛量不贡献净卖压**——暴跌归因必须把"毛卖压 top"与"净卖压 top"分开列（PUB 案 ATH 后毛卖 top5 里 4 个是净≈0 的往返 bot，按毛口径归因会完全抓错主力）（来源：PUB(Solana) 分析，2026-07-14）
- 总原则：能写结构（单向净吸、买卖计数、留存曲线），不猜身份与动机。

## 9a. 特定盘型识别：死币复活盘（僵尸币拉盘）（外部 ASTEROID(ETH) 分析考古，2026-07）

一种"无需链上吸筹"的拉盘套路，会让常规筹码分析**直接抓空**，独立成型的识别模板：

**为什么常规吸筹判定失效**：货是操盘方 1–2 年前的老库存，拉盘前无需链上吸筹——"看筹码净流入抓吸筹"在此类盘抓不到东西（拉盘前 V2 池连续多日零买入=死池）。见到"老币零链上吸筹却突然暴拉"别急着下"无人控盘"结论。

**五阶段指纹：**
1. **钱包预置**：拉盘前 3–22 个月，新钱包收小额 gas 种子后长期休眠（"先备钱包、后上资金"）。
2. **点火弹**：对无深度死池一笔大买（占供应量数%）把 K 线瞬间打十几倍，触发全网 sniper bot（DEXTools/DexScreener/Banana Gun/Maestro）警报，几分钟后卖回——制造突破信号而非建仓。
3. **洗量机器**：same-second 等额买卖对、单地址 gross 换手超总供应量、每小时买入 ETH≈卖出 ETH → 成交量/热榜排名全不可信。
4. **创建者借势出货**：老库存 → 零历史新中转钱包（CEX 提币后几分钟送 gas）→ 等额切片经 1inch/CoW 卖出 → ETH 汇 CEX，赶在 CEX 开盘前完成。
5. **二次脉冲**：提现开放日（T+1）常有最后一波脉冲（套利 + 做盘面给 CEX 看），是聪明钱标准出货窗口、非上车点。

**满贯池发射标的的四阶段变体（NOXA(Robinhood) 分析 2026-07-15）**：mint 100% 进池、创建者零库存的标的，第 4 阶段"创建者借势出货"天然缺失（创建者收入只有费通道）——按其余四阶段判定盘型；缺环本身是重要解读："操盘方变现闭环未完成"⇒ 要么真实盈利在场外/其他标的，要么发射人与做盘工作室非同一主体，两种解释并列写。新链 meme 的"死盘"阈值也应按链龄折算（新链上三周死盘 ≈ 老链一年）。

**可捕捉信号（按实战可行性排序）：**
1. **死币异动三联征** = 日成交 <$1k 超一年 + 单笔买入超池深数倍 + 5 分钟内 swap 频率 0→每分钟数十笔（DexScreener 1h volume/txns 可筛）
2. **创建者地址监控** = 最强出货预警（转向零历史新钱包 + CEX gas 种子跟随）
3. **洗量鉴别三条件** = 小时级买卖 ETH 差值/总量 <5% + 存在同秒等额买卖对 + 单地址 gross 换手 >供应量
4. **CEX 热钱包首次归集** = 上币坐实 = 利好出尽（老库存进所变现的终局信号）
5. **交易所托管余额净增速**（散户持续搬砖进所）= 派发结构

## 10. 对抗性复核制度（发布前强制）

**为什么是硬性环节：历次分析中投入产出比最高的单一环节，凡执行必实质改写结论**——修正 6/10 条结论、推翻 2/5 条核心结论并重写主叙事、删除整条指标及其图表、全面收紧表述、翻出漏检的 PLAUSIBLE 集群，各有发生（来源：OPN(BSC)/SIREN(BSC)/HYPE(Hyperliquid)/FIL(Filecoin)/bibi(BSC)，2026-07）。

**演进后的最强形态，按序执行：**
1. **本地反例自查脚本前置**：派子代理前先自己跑反驳检查（快照有无环比下降、fills 有无卖单、有无直转 CEX、核心实体有无未披露大额出账）——便宜且能先堵住明显缺口（来源：HYPE(Hyperliquid)，2026-07）
2. **N 路怀疑者子代理**：每条关键结论派一个独立"反驳代理"，**给它们本地一手数据文件路径让其自己重算（读 CSV/JSON、调 RPC、搜网），不是审阅报告文字**；prompt 附数据文件的符号约定与去重规则（来源：OPN(BSC)/SIREN(BSC)/FIL(Filecoin)，2026-07）
3. prompt 强制要求**构造备择解释**（OTC 交割/做市补库存/员工发放 vs 掩饰出货），逼出"结构成立但意图不可区分"类修正（来源：OPN(BSC)，2026-07）
4. **+1 完整性批评角色**：不攻击具体结论，专查报告缺口——漏披露的大额出账、单源信息置信度虚高、数字互相抵消的表格错误都靠它抓出（来源：HYPE(Hyperliquid)，2026-07）
5. **判定标准写死："必须实际核查，'理论上可能但无证据'不算推翻"**——否则怀疑者会用空想反例灌水（来源：SIREN(BSC)，2026-07）
6. 输出统一 schema：**CONFIRMED / WEAKENED / REFUTED + 修正表述 + 复核后置信度**
7. **修订顺序：先修数据管线再修文案**——先改分析脚本（聚类分组、去重键、口径）重跑全链产出，再逐段改报告表述与证据强度措辞，保证图表/表格/正文三处数字一致（来源：FIL(Filecoin)，2026-07）
8. **图表同步修订**：被推翻指标的图直接删除；措辞被指"美化"的图题图注同步改写，避免图文矛盾（来源：HYPE(Hyperliquid)，2026-07）
9. **裁决原样吸收，修正记录印进报告独立章节**（含被推翻的初版结论原文）；REFUTED=0 也如实写进报告——透明呈现修正过程反而增强可信度（来源：SIREN(BSC)/FIL(Filecoin)，2026-07）

**强度配置参考**（按结论重要性选档）：每结论 1 个反驳代理（基础档）→ 每结论 3 视角（备择解释/数据审计/链上复核）（来源：FIL(Filecoin)，2026-07）→ 怀疑者 + 完整性批评双角色（来源：HYPE(Hyperliquid)，2026-07）。

**与报告撰写的顺序配合：** 框架与纯事实章节可先写（与长跑采集并行），**主观定性段落留到复核裁决返回后一次成稿**——初稿全文先写完的实测代价是被推翻后 5 处以上大改主叙事（来源：SIREN(BSC)，2026-07）。

## 11. 措辞纪律与证据强度

**错误说法 → 正确说法对照表**（来源：OPN(BSC)/SIREN(BSC)/HYPE(Hyperliquid)/FIL(Filecoin)/IO(Solana)，2026-07）：

| 错误说法 | 正确说法 |
|---|---|
| 没有人在吸筹 | 链上可观测范围内没有人在吸筹（CEX 内部吸筹不可见） |
| 充入 CEX = 已卖出 | 充入 CEX = 筹码进入可售状态 |
| 热钱包流出 = 原主提走 | 热钱包流出 = 全体用户提币总吞吐 |
| 不存在 >X% 的实体集群 | 链上可证范围内无 >X% 集群（聚类数字系统性偏低 + 黑箱不可穿透） |
| （黑箱主导盘）链上无庄 | 外部可见盘（约占总供应 X%）内无达标庄家；托管黑箱 Y% 内任意规模的持仓集中链上不可见——**黑箱占比大时必须量化可见范围**，单写"链上可证范围内"不给 X/Y 会让读者高估结论覆盖面（来源：哈基米(BSC)，2026-07-18） |
| 净增持 | 净流入（"持"含意图，无法证明） |
| 已清仓离场 | 名单地址已归零（延续仓/换仓需另行证明） |
| 化整为零掩饰出货 | 协调投放；高位变现或做市供给，意图链上不可区分 |
| 解锁归零、抛压消失 | 解锁新增流量归零；已解锁未处置存量仍在 |
| 解锁后不跌反涨 | 与同期基线无显著差异（必须先对齐基线再比较） |

**固定纪律：**
- **行内置信度/证据 tag 全部取消（v2.0，2026-07-14 用户定）**：[HIGH/MED/LOW]、[单源, MED]、[INFERRED]、[UNPROVABLE] 等方括号标注不再出现在报告；以下各条纪律本身保留，改用自然语言融入行文
- 证据强度分级用词：链上铁证 / 高度疑似 / 疑似 / 未能确证——每级对应可交付的证据形态，不越级，直接写进句子（来源：IO(Solana)，2026-07）

- **★定向动词三查（提现/收割/抢费类动词入报前的账本义务）**：①"资金经过某合约"≠"进入某黑箱"——多身份设施（既是 App 通道又是公共 swap 路由）会把 swap 误读成提现，穿透该笔 tx 的完整 token/internal 流向再选动词（实锤：9.81E"App 黑箱提现"实为 swap 成稳定币后另笔交易跨链出境）；②"在场+清仓"≠"收割"——必须把买卖两腿对价都算完才能定方向动词（实锤：被判"潜伏收割"的惯犯双址实为净亏 78% 的套牢割肉）；③平台函数动作（setConfig/claim 类）定性"主动/异常"前先扫**同期全平台同类调用分布**——个体动作可能是平台级浪潮的跟随（实锤：受益人登记被初判"抢费"，事件全扫显示当日全平台 911 笔同类调用 vs 常日 25-136，且其收费在登记前已成功）。宁可只写事实不写动词。（来源：Pointless(Robinhood) 二次增量对抗复核，2026-07-17）
- **★"从池子收币"≠买入（collectLpFees 型合约的动词陷阱，定向动词三查的第④查）**：内置双币费领取的代币合约（collectLpFees 把目标币+报价币两腿手续费同时发给收款人）会让收款人呈现"从池子收到大额代币"——按 swap 定性成"买入"就把领费写成建仓（实测：一笔 857 万枚"从池买入"被复核推翻为领费，同笔另收 $259,734 报价币腿是铁证）。凡"从池子/池管理合约收币"先查该 tx 的 method 名与**双币腿**（Blockscout token-transfers 端点）：单腿=买入，双腿同收=领费/撤流动性。（来源：PING(Base) 分析对抗复核，2026-07-17）
- **"名单现持全≈0"类群体断言必须逐址复核**：对几十个地址下"全部清仓/全部沉睡"断言前，逐址过一遍终态余额——群体标签会掩盖个体反例（实测：43 址"已清仓"名单混入一个 1.02% 在场残仓，靠复核翻出）。（来源：PING(Base) 分析对抗复核，2026-07-17）
