## 链特有的坑（重要）

> 编号注记：坑 8 与坑 9 历史上各有两条（V4 成交量/零地址直铸、NOXA 机制/EIP-7702 识别）——重复编号为原文遗留、拆册原样保留，引用时以内容名区分。

1. **平台级 gas 中继污染 gas 同源信号**：`0xf70da97812cb96acdf810712aa562db8dfa3dbef` = **Relay 桥 solver 热钱包**（38 万+笔的公共基础设施）——给全链用户供 gas（RAXOL：161/238 候选地址的 gas 来自它）、替用户代发交易（txfrom 大量是它）、还替空投池发币。**"同用 f70da 供 gas"≠同一实体，只说明都经 Relay 桥入金**；做聚类前必须把它从母钱包证据里整体剔除，否则 2/3 大户会被误判成一个庄（GME 会话曾差点把它误判为庄家总金库；两会话独立踩中同一坑）。同类还有 `0x00000000aa59b37306e34cef3e021e07156cfa3a`（聚合器执行器）。已入 address-book.md Robinhood 段。
2. **Arbitrum 官方桥地址别名溯源**（穿透到 L1 身份的关键一招，GME 实测）：L2 上入金方地址若与收款地址"中段相同、前后 4 hex 不同"，即 `L2显示地址 = L1真实地址 + 0x1111000000000000000000000000000000001111`——减掉常数即得 L1 真实地址（含挂 EIP-7702 代码的 EOA），可用 Etherscan 继续溯源金主。**反向警告（TRASH 增量更新 2026-07-14，3 例误判）**：gas 首笔入金溯源时，"funder"若恰为目标地址+别名常数，则是**目标本人从 L1 跨链自充值**，不是独立金主——不做此检测会把自充值大户误记"有独立金主"，也会把两个自充值地址误判"资金独立"。gas_trace_bs.py 已内置 alias 自检（funder 减常数==目标即标 self_alias）。
3. **Virtuals 发射结构**（链上实测，RAXOL；VEX 2026-07-13 实测升级为 BONDING_V5 全解）：铸 1B → 50% 内盘 bonding + 50% 给跨项目 keeper `0x81f7ca…`（它同时是平台分账 EOA，见 address-book）→ 拆两金库：**金库1=Team 25% 合约锁仓**（TGE+1 年 cliff+6 个月线性，解锁表在 Virtuals API tokenomics 字段可直查）+ **金库2=ACF 配额 25%（EOA，平台预生成设施）**。ACF（Automated Capital Formation）= 金库2 分批把币交给平台批量执行合约 `0x3eb3…` 挂进 V3 USDG 池做**纯单边阶梯卖单**（FDV 每 +$10 万一档、五大区间各 5% 供应、上限募 $11.55M），成交本金 100% 直付创始人钱包——**"涨=项目方自动收钱"是白皮书公开机制**。分析时：①ACF 消耗进度=庄家问题的核心变量（挂进池的份额≠已卖出，在册挂单可撤回，图2 要注记会计转移效应）②毕业 tx 里工厂另拨一笔给"拨付仓"EOA（疑似内盘 99%→1% 反狙击税回收，条款 3 个月 cliff+9 个月线性归创始人）③创始人真实收入=ACF 本金+税分成 70%，其再分发路径（USDG 定向转账）是挖关联钱包网的主线索。旧记录"金库2 常拨一部分做空投池"为 RAXOL 时期观察，BONDING_V5 下金库2 专职 ACF。**HAN 实测补充（2026-07-16，全账本 wei 级复核）**：①分配比是**发射配置项非常数**（HAN=18% LP+25% ACF+25% Team+20% 协议奖励+7% 金库+3% 早期贡献者+2% 市场营销）；"50% 内盘"是名义值——发射后十几秒工厂即从内盘回收超发部分给 keeper（HAN 回收 32%），**内盘真实发售盘=披露的"X% Liquidity Pool"字段**；②全部 vesting 配额（HAN 五项 57%）进**同一个**锁仓合约（owner=keeper，平台托管），Virtuals API tokenomics 的多段 bips 结构可解析出精确日程（如 Treasury linearBips=[3000,0,583,6417]+numOfUnlocks=[1,1,1,11]=30% 立即+半年 cliff+11 次月线性）；③**ACF 在毕业前即可启动**（HAN 毕业前 54 分钟金库2 就开始喂执行器挂内盘）——"ACF=毕业后 V3 挂单"不全面，内盘期挂单对价是 VIRTUAL 而非 USDG，两段对价币种不同；④**ACF 成交量口径坑**：V3 池毛流出≠ACF 净成交（毛流出含套利搬去 V2 与买家回卖回流），净成交=挂入−池余−回流修正，报告引用必须拆"V3 净成交（USDG 对价）+内盘挂单（VIRTUAL 对价）"两段；⑤创始人自购弹药（VIRTUAL）与 ACF 内盘回款可在毕业后数小时内经 RelayRouterV3 桥离本链——转入该路由是"桥出/换出"，与"卖出"链上不可区分，措辞降级；⑥毕业时创始人获 sHAN 类质押凭证=**V2 主池 100% 初始 LP 的 10 年锁定凭证**（matureAt=毕业+10 年、founder=创始人，RPC 直查三值即可验）——撤池 rug 通道被平台机制锁死，是 BONDING_V5 标的的标准安全垫，分析必查必报；⑦**平台回购机器**（见 address-book `0x324872…`）毕业后分钟级启动 TWAP 买入，是 BONDING_V5 生态的系统性组件，买家榜前排出现它勿判外部庄。
4. **NOXA 发射结构**（GME 实测，@Noxa_Fi）：无 bonding curve——mint→V3 满贯池→**同交易可自购**（创建者可在发射 tx 内抢先建仓）；LP NFT 锁在平台合约、向创建者分交易费。发射台收费模式与 Virtuals 完全不同，别套用。**meow 实测补充（2026-07-15）**：①新版 LaunchToken 模板带反狙击限购（发射块仅 deployer 可买 LaunchBlockBuyBlocked + 后 366 个 L1 块每钱包 maxWallet 上限、deployer 豁免；block.number 是 **L1 以太坊块号**不是本链块号）；②LaunchLocker protocolFeeShare=100→费 100% 先进 feeRouter 再分（WETH 侧 creator 分成、token 侧烧 80%）——deployer 从 Locker 收到的转账是 0 wei，真实费流水看 feeRouter→creator；③**"特权自购砸价+同注资网络马甲低吸卖 FOMO"组合拳模式**：deployer 特权自购（例 12.74%）+7~14s 全卖回制造低价与首秒巨量→同一上游注资的马甲组在下一块（+15-18s）各买 ≤maxWallet 绕限购→2-3 分钟内卖给涌入公众——**凡 NOXA 类满贯池标的，必查发射后 60 秒内买家与 deployer 注资网络的资金边**（马甲注资在发射前 1-3 天、0.5-0.6E 级批量）；deployer"自购-秒卖"不能只当"无人接盘撤本金"，先排查马甲腿（meow，07-15）。
4a. **LaunchToken 参数是发射配置项、发射块特权可不行使**（BEGGAR 实测 2026-07-17）：maxTxBps=10000（100%）时单笔不限购、只有 maxWallet 生效；restrictionBlocks 可变（BEGGAR=366 L1 块）——读构造参数勿套旧案数值。发射块 deployer 独家买入特权存在但**可以不行使**（BEGGAR 官方零自购、限购期 73 分钟仅 3 个外部狙击 bot 各顶格 maxWallet）——"平台/创始人有自买前例"≠"本案必有自买腿"，用发射块 transfer 实证；狙击顶格整数枚买入（恰=maxWallet 上限）是专业狙击指纹。ENS 双向解析（ensdata.net / ensideas.com 免费 API，走代理）可对本链实体做 ETH 主网 ENS 正反解析——正反一致=域名主人自设非投毒，是官方身份"链上自认"级证据（treasury.noxa.eth 案例一锤定音）。NOXA 官方地址族与出纳机器人见 address-book Robinhood 段（出纳的 ETH 分发名单=官方关联仓发现通道，见 playbook §4）。

4b. **Flap 发射结构**（COMPUTE 实测 2026-07-12，flap.sh，第三家）：工厂=Portal 可升级代理 `0x26605f…`（地址簿有）；`newTokenV6` 创建、tx value 全额作 quoteAmt **同 tx 自购**；铸 1B 到工厂→**工厂自身就是内盘 bonding**（买入=工厂出账经中转路由分发、卖回=币回工厂；热盘 99 秒可售罄 8 亿）→毕业注 V2（实测 5 ETH+2 亿枚）+**LP 烧毁**；代币本体=EIP-1167 最小代理→官方模板 FlapTaxTokenV3（`0x…7777` 后缀是平台统一 vanity 非项目方定制，**"未验证"表象下逻辑全在已验证模板里**）；创作者可设永久买卖税（COMPUTE 2%/2%×100 年）：税先落**代币合约本体**→分批归集进随币部署的 TaxProcessor→机械卖回池子（实测中位 104 秒/笔），ETH 95% 归 beneficiary、5% 分红给持币 ≥minimumShareBalance 的地址。分析税币时：税卖出是独立机械卖压，单列勿混入庄家出货；beneficiary 资金流=项目方真实收入通道。
5. 内盘可能几分钟就毕业（RAXOL：12 分钟），内盘期无 K 线；毕业价=V2 首根分钟K open，狙击者成本用它近似并声明。
6. 交易税代币：代币合约自身持币是"税池在途"，税经固定 swapper 合约自动卖回池子——机械卖压，归因时单列，别算进"庄家卖出"。
7. Uniswap V4 是单例 PoolManager（`0x8366a39cc670b4001a1121b8f6a443a643e40951`），它的"持仓"是全部 V4 池流动性，别当大户。
8. **V4 侧成交量已不可忽略**：热门标的 V4 池日吞吐可达亿枚级（CASHCAT 实测高峰日均 0.8-1.65 亿枚双向），只拉 V3 Swap 会漏掉这部分成交额/参与者——要么补拉 V4 PoolManager 的 Swap 事件（单例合约按 topic1=poolId 过滤，采集方案见坑 12），要么在报告局限性里显式声明 V4 盲区（CASHCAT，07-13）。
9. **NOXA 平台机制细节**（发射者/销毁归因必备）：LP 手续费经 locker 100% 归集到 feeRouter `0x9efdc1a8e6e94f16a228e44f3025e1f346ee0417`，feeRouter 对代币计价份额**烧 80%、留 20% 卖回主池变现**——dead 地址的销毁大头是平台抽成机制不是社区烧币，归因时单列；creator 的代币计价份额政策可能中途变更（CASHCAT 实测 7/1 起归零改纯 WETH 领费，且平台会向 creator 发 0 枚心跳转账）（CASHCAT，07-13）。**feeRouter 的 collect 与 setConfig 均无许可**：collect 任何人可代触发、费照打给受益人（实测一窗口 6 轮 collect 中 3 轮系第三方工具代发——"creator 领费动作"计数前先查每笔 txfrom）；烧币伴随 collect 结算（谁触发都烧），成交萎缩后烧速退化为"collect 频率指标"。setConfig(token,receivers,percents)=受益人登记；**noxa 前端死亡后存在平台级登记浪潮**（实测 07-14 单日约 911 笔 vs 常日 25-136）——个体 setConfig 定性"主动抢费/权限异动"前，先按事件 topic 扫同期全平台分布（Pointless 二次增量对抗复核，07-17）。
8. **零地址直铸 ETH = 平台内部充值通道（第二种溯源断头）**（Pointless 实测 2026-07-13）：gas 溯源某金主的原生币入金时，若 `from=0x0000…0000`（Blockscout internal-transactions 里 from 为零地址的 value>0 记录），这是 Robinhood **App 内充值/托管提币通道**（平台从其托管池给用户 L2 地址打 ETH），不是链上桥。与 Relay 桥（`0xf70da…`）并列为两种断头——L1 身份不可穿透，报告按"平台通道断头"声明。实例：某狙击组金主发射前一天经此通道入金 100 ETH。
9. **EIP-7702 智能账户识别**（Pointless 实测 2026-07-13）：前排"合约持有人" `eth_getCode` 返回 **23 字节 `0xef0100`+20字节地址** = EIP-7702 委托账户（不是普通合约，是挂了 delegation 的 EOA），末 20 字节是委托实现地址。这是 Robinhood 钱包产品给用户账户的标准形态，**非机构锁仓、非合约金库**；不同用户可能指向同一实现地址（如 `0xef0100e6cae8…`），**委托实现相同 ≠ 同一实体**，勿据此聚类。与 ERC-4337（txto=EntryPoint）是两套并存的 AA 方案。Robinhood 钱包标准实现之一 `0xe6cae83bde06e4c305530e199d7217f42808555b`（TRASH 分析实测 top30 大户 12/14 个 7702 户共用它——同实现≠同实体，是 App 散户标配）。

10. **Uniswap 官方 Liquidity Launchpad 发射结构（CCA 拍卖，第 4 类发射台，TRASH 分析实测 2026-07-14）**：2026-07-13 官方宣布上线 Robinhood 链，合约层 permissionless（任何人可从 app.uniswap.org 网页 no-code 发射），源码全部 Uniswap 官方仓库（uerc20-factory / liquidity-launcher / continuous-clearing-auction）。**基建地址（跨链 canonical，Blockscout 已验证）**：UERC20Factory `0x000000e200088d55c39a11f609e5f667729ad49b`（代币模板 UERC20）、LiquidityLauncher `0x00004c4ccc709ef590f7c81102c0689f0263d4e9`、CCA 工厂 `0x000000001f26a0044baa66024e7b6599c61963f8`（每次发射它 CREATE2 部署一个 auction 实例=内盘 bonding 合约）、LBPStrategy 单例 `0x05d552391067389ee44fec3924157ed33f976000`（毕业时初始化 V4 池+迁移流动性，亦是合法 V4 hook）、V4 PoolManager `0x8366a39cc670b4001a1121b8f6a443a643e40951`、V4 PositionManager `0x58daec3116aae6d93017baaea7749052e8a04fa7`（96,061 笔的平台 keeper EOA 形态，替所有 launchpad 币建池，**gas/币流勿据它聚类**）。**机制**：铸 10 亿=X% 进 CCA 拍卖 + (100−X)% LP 储备（拆比是发射配置项，非常数；TRASH=50/50）→ CCA 连续清算拍卖（提交(maxPrice,amount)出价、逐块统一清算价、供应按时间表分块释放、防狙击靠跨块时间分布、价内不可撤未成交退款）→ 募集≥阈值即毕业注 V4 池→**创建者拿"组池后未用完的 LP 储备余数"（TRASH 案 0.095%，随清算结果浮动，非固定分成）+ LP position NFT**。协议费当前=0（费率控制器设零地址）。**创建者收益三通道**：①LP 头寸 1% 池费（NFT 在手/在其锁仓合约就归他）②组池 token 余数 ③自配 Distribution。**无 pump.fun 式平台→creator swap 费分成**。

11. **LP position NFT 归属与锁仓判别（"LP 无锁"必查，TRASH 复核推翻教训 2026-07-14）**：毕业时 LP NFT 铸给创建者 EOA **≠ 无锁可撤池**——必须查 `PositionManager.ownerOf(tokenId)`（selector `0x6352211e`，tokenId 从毕业 tx 的 ERC721 Transfer log 取）：①owner=创建者 EOA → 确实可随时撤池；②owner=某合约 → 读该合约源码判真锁。Uniswap 生态锁仓合约形态：**UniV4PositionLocker**（创建者自建、Blockscout 可验证）源码含 `LOCK_DURATION`（常量，TRASH=365 days）、`unlockTime`、`beneficiary`（immutable）、`withdraw()` 带 `StillLocked` 检查、`claimFees()`（锁期内仍可领费）——实读 `unlockTime()`（selector `0x251c1aa3`）拿到期时间戳、`beneficiary()`（`0x38af3eed`）确认受益人。协议原生也提供 TimelockedPositionRecipient/BuybackAndBurn 选件。**教训**：TRASH 初判"LP 无锁可随时撤池 rug"，复核查 ownerOf 发现 NFT 已锁进创建者自建 locker（真锁 365 天），结论整条反转为"锁池换信任+独享池费抽水"。

12. **V4 采集方案（补 CASHCAT 遗留的 V4 盲区 Known Gap，TRASH 实测收编 2026-07-14）**：V4 是单例 PoolManager，全部池的事件按 `topic1=poolId` 过滤（不是按池子地址）。**topic0 实测**：Swap=`0x40e9cecb9f5f1f1c5b9c97dec2917b7ee92e57ba5563708daca94dd84ad7112f`（data 6 字：a0,a1(带符号 int128),sqrtPriceX96,liquidity,tick,fee；topic1=poolId、topic2=sender）、ModifyLiquidity=`0xf208f4912782fd25c7f114ca3723a2d5dd6f3bcc3ac8db5af63baa85f711d5ec`（data 4 字：tickLower,tickUpper,liquidityDelta(带符号),salt）。用 `pull_swaps_v4.py`（已收编）一次拉全部池的 Swap+ModLiq，config 填 `swap_pools_v4`=poolId 数组 + `pool_manager`。实测 4.7 万条约 4 分钟。**a0/a1 方向**：token 是 currency0 还是 currency1 由两 currency 地址大小排序决定（ETH 原生=0x0 恒为 currency0；其余看地址）——**必须用实 tx 的同 tx Transfer 校准符号**（TRASH：token=currency1，a1>0=池流出=用户买入，实 tx 4/4 校准通过）。价格重建：`sqrtPriceX96` → (sqrtp/2^96)^2 = currency1/currency0 比价。
13. **V4 ModifyLiquidity 的 liquidityDelta 符号 = 撤池 vs 领费判据（TRASH 复核关键，2026-07-14）**：创建者/LP 从池子收到代币，`liqdelta<0`=真撤本金（减流动性）、`liqdelta=0`=纯 `collect` 领手续费（V4 领费的标准编码，本金分毫不动）、`liqdelta>0`=加池。**不查符号会把"领费"误判成"撤池出货"**——TRASH 案创建者"27 笔从 PoolManager 收币"全部 liqdelta=0（纯领费 4,184 万枚≈理论 1% 费的 90%），初稿误写"27 笔机械撤 LP"，复核纠正为"27 笔纯领费、零撤本金"。领费的 token 腿卖出=永续机械卖压，单列勿混"庄家出货"或"撤池"。
14. **V4 swap 归因用同 tx Transfer 净额，公共路由会虚高毛卖量（TRASH 实测 2026-07-14；地址修正 2026-07-14 增量更新）**：该链 **UniversalRouter 至少两个部署并存**——`0x8876789976decbfcbbbe364623c63652db8c0904` 与 `0x53bf6b0684ec7ef91e1387da3d1a1769bc5a6f77`（本条实测数字对应的是后者；设施剔除名单两个都必须含）。路由替散户透传卖单（同 tx 进出、净持仓恒 0）——按"from∈集团→PoolManager"的毛口径统计会把它透传的散户卖量算进集团（TRASH：毛 8.35 亿 vs 净 6.24 亿，差 2.32 亿是 0x53bf 替 66 个外部散户透传）。**正解**：按同 tx 的 Transfer 净变动归因终端买卖家（trader_ledger 做法），或先把 UniversalRouter 从集团名单剔除。复核曾把 0x53bf 误判为"私有出货漏斗"（只数集团内入边、未数全量 68 个来源）；**且当次复核只修正了账本归因、漏改实体地址表，该错误随 appendix 被增量更新继承**——复核修正的全落点同步纪律见 update-workflow U0（TRASH 更新，07-14）。

15. **第 5 类发射结构：ReflectionToken 外部资产分红盘（Index 分析实测 2026-07-18）**：区别于前四类（Virtuals/NOXA/Flap/Uniswap CCA），这类是**自建合约族 + 外部资产分红**——普通 ERC20（无税）+ 部署者建 V4 主池（Index/ETH）挂自建 `IndexFeeHook` 收**双向 3% 原生 ETH 税**（`FEE_BPS` constant、`treasury` immutable，税率与收税地址焊死不可改）→ 税进 `StockTreasury` 买"代币化股票" → `USDGBuyerDistributor` 按**链上 holder registry**（代币合约自维护、`minShareBalance` 门槛=入册阈值，`holderCount()`/`holderAt(i)` 直读）pro-rata 分发给持有人。分析要点：①**分红是外部资产**（Robinhood 代币化股票 AAPL/NVDA…）不污染本币筹码，但税=项目方现金流须用 Treasury 的 `StocksBought` 事件 ethSpent 求和量化（本案 507.8 ETH）②`LpLock` 合约=**新 rug-proof 结构**：源码无 removeLiquidity/withdraw、非代理不可升级、`seed` onlyOwner 一次性、`collect` 零 delta 只领 1% 池费——撤池通道合约层封死，"锁"的是 LP 头寸本金（被 swap 买走的币早进市场，故仍是全流通盘）③10 亿枚 100% 注入 LpLock、部署者本尊零预留——但见坑 16 的做市钱包例外。
16. **★"费收/项目方合约"可能是 EIP-7702 Ambire 做市钱包，费流去向必须实测（Index 分析对抗复核推翻子结论，2026-07-18）**：`LpLock.collect(address to)` 的 `to` 由 owner 任意指定，本案指向项目方一个 **EIP-7702 委托 EOA**（`eth_getCode` 返回 `0xef0100`+实现地址=Ambire 智能钱包，非普通合约、非部署者本尊）。**别假设费"全销毁/全回部署者"**：本案 collect 的 Index 只销毁 65%、留存 0.42% 在该做市钱包、其余转池做市；ETH 腿大头做市、少量桥出、仅 1/3 回部署者。且该钱包 `rewardsExcluded=0`——**项目方钱包本身在领本应分给散户的分红**。教训：判"项目方零留仓/纯公益"前必查三样——collect(to) 的实际去向 + 该地址 `rewardsExcluded` 标志 + `eth_getCode`（7702 做市钱包会被漏归散户）。
