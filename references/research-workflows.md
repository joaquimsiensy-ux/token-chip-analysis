# 多代理编排模板（research-workflows）

> 读者：下次执行代币筹码分析的 Claude。本文只讲「怎么派代理、怎么编排任务」，数据通道细节见同目录其他参考文档。
> 来源会话对照：OPN=BSC ①、SIREN=BSC ②、HYPE=Hyperliquid、FIL=Filecoin、IO=Solana。行尾括号即来源会话。
> 红线：本文只沉淀方法，不含任何对具体代币的分析结论。

## 一、情报 fan-out 模板（v5.0 起默认只启动路线 1；其余按需）

**v5.0 变更（2026-07-30 用户定）**：问 4 项目方背景调查随框架删除，原"背景调研 workflow 整路默认启动"废止。现规则：**vesting/解锁表标的默认启动路线 1（解锁情报，轻量单 agent）**——它是问 3 解锁小节的数据源；路线 2/3/4/6 降为**按需分析工具**（地址标注需要 CEX 地址库、事件对齐需要时间线、聚类冷启动需要分析师披露时再派）；原路线 5（项目方背景调查五块）整路删除。

**启动时机**（启用的路线）：主链上采集器一启动即派出，与采集并行、互不阻塞。（OPN、FIL）

**路线分工**：

| # | 路线 | 要点 | 实测来源 |
|---|------|------|---------|
| 1 | tokenomics 与解锁表 | **下次大解锁的时间和量是最重要的单一信息**，必须多源交叉：tokenomist.ai 与 dropstab 均实测可用且可互查（IO 用两者互验月度解锁指纹）；icodrops 为第三候选源（未实测）。⚠️ tokenomist 的「调整后释放供应量」是名义已解锁额度，不是实际流通量，两口径差过近一倍，用户曾因此读错字段 | （IO）（OPN） |
| 2 | CEX 与做市商地址库 | 收集该链交易所冷/热钱包、做市商机构已知地址，供地址标注环节消费 | （FIL）（OPN） |
| 3 | 事件时间线 | 上所/解锁/融资/黑客/营销事件，供后续与链上行为拐点对齐 | （OPN）（FIL 消息面路） |
| 4 | 链上分析师披露 | 搜 EmberCN、Lookonchain、Bubblemaps、PANews 等的既有披露，**「第三方指认名单 → 链上复核」范式**：从披露文章提取实体地址清单（含解码文中提到的大规模分发交易），再用批量余额查询核实现仓——绕过自建聚类的冷启动，不必等全量数据 | （SIREN） |
| 6 | （可选）官方文档/生态特有面板 | 如基金会文档、回购面板、跨链侧数据等，按链裁剪 | （HYPE 5 角度 sweep） |

**官方合约地址表一次拿全（正经项目标配动作，外加路线 2 的官方侧补充）**：正经 VC 币的官方 GitHub 合约仓库 README（github raw 直抓）通常自带全套协议合约地址表（代币/金库/质押/VestingFactory 等）——先抓它再谈聚类，官方系地址命名与归属一步到位（SQD 案全套协议合约+VestingFactory 一次拿全，配套 vesting 工厂枚举见 playbook-supply-recon §1）。（SQD，07-20）

另一种 fan-out 形态：对 N 个可疑地址各派一个代理 WebFetch 浏览器地址页，按统一 schema 输出（首笔注资来源/官方标签/钱包年龄/是否仍持仓），脚本端按 first_funder 分组——29 地址一轮并行约 10 分钟出全量结构化结果。（SIREN）**（外部 ASTEROID(ETH) 考古增强，2026-07）** 可升级用 Claude Code `Workflow` 工具编排（JS `tasks.push(()=>agent(COMMON+target))`），每 agent 输出加 `status_now∈[holding/accumulating/distributing/exited/inactive_dust]` 枚举、各落一份 `trace_<addr8>.md` 证据文件（每条论断带 tx hash），供对抗复核"只定位证据不信结论"独立重推；返回的 scriptPath 可编辑后 resume、失败用 journal.jsonl 续跑。

**prompt 纪律（写成 COMMON 前缀，所有路共用）**：

```text
[COMMON — 每个调研代理 prompt 开头原样带上]
1. 只用免费手段：WebSearch / WebFetch / 免费 API；禁用 firecrawl 等计费工具。
2. 接口纪律（防止与主采集器抢限速配额）：禁止对 <主采集通道> 做地址级/重型查询；
   <某面板> 调用 ≤5 次/分钟。—— 违反会把主采集长跑打成 429。
3. 每条论断必须带：来源 URL + 发布日期 + 置信度(high/med/low)。
3b. **资源约束（与限速禁令并列，2026-07-25 新增）**：禁止把查询结果 COPY/导出成 parquet/csv 文件；
    禁止任何可能产生 >100MB 中间文件的操作；duckdb 必设 memory_limit / threads /
    temp_directory / max_temp_directory_size 四项，且**每个查询必须带地址或日期过滤**，
    禁止无过滤全表 GROUP BY。—— 实锤：某复核 agent 为核查主池往来导出单个 **5.89GB** parquet，
    把可用盘从 44GB 打到 12GB，几乎拖垮全部并行任务；补派时加上本条后三路零事故。
4. 查不到就在结果里明说 "not_found"，禁止编造或用训练记忆填充。
5. 输出为严格 JSON，schema 如下：{...}（按路线定义字段）。
```

接口纪律不是客套：HYPE 会话中 5 个情报子代理与主采集器同打一个 IP 配额，把地址级长跑打到 429 刷屏（2 分钟只完成 16/1109 地址），靠「主采集限速上调 + 子代理 prompt 写死禁令」才恢复。（HYPE）

**模型选择**：两档制——机械型 `model:'opus'`+`effort:'high'`，判断型（怀疑者复核、完整性批评）model/effort 都不传继承主会话。**唯一权威源=context-discipline.md 刀 1**（完整外包/禁止外包清单、档位归属、Workflow vs Agent 写法差异都在那里，此处不重复）。

**输出处理**：Workflow 输出文件先落盘、用脚本解析抽取，再摘要打印，禁止整读进上下文（见第三节坑 2、坑 4）。

**fan-out 结果的消费去向（派之前就想好谁接盘）**：
- 解锁表 → 与链上「固定日期机械转账」指纹互验，并设下一个解锁日为可证伪观察点（预写结论强化/反转条件）。（IO）
- CEX/做市商地址库 → 直接喂给地址身份标注环节，剥离托管盘。（FIL）（OPN）
- 分析师指认名单 → Multicall3/批量余额接口核查现仓，直接量化「指认实体是否仍持仓」。（SIREN）
- 事件时间线 → 与 CEX 充提净流、金库出账的时间拐点对齐。（OPN）

## 二、对抗复核模板（发布前强制关卡）

这是五次会话中**投入产出比最高的环节**：SIREN 硬证据推翻 2/5 核心结论并重写报告主叙事；OPN 修正 6/10；HYPE 删掉整条指标、多条降级；FIL 零 REFUTED 但全面收紧表述、识破地址投毒。（SIREN）（OPN）（HYPE）（FIL）

**顺序**：先自己跑本地反例自查脚本（例：快照有无环比下降/流水有无反向记录/有无直转 CEX/核心金库有无大额出账），再派对抗代理——便宜的自查先挡一轮。（HYPE）

**分组建议（按预算三档）**：
- 轻量：每条关键结论 1 个反驳代理（5 条结论=5 代理）。（SIREN）（OPN 5 路）
- 加强：每条结论 × 3 视角 = 备择解释 / 数据审计 / 链上复核（4 组结论=12 代理）。（FIL）
- 无论哪档，**外加 1 个「完整性批评」角色**：不驳结论，专查报告缺了什么——曾抓出两处数字互相抵消的供应表错误。（HYPE）其 prompt 必含一问：**"原始数据中是否存在显著异常未被三问覆盖而漏报？"**（给它数据文件路径自查，对应三问一异常框架的开放条款——防止框架外发现被静默丢弃）。**必查"全史极值清单"（两案复现，正式）**：prompt 里明确要求它自己拉全史 **top-10 单笔转账**与**活动最密集时间窗**，逐条问"报告解释了这笔/这段吗"——怀疑者只核给定结论抓不到漏报，极值清单是漏检实体的高产发现通道（GMX 案"全史最密 48 小时"牵出被完全遗漏的协议回购链；EGL1 案"全史第三大单笔转账"牵出 47.1% 总量闪电过手的发射窗协同实体，6 路怀疑者全部未发现）（GMX 07-26；EGL1 redo2 07-28）。**极值清单第三维——日内瞬时峰值（第三案强化）**：日末口径序列对"当日买入当日卖回"的操作**整体不可见**——TROLL 案内盘 13 个月 7 轮做量/冲榜脉冲（单轮瞬时动用最高 22.3% 总供应、单日 52 址峰值和 113.7%）在日末重放曲线上持仓恒为零；PYTHIA 案同理有 W1 历史清零层（日级 max 可见、现仓不可见）。完整性批评的极值清单必须含**日内瞬时峰值扫描**（逐边重放取各址全史 max 时点持仓，不止日末），与"全期 max 仓位重放"（v4.1.0 复核 prompt 已固化）构成日级+日内双层口径盲区检查——判级流程侧走"日终＋L2 上界＋四触发日"折中口径（tiering"峰值判级口径"条），本条是复核侧的全史盲区检查、不受折中收窄；注意做量执行仓"从未真实持有"，不套"离场庄"标签（TROLL 07-29）

**可直接套用的 prompt 骨架**：

```text
你是链上取证审计员，唯一任务是推翻下面这条结论。

[待验结论] <原文粘贴，含数字与证据强度措辞>

[数据文件] <绝对路径清单 + 每个文件的字段说明、符号约定（value 正负方向）、去重规则>
你必须自己用 python 读这些文件实际重算，必要时可限量 curl 免费接口 / WebSearch 复核。
只审阅文字、不动数据的复核无效。

[必做动作]
1. 用原始数据重算结论中的每个数字，标出与原文的偏差。
2. 构造至少 2 个备择解释并逐一评估证据（示例类型：OTC 场外交割 /
   做市商多账户补库存 / 员工代币发放 / 交易所内部调仓 —— vs 原结论的解读）。
3. 检查观测边界：结论是否把「看不到」当成了「没有」。

[裁决标准]
- CONFIRMED / WEAKENED / REFUTED 三档。
- 「理论上可能但无证据」不算推翻，最多算 WEAKENED 的理由。
- REFUTED 必须给出你重算出的硬证据。

[输出 JSON schema]
{ "verdict": "...", "confidence_after": "...", "evidence": [...],
  "alternative_explanations": [...], "corrections": "修正后的表述建议" }
```

（骨架合成自：OPN 5 路审计员+强制备择解释；SIREN「必须实际核查」标准与三档裁决；FIL 附数据文件符号约定与去重规则；HYPE verdict schema 字段。）

**并行 fan-out 执行规范（B8 固化，2026-07-22）**：
- **全部怀疑者 + 完整性批评一次性同批并行发出**，不逐路串行——每路独立上下文互不知晓彼此存在，这不只是省墙钟，本身就是「独立复核」方法论的正确形态（互不污染）。裁决汇总与仲裁只在主会话做。
- **首选固化 workflow**：`Workflow({name: "adversarial-review", args: {...}})`（按名不可用时 `scriptPath: "~/.claude/workflows/adversarial-review.js"`；已实证按名解析认 `~/.claude/workflows/` 用户全局目录，但**注册表在会话启动时快照一次**——本会话中途新建/改名的 workflow 认不到，须用 scriptPath 或下个会话再按名调，2026-07-22 探针实测）——上面的 prompt 骨架与 verdict schema 已内置，**schema 强制输出**让 agent 裁决直接返回验证过的 JSON 对象（根治坑表 #2 的包装结构解析连败）；args 见脚本头注释（claims/data_note/integrity_files/workdir），脚本已带坑表 #3 的字符串化兼容层。冒烟实证：2 路 100 秒返回，完整性批评连测试数据的合成指纹都抓了出来（2026-07-22）。
- 返回的 `missing` 数组非空=有路次被跳过/失败，主会话必须补跑或人工核，禁止当零发现处理。
- 汇总仲裁规则：多路对同一结论分歧时，以**有硬重算证据**的一方为准（不投票）；REFUTED 的地址/哈希按下方 ★ 条先行为还原再吸收。

**外部异构怀疑者路（3.40.0 制度化，用户 2026-07-28 定）**：Claude 怀疑者 fan-out 之外，**每次对抗复核额外加一路 codex（GPT-5.6-sol）外部异构审计**——异构模型的幻觉模式与盲区同 Claude 不重叠，这是复核场景独有的红利（GOAT 案 GPT5.6 外部复核抓 9 条硬错误的战绩即此形态的手工实践；机械执行场景无此红利，机械外包仍走 opus+high 勿改）。**只是"额外加一路"，不替换任何 Claude 路，分档路数照旧**。

- **形态＝一路进程横扫全部 claims**（不做 per-claim 拆分）：输入=全部待验结论（编号）+数据文件绝对路径清单+data_note 字段说明，逐条独立裁决；与 Claude per-claim 深挖互补，且单进程能看见结论间互相矛盾（兼具完整性视角）。
- **调用形态（2026-07-28 冒烟实测：read-only 沙箱可真实执行 python3 只读重算并 `-o` 落盘，单次冒烟 2.6 万 token）**：`/Users/uravvv/.npm-global/bin/codex exec --sandbox read-only --skip-git-repo-check --cd <案目录> -o <案目录>/adversarial_external.md "<prompt>" 2><工作目录>/codex_err.log`，后台跑（run_in_background），与 Claude fan-out 同批发出、互不知晓。模型/effort 跟随 codex 全局配置（当前 gpt-5.6-sol + high，`~/.codex/config.toml`），命令里不硬编码 `-m`。**不复用 crosscheck.sh**（那是 @CX 顾问 PREFIX，本路要审计员 prompt）。
- **prompt＝本节怀疑者骨架的多结论版**：开头声明"你在只读沙箱，可执行 python3 只读重算（禁写盘），必须实际重算、只审文字的复核无效"；逐条列结论原文（含编号与数字）；附数据文件路径+字段/符号/去重说明；要求输出 JSON 数组 `[{id, verdict(CONFIRMED/WEAKENED/REFUTED), evidence, alternative_explanations, corrections}]` + 一段"结论间互相矛盾/全局缺口"观察；裁决标准同骨架（"理论上可能"不算推翻、REFUTED 须自己重算出的硬证据）。COMMON 资源约束照抄进去（duckdb 四项限制/禁大中间件——read-only 沙箱本身拦写盘，双保险）。
- **输入纪律（EGL1 实战教训两条）**：①待验结论**必须逐条从报告本体/findings 文件复制原文**，禁止主会话凭记忆/压缩摘要转述——上下文压缩后的摘要可能带旧口径，外审会对着不存在的错误开火空转（EGL1 案 @CX 拿到转述口径"放弃 74.37%"发起攻击，报告本体早已是拆分口径——codex 指对了转述、错怪了报告）；②数据文件清单里**已弃用的中间产物必须剔除或标注 DEPRECATED**——外审分不清哪份是权威产物，会拿弃用文件重算出"矛盾"（EGL1 案 codex 依据已弃用的 lp_pos.log 质疑 LP 份额，我方以 GoPlus+链上抽验+头寸级验算三源保留原数）（EGL1 redo2 @CX 复核，07-28）
- **裁决地位与吸收**：与 Claude 路同表仲裁，分歧照旧以有硬重算证据的一方为准（不投票）。★"地址/哈希不可信转录"条款对本路**加倍适用**（异构模型的转录进主线前必行为还原）。它若因沙箱/环境限制没跑成重算、只交文字审读——不作废但**降级**：其 REFUTED 不能单独翻案，须主线或 Claude 路重算确证后方可吸收（对齐"只审阅文字的复核无效"）。分歧裁决实例：EGL1 案 codex 三项裁决按此吸收——"等额分片"质疑我方全量重放确证 codex 对（295 笔 287 种金额，撤回等额定性）；LP 份额质疑因其依据弃用产物、我方三源硬验算在手而保留原数；充提倍数质疑部分采纳（补机制说明、核心事实保留）——**吸收的单位是"证据"不是"整份报告"，逐条各自裁**（EGL1 redo2 @CX 复核，07-28）。
- **失败兜底**：本路是增强路，超时/报错/输出为空**不阻塞交付**（区别于 Claude 路 missing 必补跑），但复核记录必须写明"外部异构路未跑成"及原因，err 日志留档备查。
- **权限边界**：沙箱 read-only（`-o` 输出由 CLI 宿主侧写、非沙箱内写），与 @CX"只读"约定同款，不给 codex 放案目录写权限。

**裁决吸收纪律**：
- 裁决必须原样吸收，不许挑着改：先修数据管线、再修文案，图表标题/箭头数字/脚注同步改。（OPN）（FIL）
- 修正记录整理成表印进报告附录，不藏着。（OPN 附录 7.3 做法）
- **★怀疑者报告里的地址/哈希一律视为不可信转录，采纳前必须行为还原**：怀疑者 agent 的结构性发现可以全对（份额/前后缀/事件时间精确），但其报告里抄写的完整地址中段可能整批是幻觉（实锤：9 个地址前缀、尾缀、份额全对，40-hex 中段全错——主分析若直接抄入 appendix 即埋雷）。标准动作：对怀疑者点名的每个地址，用其描述的行为特征（同秒共现/份额档位/首买时间）从本地数据**重新检索出真实地址**再采纳；两边对不上时以数据还原为准。它自证有效的场景同样适用于审计路（tx 哈希抽验时先在本地数据 grep 该哈希存在性）。（TRASH 更新复核，07-17）

**裁决 → 修正动作对照（历次实际发生过的处理）**：

| 裁决 | 典型修正动作 | 实例来源 |
|------|-------------|---------|

## 二b、重点实体素材装配外包模板（3.19，B2；v5.0 对象改为流转图门槛实体；模型 opus + effort high）

**定位**：阶段 3 聚类判级完成后、写报告前，每个重点实体（=达到流转图门槛的实体：当前持仓 ≥20% 总供应或 ≥20% 流通的大庄/项目方，v5.0 用户定）的**素材整理是机械活**（逐址时间线、内部转移矩阵、关键 tx 清单、流转图 spec 草稿），外包给子代理并行装配省主线轮次；**判定、定性、意图解读、报告撰写永远留主线**（成本纪律刀 1 外包禁区不变）。**模型 `model:'opus'` + `effort:'high'`**（用户 2026-07-22 定 opus，2026-07-28 补钉 effort:high；Agent 工具无 effort 参数，要钉死就走 Workflow 派）。

**完整版与 easy 版都要跑这一路（3.39.1 补，此前 easy-workflow 对本节沉默）**：easy 不出流转路径图，所以第 3 节（flow spec 草稿）在 easy 模式下**免做**，第 1/2/4 节（时间线、转移矩阵、疑点清单）照做——它们是 easy 阵营表"按实际实体结构细分"与判定块的素材源，也是 E4 怀疑者的复核靶子。

**每个重点实体一个子代理，N 路并行**。prompt 骨架（自包含，子代理看不到主线对话）：

```
你为代币 <SYMBOL>（<链>）的实体 <entity_id>（<label>）装配分析素材。只整理事实，
禁止做实体定性/判级/意图判断——那是主线的活。
成员地址（<N> 个，从 <案目录>/analysis-state.json 该 entity_id 组复制）：<逐行列出>
数据文件：全量转账 <路径>（列结构：...）；余额快照 <路径>；价格 <路径>
产出写 <案目录>/dossiers/entity_<id>_dossier.md，含四节：
 1. 逐址持仓时间线关键点：首次获币/峰值/清仓时点 + 大额变动 top10 逐笔
    （ts+tx哈希+数量+对手方地址——一律从数据文件复制，手打=编造）
 2. 内部转移矩阵：成员间互转的（from,to,总量,笔数）汇总 + 外部 top10 对手方
 3. 流转图 spec 草稿：figures_from_facts flow 格式 JSON 落 <案目录>/dossiers/
    flow_<id>_draft.json——节点/边结构照 lifecycle_flow.py docstring 排版约定，
    持仓/份额数字一律写 {{<entity_id>.amount_share}} 等 facts 宏占位，不填实数
 4. 疑点清单：数据里看到但你不下结论的异常（如某址行为与组内其他成员不同）
回报 ≤30 行：各节要点 + 产物路径 + 数据覆盖区间。
```

**主线消费**：读 dossier 做判定与撰写；流转图 spec 草稿人工校核结构后经 `figures_from_facts.py flow` 渲染出图（宏由 facts 解析，数字同源）。dossier 里的 tx 哈希/地址进报告前仍过 real_addr 反查纪律。

## 三、Workflow/Agent 工具使用坑速查

| # | 坑 | 症状 | 正确姿势 | 来源 |
|---|-----|------|---------|------|
| 1 | Workflow 不接受 `run_in_background` 参数 | 首次调用直接 InputValidationError，整段约 4KB 多代理脚本白提交 | Workflow 天然后台跑且完成会通知，去掉该参数原样重发即可 | （OPN）（HYPE） |
| 2 | 输出文件是包装结构不是裸 JSON | 按子代理 schema 用 `find('{"intel"')`/regex 截取解析，KeyError/raw_decode 连败 | `tasks/<id>.output` 顶层是 `{summary, agentCount, logs, result}`，直接 `json.load(open(f))['result']`；写解析前先 Read 文件头确认结构 | （HYPE）（FIL）（SIREN） |
| 3 | args 以字符串传入 | 脚本按对象取 `args.list` 得 undefined，fan-out 空转 | 传对象不传字符串；脚本端加 `typeof args==='string' && JSON.parse` 兼容层；已启动的 run 用 resumeFromRunId 续跑不浪费 | （SIREN） |
| 4 | 大输出整读进上下文 | 两次 TaskOutput 直接进上下文共约 55KB（调研 32KB+复核 23.8KB） | 解析后存档到 data/ 子目录，再用 sed/grep/python 定向抽取所需字段摘要打印；66KB 原文落盘不整读是正面示范 | （OPN）（HYPE） |
| 5 | 前台 sleep 被环境 Block | `sleep 90; ...` / `sleep 60` 链式等待当场被拒 | 等条件用 `until <check>; do sleep N; done`；等自己启动的命令用 run_in_background；周期监控用 Monitor 或 `tail -f \| grep --line-buffered` | （SIREN）（HYPE）（OPN） |
| 6 | TaskOutput 阻塞式等待 | `block=true timeout=600000` 连续空等约 50 分钟 | 长任务不用阻塞等待，改 Monitor 事件驱动 + 等待期干下游活 | （OPN） |
| 7 | 后台命令链里裸 glob | `rm -f part_*.csv && python3 ...` 因 zsh 无匹配 glob 报错，把后面的采集脚本一起杀死 | 后台命令避免裸 glob：`rm -f file 2>/dev/null \|\| true`、先 `setopt null_glob`、或拆成两条命令 | （OPN） |
| 8 | 子代理与主采集器抢配额 | 情报代理并发打同一 IP，主长跑 429 刷屏 | 子代理 prompt 里写死接口禁令与限速上限（见第一节 COMMON 前缀） | （HYPE） |
| 9 | 后台长任务输出接 `\| tail` 管道 | tail 缓冲把全部中间进度吞到进程结束——任务失败时诊断信息为零（PUB 的 SQD 首次被杀即死无对证）；同族：python print 不 flush 时日志文件长期 0 字节 ≠ 没干活 | 后台长任务日志**直写文件**（`> data/xx.log 2>&1`）不过管道；进度用文件侧探（ls 数据文件 / wc -c 日志）或 Monitor；判断存活看 `ps` CPU 时间增长，不看日志长度 | （PUB 2026-07-14） |
| 10 | TaskStop/pkill 的进程组误伤 | 停一个链式后台任务 + pkill 特定脚本，连带杀掉不相关的后台任务（另两个排队任务的 until 循环同时消失） | ①链式任务合并成单条后台命令内部串行，少用"等待型 until 排队"②kill 精确到 PID 而非 pattern ③关键长跑（SQD 类）nohup 脱管与 Claude 任务管理解耦（环境坑详见 environment.md 沙箱节） | （PUB 2026-07-14） |

**兜底心法**：Workflow/Agent 的返回物一律当「待解析的文件」处理，不当「可直接读的文本」；任何等待一律事件驱动，不占前台；任何长跑必须可续传、可观测、可报警。（OPN/SIREN/HYPE/FIL 四会话共同教训）
