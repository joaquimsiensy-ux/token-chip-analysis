# Robinhood Chain 数据管道（2026-07-12 GME + RAXOL 两次分析实测合并）

Robinhood Chain = Arbitrum Orbit L2（chainid 4663），原生 gas 币 ETH，Uniswap V2/V4 双栈。已知发射台四类：Virtuals Protocol（agent 币，标准 1B 总量、约 1% 交易税、内盘 bonding curve 毕业建池）、NOXA（无 bonding curve，见坑表）、Flap（flap.sh，见坑表 4b）、**Uniswap 官方 Liquidity Launchpad（CCA 拍卖，2026-07-13 上线该链，见坑 10；TRASH 分析实测）**。

> 本文由同日两次独立分析（GME 18:37 交付、RAXOL 19:09 交付）的通道结论合并而成——两会话互不知情，曾产生互相矛盾的记录（见文末修正记录），合并后以下为当前权威版本。

## 通道决策（实测）

## 链特有的坑（重要）

1. **平台级 gas 中继污染 gas 同源信号**：`0xf70da97812cb96acdf810712aa562db8dfa3dbef` = **Relay 桥 solver 热钱包**（38 万+笔的公共基础设施）——给全链用户供 gas（RAXOL：161/238 候选地址的 gas 来自它）、替用户代发交易（txfrom 大量是它）、还替空投池发币。**"同用 f70da 供 gas"≠同一实体，只说明都经 Relay 桥入金**；做聚类前必须把它从母钱包证据里整体剔除，否则 2/3 大户会被误判成一个庄（GME 会话曾差点把它误判为庄家总金库；两会话独立踩中同一坑）。同类还有 `0x00000000aa59b37306e34cef3e021e07156cfa3a`（聚合器执行器）。已入 address-book.md Robinhood 段。
2. **Arbitrum 官方桥地址别名溯源**（穿透到 L1 身份的关键一招，GME 实测）：L2 上入金方地址若与收款地址"中段相同、前后 4 hex 不同"，即 `L2显示地址 = L1真实地址 + 0x1111000000000000000000000000000000001111`——减掉常数即得 L1 真实地址（含挂 EIP-7702 代码的 EOA），可用 Etherscan 继续溯源金主。**反向警告（TRASH 增量更新 2026-07-14，3 例误判）**：gas 首笔入金溯源时，"funder"若恰为目标地址+别名常数，则是**目标本人从 L1 跨链自充值**，不是独立金主——不做此检测会把自充值大户误记"有独立金主"，也会把两个自充值地址误判"资金独立"。gas_trace_bs.py 已内置 alias 自检（funder 减常数==目标即标 self_alias）。
3. **Virtuals 发射结构**（链上实测，RAXOL；VEX 2026-07-13 实测升级为 BONDING_V5 全解）：铸 1B → 50% 内盘 bonding + 50% 给跨项目 keeper `0x81f7ca…`（它同时是平台分账 EOA，见 address-book）→ 拆两金库：**金库1=Team 25% 合约锁仓**（TGE+1 年 cliff+6 个月线性，解锁表在 Virtuals API tokenomics 字段可直查）+ **金库2=ACF 配额 25%（EOA，平台预生成设施）**。ACF（Automated Capital Formation）= 金库2 分批把币交给平台批量执行合约 `0x3eb3…` 挂进 V3 USDG 池做**纯单边阶梯卖单**（FDV 每 +$10 万一档、五大区间各 5% 供应、上限募 $11.55M），成交本金 100% 直付创始人钱包——**"涨=项目方自动收钱"是白皮书公开机制**。分析时：①ACF 消耗进度=庄家问题的核心变量（挂进池的份额≠已卖出，在册挂单可撤回，图2 要注记会计转移效应）②毕业 tx 里工厂另拨一笔给"拨付仓"EOA（疑似内盘 99%→1% 反狙击税回收，条款 3 个月 cliff+9 个月线性归创始人）③创始人真实收入=ACF 本金+税分成 70%，其再分发路径（USDG 定向转账）是挖关联钱包网的主线索。旧记录"金库2 常拨一部分做空投池"为 RAXOL 时期观察，BONDING_V5 下金库2 专职 ACF。**HAN 实测补充（2026-07-16，全账本 wei 级复核）**：①分配比是**发射配置项非常数**（HAN=18% LP+25% ACF+25% Team+20% 协议奖励+7% 金库+3% 早期贡献者+2% 市场营销）；"50% 内盘"是名义值——发射后十几秒工厂即从内盘回收超发部分给 keeper（HAN 回收 32%），**内盘真实发售盘=披露的"X% Liquidity Pool"字段**；②全部 vesting 配额（HAN 五项 57%）进**同一个**锁仓合约（owner=keeper，平台托管），Virtuals API tokenomics 的多段 bips 结构可解析出精确日程（如 Treasury linearBips=[3000,0,583,6417]+numOfUnlocks=[1,1,1,11]=30% 立即+半年 cliff+11 次月线性）；③**ACF 在毕业前即可启动**（HAN 毕业前 54 分钟金库2 就开始喂执行器挂内盘）——"ACF=毕业后 V3 挂单"不全面，内盘期挂单对价是 VIRTUAL 而非 USDG，两段对价币种不同；④**ACF 成交量口径坑**：V3 池毛流出≠ACF 净成交（毛流出含套利搬去 V2 与买家回卖回流），净成交=挂入−池余−回流修正，报告引用必须拆"V3 净成交（USDG 对价）+内盘挂单（VIRTUAL 对价）"两段；⑤创始人自购弹药（VIRTUAL）与 ACF 内盘回款可在毕业后数小时内经 RelayRouterV3 桥离本链——转入该路由是"桥出/换出"，与"卖出"链上不可区分，措辞降级；⑥毕业时创始人获 sHAN 类质押凭证=**V2 主池 100% 初始 LP 的 10 年锁定凭证**（matureAt=毕业+10 年、founder=创始人，RPC 直查三值即可验）——撤池 rug 通道被平台机制锁死，是 BONDING_V5 标的的标准安全垫，分析必查必报；⑦**平台回购机器**（见 address-book `0x324872…`）毕业后分钟级启动 TWAP 买入，是 BONDING_V5 生态的系统性组件，买家榜前排出现它勿判外部庄。
4. **NOXA 发射结构**（GME 实测，@Noxa_Fi）：无 bonding curve——mint→V3 满贯池→**同交易可自购**（创建者可在发射 tx 内抢先建仓）；LP NFT 锁在平台合约、向创建者分交易费。发射台收费模式与 Virtuals 完全不同，别套用。**meow 实测补充（2026-07-15）**：①新版 LaunchToken 模板带反狙击限购（发射块仅 deployer 可买 LaunchBlockBuyBlocked + 后 366 个 L1 块每钱包 maxWallet 上限、deployer 豁免；block.number 是 **L1 以太坊块号**不是本链块号）；②LaunchLocker protocolFeeShare=100→费 100% 先进 feeRouter 再分（WETH 侧 creator 分成、token 侧烧 80%）——deployer 从 Locker 收到的转账是 0 wei，真实费流水看 feeRouter→creator；③**"特权自购砸价+同注资网络马甲低吸卖 FOMO"组合拳模式**：deployer 特权自购（例 12.74%）+7~14s 全卖回制造低价与首秒巨量→同一上游注资的马甲组在下一块（+15-18s）各买 ≤maxWallet 绕限购→2-3 分钟内卖给涌入公众——**凡 NOXA 类满贯池标的，必查发射后 60 秒内买家与 deployer 注资网络的资金边**（马甲注资在发射前 1-3 天、0.5-0.6E 级批量）；deployer"自购-秒卖"不能只当"无人接盘撤本金"，先排查马甲腿（来源：meow(Robinhood) 分析，2026-07-15）。
4a. **LaunchToken 参数是发射配置项、发射块特权可不行使**（BEGGAR 实测 2026-07-17）：maxTxBps=10000（100%）时单笔不限购、只有 maxWallet 生效；restrictionBlocks 可变（BEGGAR=366 L1 块）——读构造参数勿套旧案数值。发射块 deployer 独家买入特权存在但**可以不行使**（BEGGAR 官方零自购、限购期 73 分钟仅 3 个外部狙击 bot 各顶格 maxWallet）——"平台/创始人有自买前例"≠"本案必有自买腿"，用发射块 transfer 实证；狙击顶格整数枚买入（恰=maxWallet 上限）是专业狙击指纹。ENS 双向解析（ensdata.net / ensideas.com 免费 API，走代理）可对本链实体做 ETH 主网 ENS 正反解析——正反一致=域名主人自设非投毒，是官方身份"链上自认"级证据（treasury.noxa.eth 案例一锤定音）。NOXA 官方地址族与出纳机器人见 address-book Robinhood 段（出纳的 ETH 分发名单=官方关联仓发现通道，见 playbook §4）。

4b. **Flap 发射结构**（COMPUTE 实测 2026-07-12，flap.sh，第三家）：工厂=Portal 可升级代理 `0x26605f…`（地址簿有）；`newTokenV6` 创建、tx value 全额作 quoteAmt **同 tx 自购**；铸 1B 到工厂→**工厂自身就是内盘 bonding**（买入=工厂出账经中转路由分发、卖回=币回工厂；热盘 99 秒可售罄 8 亿）→毕业注 V2（实测 5 ETH+2 亿枚）+**LP 烧毁**；代币本体=EIP-1167 最小代理→官方模板 FlapTaxTokenV3（`0x…7777` 后缀是平台统一 vanity 非项目方定制，**"未验证"表象下逻辑全在已验证模板里**）；创作者可设永久买卖税（COMPUTE 2%/2%×100 年）：税先落**代币合约本体**→分批归集进随币部署的 TaxProcessor→机械卖回池子（实测中位 104 秒/笔），ETH 95% 归 beneficiary、5% 分红给持币 ≥minimumShareBalance 的地址。分析税币时：税卖出是独立机械卖压，单列勿混入庄家出货；beneficiary 资金流=项目方真实收入通道。
5. 内盘可能几分钟就毕业（RAXOL：12 分钟），内盘期无 K 线；毕业价=V2 首根分钟K open，狙击者成本用它近似并声明。
6. 交易税代币：代币合约自身持币是"税池在途"，税经固定 swapper 合约自动卖回池子——机械卖压，归因时单列，别算进"庄家卖出"。
7. Uniswap V4 是单例 PoolManager（`0x8366a39cc670b4001a1121b8f6a443a643e40951`），它的"持仓"是全部 V4 池流动性，别当大户。
8. **V4 侧成交量已不可忽略**：热门标的 V4 池日吞吐可达亿枚级（CASHCAT 实测高峰日均 0.8-1.65 亿枚双向），只拉 V3 Swap 会漏掉这部分成交额/参与者——要么补拉 V4 PoolManager 的 Swap 事件（单例合约按 topic1=poolId 过滤，采集方案待实做，见 CHANGELOG Known Gaps），要么在报告局限性里显式声明 V4 盲区（来源：CASHCAT 分析，2026-07-13）。
9. **NOXA 平台机制细节**（发射者/销毁归因必备）：LP 手续费经 locker 100% 归集到 feeRouter `0x9efdc1a8e6e94f16a228e44f3025e1f346ee0417`，feeRouter 对代币计价份额**烧 80%、留 20% 卖回主池变现**——dead 地址的销毁大头是平台抽成机制不是社区烧币，归因时单列；creator 的代币计价份额政策可能中途变更（CASHCAT 实测 7/1 起归零改纯 WETH 领费，且平台会向 creator 发 0 枚心跳转账）（来源：CASHCAT 分析，2026-07-13）。**feeRouter 的 collect 与 setConfig 均无许可**：collect 任何人可代触发、费照打给受益人（实测一窗口 6 轮 collect 中 3 轮系第三方工具代发——"creator 领费动作"计数前先查每笔 txfrom）；烧币伴随 collect 结算（谁触发都烧），成交萎缩后烧速退化为"collect 频率指标"。setConfig(token,receivers,percents)=受益人登记；**noxa 前端死亡后存在平台级登记浪潮**（实测 07-14 单日约 911 笔 vs 常日 25-136）——个体 setConfig 定性"主动抢费/权限异动"前，先按事件 topic 扫同期全平台分布（来源：Pointless(Robinhood) 二次增量对抗复核，2026-07-17）。
8. **零地址直铸 ETH = 平台内部充值通道（第二种溯源断头）**（Pointless 实测 2026-07-13）：gas 溯源某金主的原生币入金时，若 `from=0x0000…0000`（Blockscout internal-transactions 里 from 为零地址的 value>0 记录），这是 Robinhood **App 内充值/托管提币通道**（平台从其托管池给用户 L2 地址打 ETH），不是链上桥。与 Relay 桥（`0xf70da…`）并列为两种断头——L1 身份不可穿透，报告按"平台通道断头"声明。实例：某狙击组金主发射前一天经此通道入金 100 ETH。

13. **V4 ModifyLiquidity 的 liquidityDelta 符号 = 撤池 vs 领费判据（TRASH 复核关键，2026-07-14）**：创建者/LP 从池子收到代币，`liqdelta<0`=真撤本金（减流动性）、`liqdelta=0`=纯 `collect` 领手续费（V4 领费的标准编码，本金分毫不动）、`liqdelta>0`=加池。**不查符号会把"领费"误判成"撤池出货"**——TRASH 案创建者"27 笔从 PoolManager 收币"全部 liqdelta=0（纯领费 4,184 万枚≈理论 1% 费的 90%），初稿误写"27 笔机械撤 LP"，复核纠正为"27 笔纯领费、零撤本金"。领费的 token 腿卖出=永续机械卖压，单列勿混"庄家出货"或"撤池"。

## 方法论坑（对抗复核实锤，通用性强）

- **平台充值通道=溯源断头**：凡入金经平台通道（f70 类）的庄组，组间真实独立性链上不可判定——报告必须声明"N 组是链上可分辨的下限拆分"。
- **"同分钟同金额转出"≠洗仓分仓**：必须核实是否存在"老仓→马甲"的直接转账；RAXOL 案例中马甲实为同分钟**从池子市场买入**（老仓早已割肉卖出），机制完全不同、成本完全不同。判据：grep 组内互转，零条即排除转账式洗仓。
- **漏斗地址检测必做**：扫"收自非市场地址且 ≥90% 即收即卖"的地址（RAXOL：12 个经手 9.37% 总量），再对最大"散户"卖家逐个查上游——归集出货网络（N 上游买入→1 hub 卖出）会完美伪装成散户卖压。
- **毛卖出/净卖出要分开报**：暴跌归因只看毛卖出会夸大散户责任（RAXOL：散户毛卖 2.6 亿枚、净卖仅 4,480 万枚）。
- **分钟K收盘定价低估大单成本**：单笔吃掉 >0.5% 总量的买入，真实滑点成本显著高于分钟K收盘；重仓组成本按"下限"表述。
- gas 同源边要查**时序**：母钱包供 gas 若晚于建仓，只能证明"建仓后共用补给"，不能写"母钱包出资建仓"。
- **外部尘埃投毒可伪造"出纳网络"**（对抗复核 REFUTED 实例）：第三方营销 dust（单日激活钱包批量给 63 址各发 0.0006 ETH）曾被误判为"庄家出纳补 gas 备出货"，实体判定整条作废。**出纳判定三查（缺一不可）**：①拉出纳地址本体**全量 tx**核验收款人全集与历史（gas_in 只采样目标侧会漏全貌——本例"19 址出纳网"实为 63 址无差别撒网的截取假象）②查收款人构成——含"从未持仓/已清仓/公开 bot 农场"地址即非庄家仓位名单③与其他代币空投名单查同额重叠。真出纳反证特征：低频专职（<500 tx）、发射前注资、金额为建仓级（0.5-1 ETH）而非尘埃级（来源：CASHCAT 分析 2026-07-13）
- **两跳马甲追踪每跳节点必须先 eth_getCode 体检**：下游集合混入公共 swap 执行合约会把"经合约买币的散户"批量误判为马甲（CASHCAT 案 132 址体检揪出 14 个合约，军团经济体现仓从 21.9% 上限修至 12.7%）；与 v1.7 的"原子中转识别法"（同 tx 进出>90%）互补使用——前者防误聚 EOA 下游，后者批量揪中转设施（来源：CASHCAT 分析 2026-07-13）
- **大集群先做"假桥"排查再报数**：聚类含公共合约节点时，其转账边会把多个独立 gas 星座虚接成单一大集群（96 址 53.97% 清洗后拆为 40/15/5 三个各自达标的星座）——呈现方式见 playbook §6a 双层范式（来源：CASHCAT 分析 2026-07-13）反之**发射前预注资**（COMPUTE：专属母钱包发射前 1-2 天批量注资矩阵成员，且与官推注册同 48h 窗口）是"预谋建仓"最硬的时序证据，值得专门做链上-链下时间对齐表。
- **该链 swap 归因必须用 swap.to 而非 txfrom**（COMPUTE 实测）：散户交易大量经 bot relayer 代发（txfrom=relayer、币直达终端），按 txfrom 归因会把几十用户的买入算到一个 relayer 头上，制造假"超级买家"。卖出侧按"给池子币的 transfer.from"归因。
- **原子中转设施识别法（先跑一遍再聚类，防 23 个设施污染庄家榜）**（Pointless 实测 2026-07-13）：重放前先算每地址"原子中转率"= Σ min(该地址在某 tx 的转入额, 同 tx 转出额) / 总流入；**>90% 即为聚合器/路由/发射台收集器/中转合约**（钱进钱同 tx 出、零驻留），Pointless 一次揪出 23 个（含 fee 收集器、DexAggregator、RelayRouter、发射台工厂等）。把它们并入 `market/infra` 集合当"市场腿"处理——否则它们的巨额过手流量（单个可达数百 M）会顶在庄家榜前排。比逐个 getCode 快且不漏。判据独立于"是不是合约"，7702 账户/EOA 中转也能抓到。
- **relayer/公共代理判据统一为"txfrom 用户数"**（Pointless 复核抓错实例）：某合约被多组同用不代表关联——`eth_getCode` 看是不是已验证 Proxy，再看 txfrom 独立用户数：**上千即公共设施**（bot relayer `0x56c2…`/`0xa67d…` 各 14 万+ nonce、经手数十种无关代币；狙击代理 `0x6505…` 1500+ 用户）。复核曾据"两组共用 0x6505"误推"同一实体"，实为公共 bot——**"共用某执行合约"永远不能作私有关联证据**。
- **Blockscout internal-transactions 端点（ETH 内部转账溯源主力）**（Pointless 实测 2026-07-13）：`/api/v2/addresses/{a}/internal-transactions`（须浏览器 UA）查合约间/充值的 ETH 流转——HyperSync transactions 按地址扫全链极慢时，金主 ETH 入金溯源改用它；直发交易查 `/transactions?filter=to`（value>0 的最早几笔即注资源）、合约转入查 internal-transactions。两者配合能把"谁给这个狙击母钱包打的钱"翻到零地址充值通道或 Relay 桥为止。
- **"漏斗/对倒环"定性前必须 getCode+查合约验证身份**（COMPUTE 对抗复核 REFUTED 实例）：DEX 聚合器（DexAggregatorCore/LiFiDiamond 栈）的"多上游归集→单点卖出+单进单出中转+净头寸≈0"形态与洗量环完全同构，误判成本极高；聚合器 USD 成交占比要与"枚数吞吐/供应"分开报，两个量纲差 4 倍以上。
- HyperSync **按块范围拉全链 transactions 响应超 16MB 会 IncompleteRead 截断**——内盘期对价重建改用 RPC `eth_getTransactionByHash` batch（20/批 subprocess+curl，466 tx 约 1 分钟）。
- 面额指纹要**先对全体参与者做独占性检验**再引用（COMPUTE 教训：初稿引用的 0.12×5/0.1667×3 实际属于名单外地址，复核抓出张冠李戴；0.05/0.1/0.25 等常见整数面额大量撞额无区分力，wei 级奇葩面额如 0.025225 才是硬指纹）。

  ⚠️ 依赖 `data/ethusdt_1h.json` 为 **list 格式** [[ts_ms,close]...]，而 cost_engine 的 quote_usd_hour.json 是 dict——两文件格式不同需各自生成（一行转换即可），首跑 FileNotFoundError 属预期（来源：BEGGAR 分析，2026-07-17）
- `pull_ohlcv.py`：GT 分钟K+小时K 翻页（带 UA/退避；pool 从 config.json 读）
- **HyperSync 429 备选通道三件套（Index 分析 2026-07-18 收编）**：`pull_transfers_rpc.py`（公共 RPC `eth_getLogs` 全量拉 Transfer，token/rpc 从 config.json 读、块范围走 argv `<起始block> <结束block>`、"log query timed out" 自适应缩窗）→ `pull_block_ts_anchors.py`（每 2 万块拉一 eth_getBlockByNumber 锚点，供 RPC 段无 ts 时线性插值）→ `merge_hs_rpc.py`（HyperSync gzip 段 + RPC jsonl 段按 block+logi 去重合并、锚点插值填 RPC 段 ts、ts 统一 unix int）。HyperSync 高峰 429 连败时的完整补救链，产物与 pull_transfers.py 兼容（下游 replay/prescan/evolution 无缝接）。
- `config.example.json`：复制到工作目录改名 config.json 按标的填写（cost_engine 用可加 fee_distributor/quote_token/deploy_block；gas_trace_bs 可加 extra_targets）

标的专属的分析/图表/报告脚本（analyze.py/build_appendix.py 等）存档于各分析项目目录，非复用件。
