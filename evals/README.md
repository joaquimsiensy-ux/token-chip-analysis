# 评测题库（evals）——skill 改动的安全网

> 建于 v6.0.0 重构（2026-07-30）。位置刻意放在 `references/` 之外：分析会话按 SKILL.md 路由只读 references/ 与 scripts/，永远不该读到本目录。

## 评测哲学（先读这段再用题库）

1. **历史结论不可当金标准。** 任何一个币、任何一个版本的历史报告，都无法保证没错——拿它当"标准答案"对答案是自欺。
2. **唯一可靠的标尺：被翻过案的错误，确定是错的。** 翻案都经过链上硬核实+用户终裁，这是全库唯一敢称"确定"的东西。
3. 因此每道题验收的是**"当年那个确证错误有没有被拦住"**，不验"是否复现历史结论"。新流程给出与历史不同但证据更硬的判定，不算失败——交用户裁决。
4. 真跑结果**由用户人工挑错终裁**，不搞机器对答案。

## 题目结构（每题两节，七要素）

每题文件分 A/B 两节：

- **A 节·执行输入**：自包含场景+数据指向+任务指令，**零答案泄漏**——可直接投喂执行会话。
- **B 节·考官侧**（含五要素，**禁止进入执行会话上下文**）：
  1. **当年确证错误**——评测的真正标尺（含翻案出处）；
  2. **唯一失败原因**——一题只测一个错误，防一题多靶互相掩护；
  3. **禁止输出**——旧确证错误不得再现的具体表述；
  4. **必做证据动作**——正确流程必然会做的检验（判卷看动作，不只看结论）；
  5. **缺证据时的结论上限**——数据不足时允许的最强表述。**防刷通过条款：把一切判成"存疑/无法确定"不算过**——凡 A 节给的证据足以支撑判定，就必须做出判定；只有真缺证据才允许退到结论上限。
  另附**预期拦截点**：v6 骨架里哪道闸/哪条判例/哪步流程应当拦住它。

## 使用方式

- **推演（每次改 skill 后的常规动作）**：主会话逐题走一遍新流程，写明"哪一步会拦住 B 节的错误"。任何一题找不到拦截点＝骨架有洞，先补洞再合并。
- **真跑（重大改动时抽题）**：新开独立会话，只投喂 A 节（复制粘贴，不给文件路径），按当前 skill 流程做判定；产出交用户挑错。执行会话**禁止读 evals/ 目录**。
- **新题登记**：每次对抗复核/外部复核产生的翻案，默认登记为候选题（见 retrospective.md 教训分流）；转正条件=翻案经用户终裁。
