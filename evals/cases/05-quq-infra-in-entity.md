# 题 5：庄家实体成员表里混进了什么

## A 节·执行输入（可投喂，零泄漏）

**场景**：BSC meme 币分析中，庄家体系聚类已初步成形。成员表候选里有三类可疑成员：①两个"bot 合约"（`0x9485…`/`0xB2D8…`，同模板字节码 22,962 字节，与庄家库存层高频互转、曾出现瞬时余额峰值 46–48%）；②一个与体系有转账往来的合约 `0x238a3588…`（当前余额仅 1.5 万枚）；③一个被大量地址反复调用的合约（几乎每个活跃钱包的交易里都出现它）。初判把三者全部计入"大庄#1 体系成员表"。

**数据指向**：案目录 `fable筹码分析/QUQ分析/`。不在则按合约 `0x4fa7…03bf`（BSC）链上实查。

**任务**：裁决三类候选是否属于庄家实体，说明判定依据。

## B 节·考官侧（禁止进入执行会话上下文）

1. **当年确证错误**（QUQ 07-22 交付后裁决+07-24 GPT5.6 外部复核，用户采纳）：三者全是**公共基础设施**——①两个"bot 合约"实为 **Pancake V3 QUQ/USDT 公共池**（22,962B 即 PCS V3 池标准字节码；"瞬时峰 46-48%"实为池内瞬时余额），"bot 世代交接"叙事作废；②`0x238a…`＝**PancakeSwap Infinity Vault**（设施误吸，成员表 215→214）；③高频被调合约＝**ERC-4337 EntryPoint** 单例。三者还曾被写进惯犯庄家标签库，07-24 curation 救回。
2. **唯一失败原因**：地址进实体成员表前没做公共基础设施先验——"与体系有资金往来/瞬时持仓高"被直接当成了成员证据（池子和入口合约跟谁都有往来）。
3. **禁止输出**：把 DEX 池/协议金库/EntryPoint 计入庄家实体成员或惯犯库；把池内瞬时余额表述为庄家持仓峰值。
4. **必做证据动作**：公共基础设施先验三测——①`eth_getCode` 与已知协议标准字节码比对（池/金库/单例都有标准模板）；②部署时间是否早于代币创建（先于服务对象存在＝公共设施）；③多币服务检验（该地址是否同时服务大量其他代币）。三测任一命中即出实体表、按设施单列。
5. **缺证据时的结论上限**：三测做不全时，最强写"与体系高频往来的未定性合约，持仓单列不计入实体合并占比"——**不允许**默认并入（并入会虚增控制占比且污染惯犯库，殃及后续所有案子）。
