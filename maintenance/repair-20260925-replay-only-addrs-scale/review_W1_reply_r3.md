**b）哈希分桶亲核**

全部使用显式 `tag VARCHAR、tx VARCHAR、li BIGINT`，K=6。

| 反例或性质 | 本轮纯内存结果 |
|---|---|
| 同键异值 | 两行同桶；桶行数 2、冲突键数 1 |
| 同键不同 b，标记为不同 run | 两行同桶；冲突键数 1 |
| 同键不同端点，仅一行命中目标地址 | 全行查重检出；提前地址过滤会漏掉该冲突 |
| 同键异值，两端均不命中目标地址 | 全行查重检出；提前地址过滤会漏掉该冲突 |
| 同 tag、同 tx/li、不同来源 | 同桶；冲突检出 |
| 不同 tag、相同 tx/li | 基线、分桶均为不同键；无同键冲突 |
| 首桶、末桶冲突 | 分别构造第 0、5 桶，各返回 `(2,1)` |
| 空桶 | 合并查询返回 `(0,0)` |
| 同值重复查询 30 次 | 哈希完全相同，返回类型 `UBIGINT` |
| NULL tx | 同值重复哈希仍一致 |

跨 run 测试在内存中模拟来源；没有生成真实双 run 文件，也不将它报告为预检端到端通过。合法通道 tag 唯一，基线本来就按 tag 分组，不能要求不同 tag 的记录作为同键冲突被拒绝。

**2.1(c) 合并查询与 r2 SQL 语义一致。** 内层每个完整键产出原始行数 `n` 和内容变体数 `variants`；外层返回 `SUM(n)` 与 `variants>1` 的键数。它没有把“冲突行数”误当“冲突键数”，也没有按哈希值替代完整键去重。

跨桶增量测试使用 **280 条唯一事件＋20 条原始复制行**，包含 mint、Z/DEAD 转入、DEAD 转出、普通地址自转、同块相反转账净零及 Z 自转：

- 生产 `_peaks_python` 与独立 Python 块末累计结果一致，得到 4 个正峰值地址。

**c）成本与资源**

2.1(c) 正常路径每桶有两条覆盖源范围的 SQL：

1. 合并行数与冲突检查。
2. `INSERT INTO ab_raw …`，执行过滤、去重和增量聚合。

建 `only_addrs`、建 `ab_raw`、最终合并 `ab_raw` 不读取原始源。冲突取样属于失败路径额外查询。日志若从 INSERT 返回值或 `ab_raw` 获取数量，无需再扫源；若实现额外查询 `raw_rows`，必须增加实际成本登记。

此前还有每通道查询：v2 的 probe、reject COUNT、保留行 COUNT；v1 的 reject COUNT、保留行 COUNT；以及后续 `maxlen` 和预检读取。**两条 SQL 不等于两次完整文件字节读取，也不直接限定物理扫描节点数。**

1.6、1.8、2.3 三处一致。1.6 中“K 次读取”仅出现在“不得登记为”的否定说明里，已不再作成本承诺。

**0.8 的默认 500 万行桶要求可执行。最省构造法是单进程内直接生成逻辑 VIEW：**

- `range(5000000)` 生成唯一 `li` 与 66 字符 tx。
- 按行生成两个 42 字符地址、19 字符时间和 37 位 value。
- K=1，执行 2.1(c) 同一条合并查询，消费最终两个标量。
- 不生成双格式文件、不签收据、不先物化宽表。
- 单独用 `/usr/bin/time -l` 测 RSS/墙钟，允许 DuckDB 在指定临时目录溢写并采样用量，记录实际连接设置。

本轮已将这个构造缩为 1,000 行验证，返回 `(1000,0)`。**未执行 500 万行资源测试。** 这种方法最省生成时间和输入磁盘，证明范围仅为宽聚合资源；不能替代原生 Parquet、blocks join 或完整补算路径测量。
