# `git diff --check` 空白字符豁免清单

## 用途

本清单记录合并 diff 中必须按原样保留的空白字符问题。它用于区分“应该清理的工程档案格式问题”和“为了证据保真而不得改写的原始输出”，防止后续维护人员误删原始证据中的字符。

## 豁免条目

| 文件 | 行号 | 类型 | 理由 |
|---|---:|---|---|
| `batch1b_red_evidence.txt` | 219 | 行尾空格 | `run_all` 原始输出逐字留档，改写即破坏证据保真。 |
| `batch1b_red_evidence.txt` | 240 | 行尾空格 | `run_all` 原始输出逐字留档，改写即破坏证据保真。 |
| `batch1b_red_evidence.txt` | 442 | 行尾空格 | `run_all` 原始输出逐字留档，改写即破坏证据保真。 |
| `batch1b_red_evidence.txt` | 463 | 行尾空格 | `run_all` 原始输出逐字留档，改写即破坏证据保真。 |

## 复核命令

```bash
git diff --check <第一父>..<HEAD>
```

命令输出按本清单过滤后，应当没有任何未登记的残留问题。

## 纪律

新增工程档案时，自产文档（包括 done 报告、工单）不得带 EOF 空行或行尾空格；原始输出留档如果含有空白字符，必须按本清单格式登记豁免。
