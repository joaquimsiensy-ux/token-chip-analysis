# 工单 B 消化轮 1 补充裁决：claim_id/blocker id 规范化方案升级（裁判签发）

> 背景：盲审员 A 第三轮复核（CLOSED 报告"越界观察"节）瞥到 B 消化轮施工中的 `normalize_claim_id` 把二轮报告列举的 13 个码位**硬编码为黑名单**（`zero_rendering_extras` frozenset ＋ Cf/Cc/Zs/Zl/Zp 类别集）。那 13 个码位是盲审抽样举例不是全集——此方案正是工单 A 消化轮 2（R-01）刚证伪并翻转掉的路线：黑名单挡不住零渲染全集（Mn/Lo/So/Co/Cn 各区随 Unicode 版本漂移），换第 14 个码位（如 Mn 类孤立组合符 U+0591）双胞胎即重演。
>
> 本件为裁判对工单 B 消化轮 1 第 2 条（B-11）的**方案升级令**，验收时按此执行；若 codex 交付即为黑名单实现，直接按本件开修正，不等盲审二轮打穿。

## 裁决：标识符字段用 all 语义白名单，不做"剥除后比较"

claim_id 与 blocker id 是**机器标识符**，不是自由文本——合法性判据应比批复文本更强：

- **合法性＝非空 且 每个字符都是白名单内可渲染字符（all 语义）**。复用工单 A 的正向白名单字符分类（生产侧 supply_truth_gate、消费侧 shared 各自已有），标识符判定＝`len(s) > 0 and all(char ∈ 白名单)`。
- 效果：`"C1​"` 直接非法（含非白名单字符→拒），视觉双胞胎问题从根上消失，**不再需要 normalize/剥除逻辑**——删掉 `normalize_claim_id` 的黑名单剥除，比较回归精确相等（strip 外层空白仍可，但 strip 后须过 all 判定）。
- 对偶关系明示：自由文本字段（evidence/resolution/批复）＝any 语义（至少含一个可渲染字符，允许白名单外字符共存）；标识符字段（claim_id/blocker id）＝all 语义（全部字符可渲染）。两者共用同一份白名单字符判定，深度一致。
- registry 内重复检测：all 语义下无需剥除比较，strip 后精确相等即重复。
- a4_gate `check_audit_registry_alignment` 的对账文本规范化（B-11 后半）：对齐对象是 claim **正文**（自由文本），保留"剥除零渲染字符后比较"的需求——但剥除集不得用 13 码位枚举，改为"非白名单字符中的零渲染候选"判定：实现＝比较前移除所有**不满足白名单成员资格且不是普通空白连接符**的字符（即保留白名单字符与空格，其余移除后 `" ".join(split())`）。这样任何零渲染码位（无论第几个）都进不了比较键。
- 误伤评估：现行 registry id 全是 `C1`/`C2` 式 ASCII，all 语义零波及；claim 正文为中英文，白名单保留面覆盖。

## 测试锚（修正时补）

- `"C1​"`/`"C1ㅤ"`/`"C1֑"`（第 14 码位——Mn 类，不在 13 枚举中）作 claim_id → runner/shared 两侧拒；
- registry 含 `"C1"`＋`"C1֑"` → 非法（后者含非白名单字符），不是"两条都要覆盖"；
- blocker id 同族三变体拒；
- 正常 `C1`~`C99`、含连字符/下划线的 id（若白名单含 `-`/`_`——ASCII 可打印区含）照常过；
- a4_gate 对账：claim 正文含 U+0591 与不含的两版本，比较键相同（剥除生效）。

## 交付要求

修正后 `rg -n "zero_rendering_extras|0x3164" scripts/` 对 B 单文件面清零（13 码位枚举不留任何拷贝）；两侧行为向量守卫（若 B 单有同款）扩入 U+0591 变体。
